# 17-13 — Physical pager pressure

Status: complete; long-context pressure acceptance is blocked by a reproducible
runtime startup crash, with raw evidence and a focused harness regression
recorded.

## Result

The V4 acceptance context resolved to 22,016 tokens. The first managed probe
used the correct context and native GPU Turbo4 placement, but its synthetic
prompt produced 22,187 tokens and was rejected before execution. The adapter
now reserves 512 tokenizer tokens, producing 10,752 synthetic words for this
ceiling; the prior overshoot is covered by the dry-run contract test.

The corrected probe started the build-cuda server at 22,016 with selective
target paging, 256-token pages, Turbo4 target KV, and native Turbo4/GPU draft
KV. Startup logged a committed native draft reservation of 22,016 rows and
23,379,968 bytes and reached `model loaded`/`listening`, but the service then
exited repeatedly with `status=11/SEGV` before the first long request. The
managed restoration loop stalled after the failed run; it was stopped, and the
original 16,384-token selective-pager service was restored and verified healthy
for six probes with zero systemd restarts.

No request reached the pager. Therefore host residency, promotion/eviction,
fault/transfer counters, H2D/D2H bytes, queue/copy/wait timing, and live table
epoch changes are not acceptance evidence from this task. The native draft
rows/bytes/placement are recorded above and in the raw attempt result, but no
claim is made about target page movement.

## Runtime boundary trace

The transfer path is intact as a testable generic boundary: `llama_context`
exports pager and direction-specific counters; `llama_kv_pager::apply_live_policy`
accumulates the live-policy transaction counters; and
`llama_kv_residency_transaction` executes H2D/D2H transfers before publishing
the new residency table. The observed failure occurs before a request can enter
that path, so changing zero counters would have been speculative.

The adapter now compares the full pre-run and post-restoration runtime
identity (binary, model, context, pager mode, page size, and native draft
placement) in addition to profile name, PID, and health. This prevents the
observed alternate 77,824-token non-pager service from being reported as a
successful restoration merely because its profile name and health matched.
