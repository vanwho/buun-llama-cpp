## Finding and implementation

`llama_kv_cache::apply_pager_live_policy()` previously appended one H2D plan per
selected cold page. The production `live_host_read()` callback receives the
run's `page_index`, whose numbering is local to a transfer plan. Consequently,
the second and later one-page plans could all read host page zero.

The boundary now builds all selected cold `llama_kv_residency_transfer_page`
records first and submits one authenticated H2D plan. The transfer-plan
builder assigns page indices across the complete vector, while the existing
residency transaction continues to fence copies, recheck full page identity and
epoch, and publish the immutable target only after successful completion.
Malformed or incomplete multi-page construction clears the promotion schedule
and leaves the previous table authoritative through the existing refusal path.

The deterministic live-policy test now uses one two-page promotion plan and a
page-index-sensitive fake host source. It verifies distinct bytes reach the two
promoted pages, along with the existing cold selection, publication, counter,
stale snapshot, and transfer rollback checks. The residency test independently
verifies plan-local page indices and destination-slot payloads.
