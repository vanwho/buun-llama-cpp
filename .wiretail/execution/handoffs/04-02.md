# 04-02 handoff

## Outcome

Added the internal `llama_kv_attention_telemetry` accumulator for bounded
per-logical-page retention evidence. It consumes the completed GPU page-mass
buffer produced by the paged Turbo4 path, with layout
`[token][layer][head][logical_page]`, and never consumes an attention matrix.
The caller-facing publication method is explicitly
`publish_completed()`: graph/event completion is required before it is called.

The accumulator has fixed storage for 1,024 logical pages and performs no
dynamic allocation during initialization, publication, or score copying. It
normalizes page mass by averaging heads, then tokens and layers. Each known
page tracks normalized attention EMA and a decayed recent peak, keyed by the
full page identity including page and representation generation. Sampling
intervals, EMA alpha, and peak decay are explicit configuration values.

Observe mode can publish the complete dense page list. Selective mode publishes
only the selected page list; omitted pages remain known but unobserved and are
not converted into zero evidence. Off mode returns immediately with no
telemetry work or counter updates. Completed samples are validated completely
before state mutation, and table epoch/page identity mismatch increments the
stale-drop counter without partially updating EMA.

The controller transfer is bounded to two float vectors: for 1,024 pages, EMA
is 4,096 bytes and recent peak is 4,096 bytes, for 8,192 bytes total. The
metadata identity ledger is separately reported as 1,024 times
`sizeof(llama_kv_page_id)` (98,304 bytes on this build). Counters cover sampled
tokens, sampled pages, stale drops, and invalid drops.
