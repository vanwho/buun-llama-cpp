# Handoff 05-04

## Outcome

Checkpoint/speculative integration now has one checked rollback frontier for
the target token ledger, recurrent rollback, MTP KV, and deferred carry. The
frontier records the accepted token count and rejected suffix range, rejects
invalid or overflowing inputs, and is used by the live speculative reject
path. A ledger/frontier mismatch is diagnosed and fails closed through the
existing slot recovery reset; release builds do not assert on this recoverable
boundary error. Cache-debug slot output exposes rollback and frontier-mismatch
counters.

Malformed MTP carry checkpoint payloads are now no-mutation failures: bytes and
carry readiness remain authoritative until the complete payload validates. A
parent-to-child slot clone captures speculative state before transition and
clears the entire destination if target, draft/recurrent, or speculative-state
copy fails, preventing a partial child image. MTP primary integration is
explicitly restricted to the supported Qwen3.8-27B GGUF architecture
`qwen35`; other architectures are refused at server model setup.

## Deferred verification

The required Qwen3.8-27B checkpoint and end-to-end selective pager fixture are
not configured in this environment. CUDA model-backed greedy spec-on versus
spec-off comparisons, zero/full/partial/repeated rejection output comparison,
real target-page pinning and routing-summary behavior, transfer cancellation,
frontier fault injection, MTP pressure/residency, and 262,144-token teardown
remain deferred. Later verification must confirm that accepted output is
identical, rejected suffixes do not evict unrelated sealed target pages, all
companions restore atomically, and host/pinned/device/recurrent/MTP resources
return to zero after clear, slot reuse, cancellation, and shutdown.

## Remaining risks

The public pager authority remains intentionally single-slot/single-sequence
and the model-backed page transfer path is not exercised locally. The server
architecture gate applies to MTP-primary checkpoint/carry integration; other
speculative modes retain their existing architecture support.
