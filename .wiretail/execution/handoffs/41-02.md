# Handoff 41-02 — explicit CPU-main-KV control boundary

## Result

The phase-41 B1–B5 launcher can now request an explicit CPU-main-KV target
while retaining GPU weights and native GPU MTP. The new `--no-kv-offload`
control is forwarded through the adapter and canonical runner as a transient
`AI_BENCHMARK_NO_KV_OFFLOAD=1` service override; the service entrypoint adds
`--no-kv-offload` independently of its native-MTP arguments.

The receipt identity now records `target_kv_placement`/`no_kv_offload` and
`mtp_placement` separately. The default selected/pager-off all-GPU profile
continues to omit `--no-kv-offload` and reports target KV placement `gpu`.
The common parser and speculative projection were audited: target
`no_kv_offload=true` maps to `offload_kqv=false`, while an explicit draft
`kv_device=gpu` still projects to `offload_kqv=true`.

Before the change, the canonical launcher rejected
`--no-kv-offload` with exit code 2 and its usage text, so it could not emit the
CPU-main-KV profile. No production profile defaults or selected route were
changed.
