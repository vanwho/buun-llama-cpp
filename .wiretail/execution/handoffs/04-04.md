# 04-04 handoff

## Outcome

Added the internal `llama_kv_prefetch_scheduler` boundary for predictive,
bounded page transfers. It accepts prior-token/query candidates up to a
configurable prefetch depth, coalesces duplicate page-generation requests,
cancels obsolete generations, and enforces queue-page, queue-byte, event,
pinned-slot, and double-buffered staging limits before submission.

The scheduler delegates the dedicated asynchronous upload stream, host-source
check, completion polling, complete-page publication, cancellation, reseal,
clean mapping eviction, and timing to explicit callbacks. Completion can be
observed out of order, but a page is publishable only after its whole intent
completes. Readiness has an explicit bounded wait followed by reuse of the old
hot set or a larger-union fallback. Clean eviction performs no D2H; dirty
pages require a separately counted reseal. Shutdown drains queued and active
work idempotently.

## Invariants/evidence

The deterministic fake backend exercises two concurrent staging slots,
attention/upload overlap, delayed and reordered completion, complete-page-only
publication, bounded pinned-slot backpressure, readiness waiting, old-set and
larger-union fallback, generation reversal cancellation, host miss, submit
failure, completion failure, clean eviction, dirty reseal, latency/copy
counters, and idempotent shutdown cancellation.

The scheduler has no direct transfer, graph, CUDA, or residency-table calls;
the callback production boundary is explicit and remains usable by a later
transaction owner.

## Deferred verification

CUDA upload-stream/event integration, real pinned staging allocation, device
slot mapping, Qwen3.8 long-context timing, and a hardware overlap smoke test
were deferred because this scheduler task had no production transfer owner
bound to its deterministic fixture. The reference GPU and Qwen3.8 artifact are
available externally; the follow-on integration must bind these callbacks to the existing
`llama_kv_residency_transfer` and composite transaction seams, then verify
real cancellation and event-fence behavior.

## Remaining risks

The scheduler is an internal callback boundary rather than live decode wiring;
production ownership must provide complete page-generation validation before
calling `publish_complete`. Queue limits, prefetch depth, and wait budget are
conservative defaults and require trace/hardware calibration before default
enablement.
