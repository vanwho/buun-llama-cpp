# 02-05 handoff

## Outcome

Added the fixed/manual residency proof boundary in
`llama-kv-fixed-window.*`. Geometry is derived from page tokens, target
layers, KV heads, K/V lengths, and the Turbo4 33/8 bit ratio; no acceptance
constant is used as a hidden allocation size. The Qwen3.8 reference inputs
derive:

- 32,768 KV values/token
- 16,896 bytes/token
- 135,168 bytes per layer/side page row
- 4,325,376 bytes per complete 256-token page (4.125 MiB)
- 4,429,185,024 bytes for 1,024 complete logical pages

The deterministic selector chooses newest pages plus explicit logical IDs
within a hard resident capacity. The scalar ledger tracks resident, host,
pinned, staging, useful/aligned D2H and H2D, checksums, stale rejects, and
evictions. Page records retain valid-token count, canonical host payload size,
checksum, dirty state, and physical slot without allocating page payloads.

## State and resource trace

```text
host-only sealed/checksummed page
    -> promote through admitted slot (H2D useful/aligned counters)
    -> clean resident page
    -> evict_clean: drop slot only, zero eviction-D2H counters
    -> promote again from the same canonical checksum

GPU-authoritative partial fill (pinned, host-invalid)
    -> seal(valid_tokens, checksum, aligned bytes)
    -> host-valid clean resident page
    -> mutate: host generation invalid/dirty
    -> reseal: one D2H seal counter increment
```

The proof models 1,024 page records and a 304-slot physical window; it does
not allocate a full-context GPU tensor or a multi-gigabyte host vector. The
test uses 32 MiB staging headroom and a host budget exactly equal to the
derived full-context payload. The fixed selection is 303 newest pages plus
explicit page 0, giving 304 residents deterministically.

## Deferred verification

CUDA/device verification remains deferred because this environment has no
configured CUDA backend or target hardware. A later reference run must bind
the fixed-window ledger to real VMM slots and separate compute/upload events,
then execute fill/seal/promote/evict/restore checksums while reconciling the
device, pageable-host, pinned-staging, and transfer ledgers. The current
CPU/fake proof does not claim hardware success.

No attention-driven selector or custom paged kernel was added. The manual
window remains an experimental proof boundary for the next phase.
