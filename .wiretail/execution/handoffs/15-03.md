# 15-03 handoff — live launcher and persistent lifecycle

## Outcome

Added explicit pager benchmark controls for mode, device, logical page size,
context selection, native/off MTP, and an optional server-binary override.
Successful runs keep the tested profile loaded by default; explicit control
runs restore the previous profile. Lifecycle state is captured in
`lifecycle-state.json`, and unsupported binaries are rejected before a service
restart so systemd cannot enter a restart loop.

## Changed files

- `tools/server/bench/run-pager-profile-benchmark.py` — explicit launcher
  arguments, launcher manifest fields, lifecycle state, and resume decision.
- `tools/server/bench/README.md` — live controls and lifecycle contract.
- `/srv/ai/benchmarks/run-profile-benchmark.sh` — explicit controls, transient
  systemd overrides, capability preflight, lifecycle state, and keep-loaded
  cleanup semantics.
- `/srv/ai/scripts/start-primary-llama-profile.sh` — consumes transient
  benchmark overrides, enables pager only for an explicit pager run, and pins
  native target/draft K/V to GPU Turbo4.

## Invariants/evidence

- No production profile file was mutated; benchmark settings use transient
  systemd-manager environment variables and are cleared after the run.
- `--context derived` uses the resolved profile context; no historical hotset
  or fixed token/page capacity is introduced.
- Native MTP forces Turbo4 draft K/V and GPU draft-K/V placement.
- Pager telemetry remains fail-closed; absent `llamacpp:kv_pager_*` data is not
  substituted with zeros.
- The service snapshot and exact command line are retained in `run-config.json`.

## Deferred verification

Native pager+MTP live model-backed smoke remains deferred because no available
benchmark server binary combines the pager CLI with a usable accelerator. The
launcher boundary, explicit not-configured/fail-closed behavior, deterministic
dry-run, and control/revert lifecycle are locally verified. Later setup should
provide a CUDA-enabled compatible binary and rerun the native smoke, preserving
the successful tested profile loaded for the next task.

## Remaining risks

The installed external profile binary must be rebuilt/repointed to the current
pager-enabled CUDA build before native acceptance can run. Phase-15 quality,
performance, and soak gates remain dependent on that live runtime evidence.
