# 10-05 handoff — exact page-wave live boundary

## Outcome

The exact route now has a real canonical page inventory at the pager boundary.
`llama_kv_pager_host::pages()` returns immutable copies of all live catalog
views, and `llama_kv_pager::exact_page_records(sequence_id)` reconciles those
cold records with the sequence-filtered resident table. Resident pages retain
their physical slots; cold pages retain their authenticated identity and host
validity. Identity generations, logical order, native position ranges, and
tail lengths are passed into the exact wave planner.

When exact mode is selected, `llama_context::prepare_kv_attention_graph`
builds a bounded all-page wave plan from that inventory. The wave size is
bounded by the admitted physical page window, the plan charges useful and
aligned H2D bytes, and its ledger is copied into execution telemetry. Invalid
identities, invalid tails, missing host backing, stale resident records, and
duplicate or missing logical coverage fail closed. Exact mode no longer
silently enters the dense graph path.

The existing exact executor remains the backend-neutral `(m,l,o)` contract:
serial and double-buffered staging, wait/compute callbacks, exactly-once page
coverage, stable merge, and one final normalization. No CPU Turbo4
dequantization fallback was added.

stage a cold page, launch the CUDA Turbo4 partial-state kernel, wait on its
event, and merge before the next transformer layer. The context therefore
returns `not_configured` after validating and recording the all-page plan; no
dense fallback is used. A linked current-tree CUDA model run was unavailable,
so the following remain deferred:

- CUDA stream/event upload, wait, partial-state, cancellation, and
