# 31-02 handoff — repaired

Status: done.

## Root cause and fix

The live CUDA write fault was caused by confusing a model layer ID with the
compact attention-layer ordinal in the pager's layer-aware `physical_row`
overload. Graph inputs pass model IDs from `get_layer_ids()`. For a sparse or
high model ID, the old ordinal comparison rejected the mapping and silently
fell back to the logical KV row. Once the logical position exceeded the
bounded physical window, `k_set_rows_turbo4_coop` could write past its layer
allocation.

The pager now authenticates layer IDs against the runtime-derived
`model_layer_ids` geometry (while retaining ordinal validation for legacy
synthetic geometry). Unknown IDs fail closed, and write-ticket validation uses
the same identity rule. The promotion path keeps the bounded H2D ring
asynchronous, maps the reserved destination before issuing device copies, and
the transaction authenticates the destination slot against the desired
publication before publishing it. Publication remains after chunk completion
and generation/identity recheck. The context teardown also joins the pager
before backend destruction so its asynchronous workers cannot outlive CUDA
storage.
