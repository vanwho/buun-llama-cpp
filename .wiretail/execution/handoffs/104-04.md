## Result and current state
Implemented `GGML_OP_KV_PAGE_RERANK` in the experiment worktree. The API
consumes transformed probes, separate resident and staged Turbo4 K tensors,
10-word page descriptors, identity/validity metadata, and caller-owned
streaming max/sum state. CPU and CUDA paths decode represented Turbo4 keys,
apply causal row masking, GQA head mapping, attention scaling and optional
softcap, then emit per-page/head/probe log mass. No V data or resident K copy
is used by the op.

Added a fixed two-slot staging ring: each caller-provided pinned host slot and
encoded-K device slot is at most 4 MiB. Reads are bounded contiguous chunks;
the source is rechecked before and after reading, its canonical page/unit
holder remains alive through the key-reader event, and reuse waits for a
terminal event. Owner callbacks enqueue H2D plus reader work on one stream.
The fake backend verifies two-slot backpressure, source-holder lifetime,
event retirement, and byte accounting. Production owner buffer
allocation/stream binding and the boundary route are exercised in later
104-05/104-06 work.

The CUDA fixture now checks an independent decoded-key scalar LSE reference,

## Decisions and invariants
- Probes are consumed after the router transform; no second transform or RoPE.
- Descriptors are `[logical, physical_slot, valid_rows, stream, page_size,
  generation, content_version, eligible, first_absolute_row, key_set]`;
  identity is generation plus content version. Key set 0 is resident, 1 staged.
- Keys remain encoded Turbo4. Log mass combines chunks with stable `(m,s)`;
  partial/padded and future rows are excluded.
- Staging owns exactly two host/device slot pairs (4 MiB maximum each). Event
  terminal status must guarantee the reader no longer accesses either slot.
