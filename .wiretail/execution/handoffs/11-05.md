# 11-05 handoff — predictive prefetch and atomic live lifecycle

## Outcome

Added the backend-neutral `llama_kv_live_lifecycle` owner that composes the
bounded prefetch scheduler with live policy publication. Ranked future intents
are coalesced by page, sorted by priority, stamped with the active operation
generation, and submitted through the existing asynchronous staging/event
limits. Required-page readiness retains the scheduler's wait-budget, prior-hot
set, and larger-union outcomes.

The lifecycle requires one admitted slot, rejects `slot_count != 1`, and
monotonically fences session, sequence, and operation generations. Prompt
adoption, checkpoint restore, clear, cancellation, slot reuse, checkpoint save,
and shutdown cancel unpublished work before changing or retiring ownership.
Late completions have no publication path after cancellation or generation
rotation.

## Lifecycle diagram

```text
retrieval/controller ranks
          |
          v
coalesce + priority sort + generation stamp
          |
          v
dedicated prefetch events/staging --complete--> ready-page set
          |                                      |
          | required at decode boundary          |
          +--> wait budget -> old hot / union ---+
                                                 v
       complete live-policy target + transfer transaction
                         |
             generation and frontier recheck
                         |
       companion publish (target/recurrent/MTP/speculative)
                         |
                 immutable table publish
                         |
                   retire old mappings
```

Companion publication is called from the transaction publish phase, before the
table's linearization point. A rejection aborts the transaction and invokes the
companion rollback hook; a stale generation fails the recheck and publishes
nothing.

## Concurrency scope and invariants

- Selective live authority is explicitly single-slot/single-sequence. Startup
  with more than one slot returns `unsupported_slots`; ordinary non-selective
  multi-slot behavior remains outside this owner.
- Target, recurrent, MTP, and speculative state use one validated frontier.
  Accepted/rejected speculative suffix arithmetic is checked before a boundary
  can publish.
- Every tracked transfer is cancelled on generation rotation. Page identity,
  sequence generation, snapshot epoch, transfer destination, and operation
  generation remain separate checks.
- Only complete scheduler events publish. Dirty victims continue through the
  existing reseal path, and the existing transaction owns transfer rollback.

## Fault and lifecycle results

- duplicate future intent: coalesced before submission;
- stale required intent: rejected without queueing;
- companion publish rejection: table epoch stayed unchanged and companion
  rollback ran;
- prompt adoption/slot reuse: old pending ticket was cancelled and its later
  completion did not publish;
- checkpoint save: unpublished predictive work is cancelled before the event
  callback;
- checkpoint restore, clear, and shutdown: generation/state transitions are
  fenced and teardown is idempotent;
- multi-slot configuration: rejected explicitly with `unsupported_slots`.
