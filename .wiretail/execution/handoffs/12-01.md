summary and one resolved startup diagnostic. `off` remains the default. `auto`
continues to mean runtime-derived capacity or policy; no hot token/page count

## Diagnostics and refusal behavior

Enabled contexts emit one `KV pager startup` key/value record containing the
normalized policy, resolved context, logical/admitted pages, physical rows and
bytes, page charge, ledger usable/charged/reserved/headroom bytes, device,
route, and refusal status. MTP fields are explicit runtime admission values;
unavailable placement is not replaced with a guessed value.

Capability validation remains fail-closed before pager owner construction. It
reports the comma-separated reason codes for unsupported backend, architecture,
causality, Turbo4 K/V, attention/page geometry, device topology, sequence
layout, host budget, MTP, or conflicting VBR authority. Invalid parser values
are rejected before model/context setup.

## Refusal examples

```text
--kv-pager bogus       -> invalid --kv-pager mode
--kv-page-size 128    -> --kv-page-size must be a multiple of 256
non-GPU backend        -> KV pager capability refused: backend
non-Turbo4 K/V         -> KV pager capability refused: cache_type
multiple target slots  -> KV pager capability refused: sequence_layout
conflicting VBR owner  -> KV pager capability refused: conflicting_vbr
```
