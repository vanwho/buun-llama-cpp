# 02-04 handoff

## Outcome

Added a composite KV residency transaction around the immutable residency
table and the 02-03 bounded transfer pool. The transaction accepts one
complete policy target plus bounded D2H/H2D plans, snapshots the table epoch,
reserves every transfer before mutation, pins the old snapshot, reseals dirty
pages before eviction, drops only clean victims through reversible callbacks,
fences and rechecks all transfers, and publishes exactly once.

The table remains unchanged on every pre-publication failure. Newly loaded
pool mappings, completed catalog reservations, clean victim drops, and pins
are rolled back in reverse order. The table epoch advances once only after the
publish call succeeds. Post-publication retirement and release are cleanup
steps over the already-authoritative immutable snapshot.

## Publication state diagram

```text
snapshot(epoch E)
    -> plan target / reject stale identity, dirty victim, pinned victim, or missing source
    -> reserve all transfer slots, events, staging, and catalog bytes
    -> pin old snapshot
    -> reseal D2H dirty/uncached pages and fence their completion
    -> drop clean victims (restore callbacks retained)
    -> load H2D additions and fence events
    -> recheck full page identities and epoch E
    -> publish table (linearization point; epoch E+1 exactly once)
    -> retire old resources
    -> release pins and successful reservation ownership
```

Any failure before the publish arrow follows the reverse path and leaves the
old immutable table snapshot authoritative. A stale table publish is rejected
by the existing table epoch check; ABA is rejected by the complete logical
page identity and generation checks before transfer and again before publish.
