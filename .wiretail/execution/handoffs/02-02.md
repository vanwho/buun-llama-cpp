# Handoff 02-02 — Host Turbo4 page catalog

## Outcome

Implemented the canonical selected-page host backing boundary. Sealed pages are
stored as immutable pageable segment chains with their complete 32-unit
descriptors, native positions, payload size, transfer provenance, dirty/clean
state, and capture-scope/page identity. GPU residency is represented as a
duplicate of the canonical host backing; only bounded pinned staging is charged
separately.

## Changed files

- `src/llama-vbr-artifact-catalog.h/.cpp`: added the selected-page host key,
  immutable page view/catalog, authenticated payload and Turbo4 validation,
  serial-safe budget admission, per-page accounting ownership, alias/dedup,
  invalidation, and shutdown release.
- `src/llama-cache-accounting.h/.cpp`: added non-manifest-mutating accounting
  cell creation for internal transactional stores.
- `src/llama-vbr-artifact-capture.h/.cpp`: capture quote now carries the
  authenticated source namespace, child, and stream scope used by host keys.
- `tests/test-vbr-artifact-capture.cpp`: added sealed-page round-trip,
  bounded host budget, alias, lookup, and invalidation coverage.

## Deferred verification

CUDA/device-resident duplication and hardware pinned-memory behavior remain
deferred because this environment provides no configured CUDA backend or target
Turbo4 hardware. The production boundary is explicit: pageable backing is
always canonical, pinned staging is bounded and budget-accounted, and no full
4.125 GiB page is pinned by default. Later verification should publish a real
selected capture through the CUDA pager, confirm device reloads read the host
catalog view, and inspect ledger pageable/pinned/device rows across replacement
and clean shutdown.
