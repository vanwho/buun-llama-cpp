# 93-11b handoff — Cold selector descriptor repair and remaining CUDA graph failure

## Reproduced failure and local repair

The signal-handler capture for the managed four-page route recorded a SIGSEGV
in `llama_kv_cache::apply_pager_live_policy()+0x242` during the cold rung's
first 30-token request. The stack is
`/srv/ai/paged-kv/results/v10/93-11b/attempt-01/stale-graph-descriptor-stack.log`
(SHA-256 `cb8a430962d7b7bde65b97e45cdd2172208aada2aeb5f0ca9be6a0c080634eeb`).
Disassembly mapped the faulting instruction to the selector-output scan's
`output.tensor->buffer` access. `set_kv_page_select_inputs()` refreshed every
stored descriptor with the same layer number, including descriptors whose
tensor belonged to an older graph. The graph input already calls
`capture_kv_routing_query()` immediately afterward with the exact selected
tensor, so the broad layer-only stamp was unnecessary and unsafe.

Removed that layer-wide update and made the descriptor lookup use exact tensor
and layer identity. Added a deterministic regression for same-layer,
different-graph tensor identity in `test-llama-archs`.
