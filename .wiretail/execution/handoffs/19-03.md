# 19-03 Handoff — live residency transactions

## Outcome

Completed the production live-residency boundary and deterministic transport
coverage. Decode/ubatch records the current sequence, sealing occurs at the
existing scheduler boundary, and live policy runs after attention graph
completion. The pager now binds the canonical host catalog, upload ring,
layer-aware GGML adapter, synchronous completion, identity rechecks, and
clean-drop/restore rollback hooks. Publication updates the pager mirror only
after the residency table is revalidated.

Promotion uses per-layer K/V byte views over the cache-owned layer-major slab;
attention reads that same slab. The adapter does not retain a duplicate dense
cache. The deterministic selected-page diagnostic remains separate from later
attention-aware scoring.

## Production caller and transaction trace

`llama_context::synchronize()` → `seal_kv_pager_pages()` → completed attention
graphs → `apply_kv_pager_policy()` →
`llama_kv_cache::apply_pager_live_policy()` →
`llama_kv_pager::apply_live_policy(boundary)` →
`llama_kv_residency_execute_transaction()` →
`llama_kv_residency_execute_transfer()` →
`vbr_h2d_chunk_ring::stream()` → GGML `run_tensor()` → CUDA completion and
identity/table recheck.

## Invariants

- K/V remain canonical Turbo4 bytes; no dequantize/requantize transfer path.
- Device offsets are layer-relative run offsets over the cache-owned slab.
- Host reads follow the catalog's canonical concatenated unit order.
- A copy completion must match page identity, epoch, and physical slot before
  publication; failed replacement restores the prior clean mapping.
- Mapping gaps are reconciled before transactions; no policy-trace failure
  defaults to overwriting slot zero.
- Counters are taken from actual ring submission/completion statistics.
