# 17-01 handoff — benchmark lifecycle cleanup and runtime identity

## Outcome

Implemented lifecycle cleanup and fail-closed runtime identity checks. A
successful, fully validated adapter run keeps the tested candidate loaded by
default. Canonical-run failures and adapter-owned post-validation failures
restore the captured profile through the established activator; cleanup is
repeatable and records `restored`, `restore_failed`, or `known_stopped` state.
The managed server is identified from the configured systemd `MainPID` (or an
explicit test PID), so unrelated `llama-server` processes are not selected.

## Invariants/evidence

- Successful runs use `keep-loaded-on-success`; restoration is only requested
  for controls or failure paths.
- HTTP/request errors now make the canonical runner fail, ensuring its EXIT
  cleanup path runs instead of treating an error record as success.
- Adapter telemetry validation uses the post-run scrape and never substitutes
  pre-run values or environment values for missing runtime counters.
- No credential value was written to output; only the existing API-key file
  path may appear in a server command line captured by the external runner.

## Remaining risks

The external live adapter must be invoked with `LLAMA_ACTIVE_PROFILE` and
`LLAMA_PROFILE_ACTIVATOR` so prior-profile restoration is observable and
portable. A run with no captured prior profile can only report a known-stopped
state; it cannot invent a profile to restore.
