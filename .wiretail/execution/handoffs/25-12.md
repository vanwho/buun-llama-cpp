# 25-12 handoff

## Outcome

Implemented a guarded native-MTP target-hidden device handoff. The draft
catch-up path still stages the batch and pending boundary row normally, but
compatible non-host tensors use a backend device-to-device copy for the
contiguous shifted target rows. The request is consumed once by the next graph
submission and the host path remains the explicit fallback.

## Invariants/evidence

- Direct path requires F32, matching row width, valid contiguous row ranges,
  non-host buffers, and identical backend devices.
- Host staging remains in place until direct compatibility is confirmed.
- Only rows 0..n_tokens-2 are handed off; the pending boundary row remains
  host-owned and is installed by the existing lifecycle code.
- No model weights, KV codec, token mapping, or MTP allocation settings changed.

Deferred: direct-path CUDA execution, host-copy and stage timings, accepted /

## Remaining risks

The direct copy assumes the target output tensor and draft input tensor remain
valid through the single next graph submission, which is enforced by the
single-use request and existing graph ownership. A backend-specific async-copy
ordering issue must be checked on CUDA with the target and draft contexts on
the same device.
