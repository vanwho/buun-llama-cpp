# 09-03 handoff — live target writes and mutation publication

## Delivered

The selective/exact pager is now connected to the ordinary attention-cache
caller path. `llama_context::init_kv_pager()` binds the admitted owner to the
attention child (including the Qwen3.5 hybrid attention child). Before a
committed `apply_ubatch()` enters graph construction, the cache reserves one
pager row per logical token. K/V index inputs use the returned physical row
only when the row is resident in the compact target; logical `ubatch.pos`
values remain authoritative for RoPE, causal masking, and sequence ordering.
Observe mode has no physical target and follows the legacy path unchanged.

Each reservation carries sequence/page generation, logical position, physical
slot/row, and whether the row was newly valid. The memory-context `finish()`
callback completes all tickets after graph submission or cancels them on any
apply, graph-build, allocation, or compute failure. Duplicate positions are
cancelled in reverse reservation order so a failed graph cannot leave a row
published by accident.

## State diagram

```text
absent
  | begin_write: free slot or clean host victim; row cleared/invalidated
  v
filling_gpu, pinned current frontier
  | complete_write(success): all required K/V segments + every valid row?
  |                         no -> filling_gpu, partial frontier remains pinned
  |                         yes
  v
gpu_dirty, device authoritative
  | later transfer/seal callback (09-04; all layer/KV segments complete)
  v
gpu_host_clean or host_clean, unpinned and evictable

filling_gpu/gpu_dirty -- complete_write(false) --> absent or prior valid range
gpu_host_clean/host_clean -- begin_write victim --> absent -- begin_write --> filling_gpu
any unpinned page -- atomic remove/keep/clear/rewind --> absent
any selected unpinned page -- atomic copy/shift --> new logical identity
any touched pinned page -- mutation preflight --> all_pinned (no publication)
```

The pager keeps a valid-row bitmap per page. A tail page is represented as
`filling_gpu` with its native logical begin/end range; it is never treated as a
clean eviction victim. A page is sealed only after the expected
`attention_layers * 2` K/V segment completions and all rows in the page are
valid. The current partial page remains device-authoritative and pinned until
a later write frontier takes over.

## Callers and composite behavior

- `llama_context::process_ubatch()` calls `mctx->finish(false)` on every
  pre-graph/graph failure path and `mctx->finish(true)` after successful graph
  submission.
- `llama_kv_cache_context::finish()` drains the cache pager tickets.
- `llama_memory_hybrid_context::finish()` forwards to its attention child;
  recurrent state remains in the same `apply_atomic()` transaction and has no
  separate pager representation.
- Pager metadata mutations are wired at the attention-cache boundary for
  clear, remove, copy, keep, and page-aligned shift. Pager mutation publication
  reconciles only changed records, preserving unrelated pinned pages.
- The pager exposes no physical order to RoPE or masking. `physical_row()` is
  used solely for graph K/V destination indices.

## Failure and ownership rules

- No legal physical slot returns `no_victim`; a pinned-only target returns
  `all_pinned`.
- A mismatched sequence/page generation returns `stale_generation`.
- A graph failure cancels reservations and removes newly valid rows; no
  successful page completion is published.
- Mutation preflight rejects touched pinned pages before changing either the
  pager table or its page-state copy. Table publication is one residency
  transaction, with rollback on validation/publish failure.
- Payload transfer/sealing is intentionally not claimed by this task. The
  pager’s opaque backend allocation remains the target physical reservation;
  page transfer ownership is the existing residency-transfer seam.

## Exact callback required by 09-04

The next task must replace the provisional completion count in
`llama_kv_cache::finish_pager_batch(bool)` with the real target completion
callback. The required contract is:

```cpp
pager_->complete_write(ticket,
    completed_kv_segments_for(ticket.logical_page, ticket.position),
    graph_succeeded);
```

That callback must be invoked only after every required Turbo4 K/V segment for
the ticket’s page and logical position has completed on the target device. It
must provide the actual segment count (not merely graph-submission success),
perform any device-to-host seal/clean transition through the existing transfer
owner, and preserve the page’s native logical positions. On failure it must
call `cancel_write(ticket)` for all still-pending tickets and leave no half
published page/copy/mutation. The callback must also coordinate recurrent and
MTP state in the enclosing hybrid transaction before reporting success.
