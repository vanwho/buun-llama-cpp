## 93-04 failure sequence and diagnosis

The selected resident raw log records the request launch, then
`memory_seq_rm [0, end) rejected`, then systemd records process termination
with `status=11/SEGV`. The log contains no call stack or per-context trim
result, so it cannot identify whether target or draft returned `false`, nor
the exact faulting instruction.

Source tracing identifies the first server operation after that warning:
`server_cache_mandatory_recovery_reset_impl(ctx_tgt, ...)` calls
`common_context_seq_rm`, which calls the fallible
`llama_memory_seq_rm`; `common_context_seq_rm` invokes `GGML_ABORT` when that
operation returns false. Thus the fallback reissued a fallible public removal
through an asserting wrapper. The retained artifact establishes the unsafe
operation sequence and failure, but does not prove that this wrapper was the
instruction-level SIGSEGV site. New logging reports target/draft trim and reset
results separately for the next bounded reproduction.

## Change

- `tools/server/server-prompt-trim.h` adds a callback-driven, deterministic
  trim/recovery transaction. Any rejected partial trim triggers independent
  target, draft, and active backup-sequence reset attempts.
- `tools/server/server-context.cpp` uses transient per-sequence removal for
  mandatory cleanup, logs side-specific results, clears speculative rewind
  vectors and slot metadata, and releases the request before decode when a
  paired reset fails. Successful recovery starts from an empty slot image.
- `tests/test-server-prompt-cache.cpp` exercises target-trim refusal, draft
  trim refusal after target success, reset failures, and independent backup
  cleanup without a production fault toggle.

The invariant is that a false partial removal never advances into decode as a
successful trim. Both target and draft full resets are attempted independently;
any live backup is also retired. If the required cleanup does not complete,
the request is failed and released before another decode. Checkpoints, cache
plan deliveries, token ledger, prompt statistics, speculative draft vectors,
and rewind state are invalidated on the recovery path.
If memory cleanup itself fails, request release skips the child-slot cleanup
path that would otherwise retry through the asserting public removal wrapper.
