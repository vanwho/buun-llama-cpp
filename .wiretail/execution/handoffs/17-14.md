# 17-14 Handoff

## Result

Completed the exact/native and concurrent response-oracle repair. The exact
attention path still fails closed when its CUDA page-wave callbacks are not
configured, but that supported refusal now crosses the server boundary as
HTTP 501 with `not_supported_error` and the specific refusal reason. A true
compute failure remains HTTP 500 `server_error`.

The soak harness now records raw response bodies, HTTP status, transport
classification, semantic classification, and exact-marker classification
independently. Concurrent requests use distinct `id_slot` values whenever at
least two slots are available and constrain each response to its own literal
marker. If the service exposes only one slot, or either response fails a
semantic/marker check, `concurrent-oracle.json` is `blocked` with machine-
readable blockers rather than treating HTTP 200 as correctness.

The startup path is now a bounded pre-corpus gate. It records systemd state and
the recent service journal, classifies an unhealthy post-restart service as a
runtime crash/unavailable (or restart failure), writes a blocked run summary,
and returns before long corpus requests or resource sampling begin.
