# 95-02 handoff

## Result and current state

Implemented a slot-owned query checkpoint captured before decoding the exact authenticated final-user seam. The checkpoint stores host-backed target/draft `PARTIAL_ONLY` images, exact target/draft frontiers, MTP carry when available/required, request/session identity, and scalar pager table/representation epochs. Restore stages recurrent undo images, validates request and representation identity, restores recurrent state, removes only attention KV at/after the query start, restores carry once, and preserves the live newly published page map. An unrecoverable draft-tail removal quarantines the draft/carry while retaining the restored target frontier. No full-L attention/KV image is captured.

The focused deterministic and CUDA proofs pass, receipt validation passed, and task 95-02 is done. The state tool advanced the project pointer to 95-03 in `ready` state.

## Decisions/invariants

- Host state APIs are used; `LLAMA_STATE_SEQ_FLAGS_ON_DEVICE` is never used for this checkpoint because that mode invalidates prior same-sequence device snapshots owned by speculative rollback.
- Capture requires processing to be exactly at the checked `user_begin` token seam and both state frontiers to end at `user_begin - 1`.
- Restore validates request/session/sequence and pager representation identity. It permits the pager table epoch to advance, never installs a captured page table, and uses attention-only range removal so selected history survives.
- All recurrent undo buffers are allocated before mutation. Restore is idempotent after its `restored` phase. Stale async D2H remains rejected by pager page/content generation checks.
- Snapshot storage scales with target/draft partial recurrent state and MTP carry. The checkpoint log records recurrent/carry byte counts and `history_bytes_copied=0`.
