# 13-03 handoff — host sealing, promotion, and transfer overlap

## Outcome

Retained a bounded H2D overlap optimization for ordinary and packed transfer
adapters. A cancellation callback no longer forces each H2D submission to
wait before the next bounded ring slot is filled. Cancellation is still
probed before every fill, and the ring core drains/cancels/releases all
pending chunks before returning. The existing D2H cancellation serialization
was deliberately left unchanged.

The deterministic fakes observe two in-flight chunks with an 8 MiB ring and
4 MiB chunks, for both ordinary and packed H2D. The transfer remains bounded;
the tests still validate byte content, source digest stability, completion,
failure cleanup, and zero pending operations. CPU wall time is unchanged
within noise because the fake destination does not model GPU copy latency:
capture was 1.11–1.12 s before and 1.10–1.12 s after; adoption was 0.07 s
before and 0.06–0.07 s after.

## Sweep and selected rule

| Hypothesis / geometry | Measurement | Decision |
| --- | --- | --- |
| H2D callback + 8 MiB ring / 4 MiB chunks | ordinary and packed peak outstanding operations > 1; final pending set empty | Retain pipelining |
| Bounded 8 MiB pinned ring versus 257 MiB transfer | capacity < transfer; peak pinned bytes <= capacity; backpressure and all chunk completions checked | Retain bounded backing; no whole-transfer pinning |
| D2H callback cancellation path | cancellation probes=2, one chunk submitted, partial chain unpublished | Retain D2H serialization |

The selected rule is structural rather than machine-tuned: H2D uses the
existing bounded ring depth even when cancellation is enabled; D2H keeps its
single-submission cancellation mode. No stream-priority/count, prefetch
distance, pageable-versus-pinned backing, or ring-size auto rule was selected
without live pager counters.

## Before/after timeline

Before, when a continuation callback was installed:

```text
fill slot 0 -> submit H2D -> wait/consume slot 0 -> release -> fill slot 1
```

After:

```text
fill slot 0 -> submit H2D -> fill slot 1 -> submit H2D
                         -> wait/consume oldest -> release -> continue bounded
```

If a continuation probe returns false, the fill stops and the existing
`abandon_pending()` path waits/cancels/releases every submitted bounded slot;
no partial H2D operation is published. D2H retains its serialized timeline to
bound cancellation response latency before publication.

## Deferred verification

The configured service does not expose a live selective pager route with the
component counters needed for warm/single-fault/burst-fault/focus-shift/churn
profiles. Deferred checks are: real CUDA H2D/D2H useful and aligned bandwidth,
copy/compute overlap, fault-segment latency, CPU waits, p95/p99, RSS and pinned
high-water under a model workload, VRAM staging, stream priority/count,
prefetch distance, and pageable-canonical versus bounded-pinned end-to-end
comparison. Nsight Systems/Compute, live corruption/stale/cancel timing, and
MTP/model acceptance remain deferred to the configured pager service and
phase-13 gate. No unavailable hardware or service result is claimed here.
