# 59-01 handoff

Status: complete. Repaired the full-L first-request resource boundary and
revalidated both packet fixtures against the rebuilt CUDA candidate.

## Implementation

- `llama_context::prepare_kv_attention_graph` now charges the compact packed K/V
  workspace across every attention layer, with overflow/refusal handling, before
  graph construction can discover per-layer owners.
- `llama_context::process_ubatch` now finishes the pager batch on exceptions from
  graph construction or scheduler allocation, preventing pending pager writes
  from surviving a refused graph.
- The CUDA and CPU focused KV/cache tests remain green.

  packed-prefill route, target Turbo4/CUDA, full-L draft Turbo4/GPU.
- `L262144/H16384/B128/U64`: 1200 prompt tokens, valid 8-token response,
  packed-prefill route, target Turbo4/CUDA, full-L draft Turbo4/GPU.
- Final H16384 metrics: 262144 requested/resolved context, 1207 target-valid
  rows, 1220 target tokens processed, 27 graph submissions and completions,
  13 graph replays, 14 rebuilds, and 26,542,080-byte scratch high-water mark.
- No pager-pending-write assertion or graph-allocation failure occurred; the
  final metrics show no unexpected replay scratch growth.
- The managed profile wrapper was not used for exact B/U launch values because
  its installed qwen38 profiles hard-code BATCH/UBATCH. The exact fixtures were
  run through the immutable rebuilt candidate bundle with `LLAMA_SERVER_PID`
  bound to the direct endpoint; this setup limitation is recorded rather than
  treated as a code or hardware failure. The llama-server service was restored
  and is active after testing.
