# Handoff — task 15-06

## Result

Bound the production exact route to the existing Qwen Turbo4 paged CUDA graph
for the resident decode case. Exact planning now validates the complete
resident/host catalog and records page-wave ledger data; resident decode builds
the canonical page view, native logical positions/mask metadata, and selects a
dedicated `exact_direct` route. The graph input/reuse paths dispatch that route
through the direct Turbo4 node, whose page mass is published after the existing
scheduler fence.

Cold exact waves remain fail-closed. The current graph boundary cannot upload a
cold page per layer and merge online `(m,l,o)` state without a new graph
boundary, so this task does not claim live cold-needle, multi-wave H2D, CUDA
event, or online-softmax parity from the deterministic planner alone.

The live pager metrics boundary now exposes physical capacity, direction-aware
transfer counters, promotion/eviction pages, selected/exact page counts,
faults, waits, transfer cancellation/stale/event/backpressure counters,
H2D/D2H useful and aligned bytes, table rebuilds, attention-mass counters, and
explicit routing-recall availability. `routing_recall` is null with
`routing_recall_available=0` until a live selective-vs-exact all-page oracle is
available. `late_waits` and overlap remain measured zero/unavailable rather
than being inferred from generic backpressure or planner estimates.
