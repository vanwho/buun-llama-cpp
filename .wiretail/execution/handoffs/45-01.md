# Handoff 45-01 - current-Q candidate and promotion bridge

## Result

Repaired the first missing production edge after phase-43 current-Q
publication. A policy boundary now wakes for a current, refresh-enabled
selector result instead of requiring an already-ready mailbox slot. The
selector output is also re-registered from the graph input lifecycle on graph
reuse, because graph reuse does not call the graph callback again and the
policy boundary consumes the previous registration after reading it.

The bridge remains fail-closed: refresh results must match the current query
generation, table epoch, sequence, and registered tensor before candidate
construction; existing mailbox identity, stale-generation, host-catalogue,
and promotion validation remains unchanged. No forced page or superseded
direct attention path was used.

## Deferred verification

The 27B natural CUDA C>H recall/append smoke was attempted with
`test-kv-pager-model --model /srv/ai/models/text/Qwen3.8-27B-UD-IQ4_XS.gguf
--context 4096 --n-batch 256 --n-ubatch 256 --hot-pages 2 --generate 8 --mtp
off`, but an existing `llama-server` occupied 14.1 GiB of the 15.9 GiB RTX
4080, leaving 1.5 GiB and causing CUDA allocation failure for the 12.7 GiB
model buffer. The bounded fallback with
`LFM2.5-2.6B-QAD-Q4_0.gguf` was not production-compatible: its
`n_embd_head_k=64` is not divisible by the required Turbo4 block size 128.
Candidate publication, promotion, useful H2D, selected cold-page use, and
coherent natural model output therefore remain deferred to the existing 27B
CUDA fixture after that external GPU process releases the device. No hardware
success is claimed.
