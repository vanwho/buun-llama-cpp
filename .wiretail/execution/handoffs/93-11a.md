# 93-11a handoff — Optional graph tensor naming and remaining cold-route failure

## Reproduced crash and repair

The 93-11 selected request still crashed after the empty-suffix trim fix. A
managed, selected, MTP-off diagnostic with a signal/backtrace preload captured
`ggml_format_name` dereferencing `tensor == nullptr` while Qwen3.5 graph
construction named an absent `attn_inp_kq_mask` on recurrent/hybrid layers
3, 7, 11, …, 63. The stack ran through `llm_graph_context::cb`,
`llama_model_qwen35::graph::build_layer_attn`, and
`llama_context::graph_get_cb`. The failure was in the naming callback, before
operator execution. The bounded raw trace is
`/srv/ai/paged-kv/results/v10/93-11a/attempt-01/original-null-name-stack.txt`
(SHA-256 `535e7ff8d0f41da3cdd67c56f31d72dc1a6ef87603c778d939645d8ee629f7be`).

Added `llm_graph_name_tensor`, which treats a null optional graph tensor as a
no-op and preserves normal layer naming for present tensors. The production
`graph_get_cb` now uses it. `test-llama-archs` directly checks both the absent
tensor call and normal indexed naming.
