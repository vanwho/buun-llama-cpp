# 31-03 handoff — repaired

Status: done.

## Root cause and fix

The selected-direct execution path treated every residency-table epoch as a
graph-shape change, even though its page table, native positions, mask, and
query positions are mutable device inputs patched before submission. It also
fenced the common `NO_UPDATE` memory path and rebuilt pager policy inputs after
unchanged write-frontier publications.

The direct route now reuses a stable graph layout across table epochs while
retaining each immutable view lease until its submission completes. Memory
updates probe before fencing and only preserve the synchronization boundary for
real updates or failed preparation. Pager policy work is dirty-driven by page
maintenance, current-page boundaries, and ready routing candidates; refused
transactions retain their retry ownership.
