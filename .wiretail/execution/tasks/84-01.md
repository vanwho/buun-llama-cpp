## Mandatory geometry-control repair before MTP diagnosis

The phase-83 launcher receipt established a concrete setup defect:
`AI_BENCHMARK_UBATCH` was requested as `128`, but the endpoint-owning process
still loaded profile-default `-b 128 -ub 64`. Do not call that a U128 result,
and do not use it to diagnose MTP or compare speed. Repair the local benchmark
control plane first, outside portable upstream code:

1. In `/srv/ai/scripts/start-primary-llama-profile.sh`, after sourcing the
   selected profile and before constructing `args`, apply optional
   `AI_BENCHMARK_BATCH` and `AI_BENCHMARK_UBATCH` overrides to the local
   `BATCH` and `UBATCH` values. Accept only positive base-10 integers and
   reject `UBATCH > BATCH`; an invalid manager environment must make service
   startup fail clearly rather than silently use the profile geometry.
2. Keep profile files unchanged. The override is a transient benchmark-manager
   setting only; no `/srv/ai` pathname, GPU model, or fixed geometry enters
   portable Buun code or an upstream commit.
3. Add/extend the V10 launcher contract test so it launches a harmless
   command-construction probe with B128/U128 and B128/U64, then asserts the
   observed endpoint-owner argv contains exactly the requested `-b` and `-ub`.
   The driver must fail a row before sending any inference request when actual
   argv differs from requested geometry.
4. Restart the named Qwen service through `sudo -n`, capture the PID command
   line and loaded DSO identities, and verify B128/U128 is truly loaded. If it
   now fails startup, record it as a real U128 capacity/shape result; only
   then use the separately labelled B128/U64 control.

Do not begin token/state comparison until this control-plane proof passes.
The intended primary coordinate is B128/U128 because it is the normal
high-throughput CUDA prefill shape; U64 is a causal memory/shape comparison,
not a silent substitute.

Use these concrete source locations, not a new parallel MTP path: speculative
entry/verification and rollback in `tools/server/server-context.cpp` around
`common_speculative_process` (about lines 20017-20060),
`common_sampler_accept_draft`/proposal retrieval (about 20707-20747), and
accepted/rejected suffix restore (about 20820-21034); draft/target handoff in
`common/speculative.cpp` `common_speculative_process` (about 6196) and
`common_speculative_accept`; target graph preparation and MTP verification in
`src/llama-context.cpp` around `kv_attention_mtp_verification_`, the MTP graph
builders, and `llama_set_kv_attention_mtp_verification`; and route planning in
`src/llama-kv-attention-execution.cpp` `planned_route`, `prepare`, and
`selected_page_ids`. Add a bounded diagnostic hook or
regression test, not an always-on telemetry pass, that records for the first
eight verify steps: target and draft input token IDs, positions, argmax token
IDs, logits checksum/top-k identity, n_past/cache_n, checkpoint generation,
route, page-table epoch, and whether target/draft state was restored before
verification. Redact prompt contents and keep the hook disabled by default.

Compare all-GPU native MTP at B=U=128 against feature-off greedy target and
against the selected native row only after the all-GPU row is valid. If U128
cannot start for capacity/shape, retain that startup receipt and use one
explicit U64 control to separate geometry failure from state failure. If U128
passes and U64 fails, document the shape restriction and make U128 the stable
diagnostic/benchmark default. If both geometries fail everywhere, isolate the
first common divergence before touching paging. If only selected native fails,
verify that page-table publication and cold-page completion happen before MTP
verification; do not globally disable MTP to hide the failure.

Add a deterministic test for the discovered invariant and record the exact
minimal source change if one is required. Do not claim a fix merely because
the server starts or counters are nonzero. Deliver a root-cause classification
and a repair-ready handoff for the route/promotion task and speed task.
