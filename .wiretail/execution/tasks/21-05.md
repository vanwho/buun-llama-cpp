# 21-05 — Validate selective quality on a bounded representative matrix

Recommended model: **Luna High**. Phase 21; cluster `21b-controls-soak`.
Depends on: `21-04`.

## Objective

Measure real correctness after the runtime and harness repairs without
repeating the invalid 24/48-case campaign. This is a quality checkpoint, not a
speed curve and not a full 256K proof.

## Work

1. Freeze one release/model/template/corpus/config identity and run dense or
   selected-all controls for warm-focus, cold-early, cold-middle, cold-end,
   competing-fact, and focus-shift cases.
2. Run the matching selective cases with a budget-derived hot set. Include one
   deliberately cold needle and verify selected page IDs, host checksum,
   promotion, and answer before scoring.
3. Use T=0, seed 42, thinking off, and a short output. Run one trial per case;
   add a repeat only when the first result is ambiguous. Stop immediately on
   a capability refusal or two identical failure classes.
4. Report exact/selected-all/selective scores separately, with omitted-page
   and sparse-policy labels. Do not call a selective failure a model-quality
   failure if route or movement telemetry is absent.

## Acceptance and deliverables

Produce `handoffs/21-05.md` and `evidence/PHASE21_QUALITY.json/.md` with
numerators/denominators, raw IDs, route/movement telemetry, and repair owners
for negative rows. A truthful negative result completes this checkpoint but
does not authorize the final speed curve.

Run focused tests and state validation. Keep all four KV codecs Turbo4 and
native MTP on GPU; do not substitute a 16K-only result for later capacity
proof.
