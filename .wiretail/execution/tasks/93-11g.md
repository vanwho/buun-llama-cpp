# 93-11g — Natural two-topic file recall and hot-page promotion

Revision: `repair93-two-topic-recall-20260924`.

Model: `gpt-6-luna`, High; recovery assessment is also `gpt-6-luna`, High.

## Goal

Replace the brittle one-file A/B recall test with one ordinary same-slot
conversation that compares five Python merge files, then five Bash watcher
files, then asks the Python comparison again. Capture whether the page holding
the winning Python implementation was naturally evicted and brought back by
the last question. This is a short functional paging/MTP proof, not a speed
benchmark or a judgment of real-world Python/Bash runtime performance.

The current one-file test repeatedly failed on fragile synthetic answer gates
and page selection. Keep the new sequence to three natural requests, always
send the final repeat question, and record content/paging/MTP evidence even if
an answer is imperfect. Do not stop after a model wording mismatch.

## Why this test uses 16K context

The ten immutable fixtures contain 10,240 tokenizer tokens before chat
wrappers, questions, and actual assistant replies. An 8,192-token server
context cannot retain the complete A→B→A conversation. Use server context
`16,384`, GPU hot KV budget `4,096`, page size 256, one slot, B=128/U=64,
selective Turbo4 target K/V, and native MTP with GPU Turbo4 draft K/V. The
small hot budget—not a total-context overflow—must create ordinary page
replacement. Do not change the context or hot budget after beginning the live
sequence; preflight the exact rendered final request first.

## Exact three-request conversation

Use only the first five fixtures of each requested category:

- Python: `PY_MERGE_01` through `PY_MERGE_05`
- Bash: `BASH_WATCH_01` through `BASH_WATCH_05`

Preserve each complete fixture body byte-for-byte. Build exactly these three
user turns in one slot, appending the model's actual prior assistant replies
between turns:

1. Include all five Python file bodies in manifest order. Ask: “Among these
   five Python implementations, which one uses an exactly preallocated result
   list and writes each result position once, the most allocation-efficient

   The intended unique answer is `merge_sorted_lists_03.py` (`PY_MERGE_03`).
2. Append all five Bash watcher bodies in manifest order. Ask: “Among these
   five Bash watchers, which one is the leanest for a single nonrecursive
   directory when it reports CREATE and MOVED_TO events without an extra
   per-event file test? Reply with only the exact filename.” The intended
   answer is `watch_directory_new_files_01.sh` (`BASH_WATCH_01`).
3. Append no new file bodies. Repeat the exact Python question from request 1
   verbatim. Do not mention internal page IDs, residency, cache placement, or
   expected filenames in this last question.

The word “efficient” is deliberately operationalized by the stated behavior;
do not claim the fixture corpus establishes measured wall-clock performance.
Score whether the response names the intended filename, but never make a
response-format mismatch abort request 2/3 or suppress page/MTP evidence.
Use natural EOS and the context-derived completion allowance; do not add an
arbitrary short token cap, stop sequence, forced extraction prefix, or exact
