# 93-11g — Verify natural file recall after ordinary KV paging

Revision: `hotpath-v10-20260914`; amendment: `repair93-mtp-fast-20260922`.
Cluster: `repair93-mtp-diagnostics-v10`.
Implementation and assessment model: `gpt-6-luna`, High.

## Goal

Prove one ordinary same-slot interaction can keep a real file in the logical
conversation, let normal 8K/4K pager pressure make its KV page host-backed and
nonresident, then naturally ask about that file and observe selection,
promotion, and target plus native-MTP use. This is one functional proof, not a
24-case accuracy contest or speed benchmark. The prior attempt passed the
neutral A question but stopped at B1 because every filler response had to
match an exact synthetic `RETRIEVAL_KEY` sentence. That gate tested response
formatting, not page movement. It is removed below.

Keep `-c 8192`, 4,096 target hot tokens (16 × 256-token pages), one slot,
B=128/U=64, selective Turbo4 target K/V, and native MTP with GPU Turbo4 draft
K/V. Reasoning is off. Do not change fixtures, expected facts, server context,
hot geometry, route, page IDs, selector scores, or residency manually.

## Test protocol

1. Offline-check the fixture manifest and hashes. Verify all 24 files still
   have their expected tokenizer count and syntax. Never shorten, regenerate,
   reword, or pad fixture facts to fit an answer budget. Fixture bodies are
   test data, not response templates.
2. Use only `PY_MERGE_01` as A for the required live proof. Use the next four
   Python fixture files as B fillers; append B5/B6 only if the read-only page
   snapshot shows A is still resident. The other 23 fixtures remain available
   for optional follow-up coverage, but are not a live completion gate.
3. Before sending requests, verify the managed service is the expected
   candidate/model/build and the allocator admitted exactly 8,192 context,
   4,096 hot tokens, and 256-token pages. If the expected binary is already
   loaded and the handoff says `continue_loaded`, reuse it. Otherwise use the
   canonical managed lifecycle to load that binary. Never launch a second
   Qwen process or touch port 8092. Use noninteractive `sudo -n`; if it fails,
   diagnose/fix the invocation or sudoers configuration in this task rather
   than declaring authorization unavailable.
4. Erase slot 0 once before the case and verify it is empty. Then send ordinary
   chat-completions turns in the same slot with prompt caching:
   - A: full `PY_MERGE_01` contents, followed by “Read this file; I will ask
     about it again later. Acknowledge briefly without summarizing or quoting
     a detail.”
   - B1–B4: append each complete B file as a new user turn, followed by “Read
     this additional file as context for later; acknowledge briefly without
     summarizing it.”
   - If A is not cold, append B5 and then B6 using the same wording, checking
     A's residency after each.
   - Once A is verified cold, ask naturally: “For
     `merge_sorted_lists_01.py` (fixture `PY_MERGE_01`), which input is emitted
     first when the current values are equal? Answer naturally in one
     sentence.” Referring to A by its exact filename and/or fixture identifier
     is explicitly allowed and is ordinary user-level document reference, not
     a test shortcut. Do not resend A's file. Do not expose internal pager
     logical page IDs, selector scores, or force a route/residency change in
     the prompt; those are implementation details, unlike the fixture ID.
5. Build each cumulative message list from the prior *actual* assistant
   replies. Acknowledgements and filler answers are free-form: do not require
   `YES`/`NO`, exact text, an exact prefix, or a fixed token count. Record the
   raw response and continue. For each request render/tokenize with the
   candidate's `ServerPromptRenderer`, preserve the exact messages and
   response, and refuse context shifting or a prompt that exceeds the actual
   8,192-token context.
6. Give each generation all available completion room under the actual
   context: `max_tokens = admitted_context - rendered_prompt_tokens - 128`.
   This is a context-safety calculation, not a desired output length. Do not
   set a short fixed output cap, stop at newline, truncate text, or size the
   budget from the number of characters in a manifest answer. Natural EOS
   ends acknowledgements and answers; record `finish_reason` and usage when
   supplied.
7. Immediately before A-again, save `/slots` and page inventory. Require the
   original A page(s) to be complete, host-backed, and nonresident while A is
   still present in logical context. If the page is still resident after B4,
   add B5/B6; if still resident after B6, diagnose the normal pager/context
   behavior rather than claiming eviction. Never use a forced eviction,
   page-selection, or promotion API.
8. Save the A-again natural answer even if its wording is imperfect. Score it
   with a paraphrase-tolerant concept check (answer identifies the left/first
   input as taking precedence); do not require sentence equality. A response
   scoring poorly must not abort before page/event evidence is collected.
9. For the final request, require and correlate this same-page order using the
   runtime's request-local events: cold-before; normal selector nomination;
   H2D completion; mapping publication; target attention consumption; native
   MTP draft consumption. Match request ID, logical page ID, generation,
   content version, and increasing event sequence. Positive global counters,
   correct text, or a route label alone are not proof.

## Repair and iteration rules

- The first implementation change should be limited to the prompt planner,
  live driver, and focused tests: remove exact-answer gates on A/B, use natural
  acknowledgements, ask one natural A-again question, use context-derived
  generation room, and retain all raw evidence. Do not modify KV attention or
  MTP source unless the candidate-bound event trace identifies a concrete
  missing/incorrect page transition.
- Run local fixture/planner/driver/validator tests first. Then run exactly one
  fresh candidate-bound A→B→A case. Do not rerun all 24 target files.
- If a setup problem occurs, repair and repeat only the affected request/case
  from a clean slot, preserving the failed raw root. If the answer is wrong,
  still collect the cold snapshot and promotion events before diagnosing it.
- If required event data is unavailable, add only bounded transaction-level
  telemetry at the missing selection/transfer/publication/consumer seam; no
  per-token logging, synchronizing hot-loop instrumentation, or new attention
  route.

precedence. Keep physical-promotion proof and answer-quality result as separate
fields. If physical promotion passes but natural recall does not, preserve the
completed trace and keep the task `in_progress` with a concrete diagnosis; do
not redo a 24-case sweep.
