## Selected implementation

1. Inspect `llama_kv_routing_summary_store::update_pages` (~472),
   `reconcile/invalidate_page/invalidate_pages` (~595–665),
   `rebuild_accounting` (~744–819), and private page in its header. Currently
   result=*this deep-copies retained vectors; accounting then hashes all their
   floats. Preserve immutable returned-store/snapshot semantics, but store
   each page's vectors/ranges/radius in an immutable shared payload owned by
   that page version. Copy only small page descriptors/shared handles.
   Construct a fresh payload for each changed page; never mutate a payload
   held by an old graph/store. Existing public const-vector accessors keep
   returning stable data through the payload owner.
2. Compute payload byte counts, finite validation and a payload digest once
   when a page payload is constructed. Build the table content hash from
   configuration/coordinate identity plus sorted page identity, content
   version and cached payload digest. Do not rehash unchanged float vectors
   in update/reconcile/invalidation or on a residency-only epoch change.
   Preserve deterministic ordering and collision-safe identity/version checks;
   a content hash is not a replacement for authenticated page identity.
3. Because this changes the content-hash construction, audit all consumers
   with rg for content_hash/LLAMA_KV_ROUTING_SUMMARY_VERSION. Version the
   internal hash contract if retained/imported summaries require it; invalidate
   incompatible derived caches. Do not change Turbo4 codec/codebooks, host
   byte hashes, or weaken required identity checks to preserve an old number.
4. Keep overflow/byte-budget/accounting guards. Charges count unique live
   payload allocations and simultaneously retained versions; shared handles
   are not a license to undercharge actual retained memory. Metadata counters
   may walk page descriptors, but unchanged vector payload copy/hash work
   must be zero. An unchanged content set with a new residency epoch retains
   its content digest; updating a page version changes the appropriate digest.
5. In `tests/test-kv-routing-summary.cpp` prove retained old snapshots remain
   numerically unchanged after update/invalidate, changed inputs update only
   their payload, deterministic digest across insertion order, version/codec/
   coordinate separation, budget/overflow failure, and stale-page exclusion.
   With 2 then16/64 synthetic pages and one-page deltas, assert payload reads/
   hashes scale with changed payload, not all retained payload. Instrument
   counts in the fixture or profile gate, not timing-sensitive CTest limits.
6. In `seal_ready_pages`, avoid the extra first-layer `routing_summaries_=next`
   deep payload copy through the shared owner; keep canonical per-layer/head
   index and legacy accessor semantics. Atomic failure retains the old table.
