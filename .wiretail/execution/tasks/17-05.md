# 17-05 — Repair speculative rollback and page-generation atomicity

## Objective

Eliminate the selective+native-MTP request failure observed during speculative
suffix rollback and make target-page, transfer, sequence, and draft state
failure-atomic.

## Read

- Cluster `17b-mtp-capacity`, handoff 17-04, phase-15 runtime-lifecycle work,
  server task rollback paths, page residency transactions, and the raw 32K
  HTTP-500 evidence.

## Work

1. Reproduce the rollback failure with accepted and rejected draft suffixes.
2. Audit generation IDs, page-table epochs, in-flight H2D/D2H events, host
   canonical pages, target sequence metadata, and the MTP draft frontier.
3. Commit or roll back all affected state together; stale completions must not
   publish after cancellation, slot reuse, or checkpoint restore.
4. Preserve Turbo4 representations and GPU MTP placement throughout rollback.
5. Add focused deterministic tests for accepted/rejected suffixes, partial
   tails, cancellation, in-flight promotion, slot reuse, and restore.

## Acceptance

The 32K regression returns valid responses with no HTTP 500, stale-generation
publication, leaked mapping, or host/device accounting drift. Run a live smoke
before allowing the benchmark phase to proceed.

## Deliverable

Create `handoffs/17-05.md`, implementation/tests, and raw regression evidence.
