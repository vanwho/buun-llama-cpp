## Source-directed work

Use 100-03e's per-request bytes and wait attribution plus 100-03f's single
post-edit row. 929 MB cumulative D2H across 12 selected rows may be the
*necessary once-per-new-page canonical write*; no optimization may delete
the inclusive CPU Turbo4 store. First compute expected newly completed page
bytes from actual model/page geometry and compare submitted D2H bytes and
copy calls. Inspect `src/llama-kv-cache.cpp::seal_kv_pager_pages`,
`src/llama-kv-pager.cpp::seal_ready_pages`, `poll_host_completions`,
`host_->enqueue`, `host_->wait`, and the host capture ring. Classify waits as
real queue exhaustion, current-page overlap, safety fence, or needless
per-ubatch/per-layer synchronization.

If measured sealing/wait is material (same >=20% rule as 100-03f), implement:

1. Keep the mutable current page GPU-owned; seal a completed immutable page
   once for its content version, on the existing bounded async ring. Do not
   recopy a growing partial page or enqueue an already host-valid version.
2. Process completion on the next ordinary scheduler boundary without
   blocking compute. Wait only if the bounded ring is exhausted or a specific
   eviction/promotion requires those canonical bytes. The queued page stays
   pinned and cannot be selected as a clean victim until its completion event
   has published the matching host version. Maintain the existing allocation
   failure full-scan fallback, but no regular full-L scan.
3. Batch adjacent newly complete rows/pages where the current ring/API makes
   this possible *without* changing Turbo4 encoding or page IDs. A batched
   transfer must retain each page's content version and publish individually
   after the batch fence. No device-global synchronize for instrumentation.
4. Ensure prefill C>H can progress under actual queue pressure without a
   false `no_victim`; retain strict cancellation/replay ownership. On a true
   saturated ring, report actual backpressure rather than spin or silently
   drop canonical host data.

If seal is not material or D2H is already exactly once per completed page and
overlapped, do *not* rewrite it. Record expected/actual bytes, queue depth,
wait attribution and a tested no-change decision. KVMem's packed stage-in/out
diff in `src/adapter/llama-memory-kvmem.cpp` is a useful conceptual check,
not code to import or a reason to add another pager.
