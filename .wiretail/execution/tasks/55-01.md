# 55-01 — Close the full-L CUDA resource boundary

Revision: `hotpath-v10-20260914`. Cluster: `55a-full-l-resource-v10`.
Model: Luna High; first retry High. Prerequisite:54-01.

## Objective

Repair or complete the full-L request resource contract. Phase 53's focused
repairs exist, but the phase-53 summary still has the last measured failures
at `C=0` and no live post-repair request because the candidate was displaced
by another CUDA process. This task must prove the combined request boundary
before any occupancy or speed campaign.

## Exact owners and hypothesis

Inspect only the existing owners `ggml_cuda_fattn::kv_dequant_scratch_try`,
`ggml_backend_cuda_kv_dequant_scratch_memory`,
`llama_kv_cache::vbr_scratch_reserve`,
`llama_kv_attention_packed_cache::find_or_create`,
`llama_kv_attention_packed_cache::submit_graph`, and CUDA
`launch_mul_mat_q`. Hypothesis: one of the two repaired reservations is still
not charged against the same pre-submit budget/launch contract when the full-L
view, packed selected view, pager lease, and graph resource are combined; a
request can therefore reach a mid-graph scratch/launch failure or leave a
pending pager write after an allocation refusal.

## Minimal fixture, invariant, and numerical discriminator

Preserve and run both smallest failures:

- `L262144/H30208/B128/U128`, a 1200-token request, for VBR f16 scratch;
- `L262144/H16384/B128/U64`, first request, for packed allocation and dynamic
  shared memory.

Before is the phase-53 evidence: `max_observed_C=0`, a scratch/launch failure,
and in the packed case a pending pager-write cleanup assertion. After the
focused test must report `physical_if_reserved >= required_bytes`, a launch
shared-memory request no greater than the device-supported limit, zero pending
pager writes after refusal, and one completed request whose observed `C` is at
least the actual token count of the submitted 1200-token fixture (strictly
`C>0` if the harness uses a different tokenizer count). The same request must
retain Turbo4 target KV and GPU Turbo4 full-L draft placement, and graph replay
must not grow scratch.

## Stop condition and proof

Stop at the first remaining accounting, launch-resource, or ownership
mismatch. Do not lower L, move draft KV to CPU, switch attention routes, or
start an occupancy curve to hide a failure. Add/extend the smallest focused
CUDA regression assertion and run the exact live fixtures. Required proof is
`full_l_resource_boundary_repair`; retain the raw focused/live log.
