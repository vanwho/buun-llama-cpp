# 25-07 — Make canonical host publication coalesced and asynchronous

Scope revision: speed-first-20260911. Recommended model: Luna High.
Phase 25; cluster `25c-host-movement`; depends on `25-06`.

## Objective / hypothesis

Canonical host KV must be inexpensive append-only traffic, not a synchronous
archive operation on the compute critical path. Transfer newly produced
Turbo4 bytes once, overlap them, and make clean-page eviction copy-free.

## Source anchors

Strategy section 5; llama_kv_pager_host::seal in src/llama-kv-pager.cpp,
src/llama-kv-cache.cpp pager_host_prepare/snapshot helpers;
vbr_selected_page_capture_transfer and host catalog in existing VBR source
(find by symbol, don't create a parallel representation system);
ggml backend async copy/event capabilities and current residency transfer ring.

## Implementation recipe

1. Inventory actual allocation/copy/hash path of one page seal. Preserve
   generic page identity and opaque Turbo4 payload layout but avoid using
   heavyweight checkpoint/archive/checksum logic on every normal append.
   Reuse the current host catalog API with a fast runtime backing path if
   necessary; optional durable snapshots remain separate.
2. Allocate pageable canonical slabs by layer/logical page and one bounded
   pinned staging ring (or measured pinned backing). Pack adjacent changed
   rows per layer into coalesced D2H; don't issue a blocking copy for each
   representative row. Tail delta copies must not rewrite the whole page
   per generated token when only a suffix changed.
3. Enqueue copies after the producing compute event. Track inflight source
   content/slot generations and pin the GPU source until D2H completion.
   Host-committed version advances only after bytes arrive. Reuse staging
   entries only after CPU consumption/next transfer ownership ends.
4. Drain completion events asynchronously. Consumers may use already committed
   host versions; eviction waits only if that victim is dirty/inflight.
   Canonical RAM may trail an inflight batch, but every committed target page
   must become recoverable before its GPU slot can be dropped. Report lag
   separately from logical occupied rows.
5. Compute routing summaries from committed host bytes initially (25-03) or
   attach one pooled GPU summary output. No redundant D2H full K reads.
6. Benchmark synchronous vs asynchronous host publication on one 4K prompt,
   B from 25-06, then 128 generated tokens. Measure total new payload, actual
   copied payload, metadata, D2H calls/waits and overlap. Tune only a couple
   of ring sizes against the ledger. D2H and H2D copy engines may contend:
   do not infer overlap from use of multiple streams.

## Checks / acceptance

Existing fake-event residency tests: source writes complete before read,
source/destination/ring reuse after fences only, appended tail/version
overwrite, dirty victim refuses/drop waits, clean eviction no D2H.
CUDA byte equality on selected K/V pages; no extensive crash/soak matrix.
Actual canonical host bytes must grow with processed history, while duplicate
payload/copy call inflation disappears. Keep native GPU Turbo4 MTP enabled.

Record evidence/SPEED25_07_HOST with payload amplification, throughput and
bounded allocation totals. Unsupported async backend may keep synchronous
fallback; target CUDA must execute the measured async path before done.
