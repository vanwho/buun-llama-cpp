## Exact change

1. Existing single-row ring fixture is insufficient. Reproduce production
   begin_write_batch with full pool, partial current page, two-page verify
   packet, rejected speculative suffix, accepted append and a page wrap.
   Include clean-oldest, seal-in-flight-oldest and frozen-history cases.
2. Preflight currently counts eligible victims before begin_write releases
   the previous frontier. Release ONLY a prior completed frontier no longer
   touched by this batch after its graph fence; queue maintenance, drain ready
   completions, then evaluate availability. Never decrement unrelated in-flight
   or speculative pins; distinguish frontier pin ownership if a single counter
   cannot safely identify it. A still-touched tail remains protected.
3. Build one bounded reservation plan: unique written pages, missing pages,
   free slots and ordered eligible output victims. Exclude every written page
   from victim selection. Use that same plan for allocation; do not count
   candidates in preflight and independently choose different victims inside
   begin_write. Prefer an internal planned-slot/victim overload over duplicating
   pager or public APIs. Validate identities/content versions before changes.
4. All tickets are preallocated/validated before irreversible eviction. Apply
   clean mapping drops and new slots transactionally, or use the existing
   residency transaction with rollback ownership. Cancelling a later ticket
   must not pretend it restores an earlier evicted page. On any refusal,
   no partially published map, lost canonical host copy or leaked pin remains.
5. Keep chronological FIFO: stale entries may be discarded; a valid oldest
   entry awaiting its seal/pin fence is not bypassed to steal a younger page.
   On actual pressure, drain completions and wait once for the affected producer,
   then retry admission. No per-token global synchronize, spin polling or
   scanning all L pages. Distinguish transient awaiting-seal from a truly empty
   generation queue/invalid geometry in bounded diagnostic fields.
6. Complete_write/accepted rollback must assign current_turn_generation with
   the active turn ID and enqueue exactly once when clean. A suffix rewrite
   invalidates old seal/summary/content versions; a stale event cannot release
   or requeue a newer incarnation. mutate/cancel/clear removes stale queue
   entries and preserves frozen historical identities. At turn end, sealed
   output becomes ordinary retrievable history next turn.
7. Reuse asynchronous page sealing: dirty completion -> bounded D2H -> exact
   version publication -> routing readiness -> eligible FIFO. G limits minimum
   reserved space, NOT output count. Preserve host copies when dropping slots.
