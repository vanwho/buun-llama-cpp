# 25-03 — Eliminate immutable-page readback and quadratic summary maintenance

Scope revision: speed-first-20260911. Recommended model: Luna High.
Phase 25; cluster `25a-speed-attribution`; depends on `25-02`.

## Objective / hypothesis

Make append/seal/index maintenance proportional to new/changed pages instead
of repeatedly reading all old pages. Source currently revisits gpu_host_clean
pages whenever routing_summary_provider_.build is non-null, and copies/sorts
summary stores inside nested page/layer loops.

## Source ownership

Strategy sections 2, 3, 5; dependency's short timing table. Inspect:
src/llama-kv-pager.cpp seal_ready_pages, publish_page,
reconcile_routing_summaries, invalidate_host_page and write completion;
src/llama-kv-cache.cpp pager_routing_summary_build/pager_host_prepare;
src/llama-kv-routing-summary.cpp update_page/reconcile/rebuild_accounting;
src/llama-kv-routing-summary.h; existing pager/routing tests.

## Implementation recipe

1. Add a content-version/freshness contract distinct from snapshot/table and
   physical-slot epochs. Queue a page once when valid content advances; store
   last host-committed and summarized content versions. An identity-preserving
   publication, promotion or pin change must not reread immutable K.
2. Drain only completed dirty pages at the established fence. Tail append
   updates only that page/version; speculative rewind/overwrite, seq clear and
   slot-generation reuse invalidate it correctly. A tail with unchanged valid
   extent must not be recopied for each decode with no KV mutation.
3. For the first fix, obtain representative rows from the canonical captured
   Turbo4 host image already produced for that version. If host copy is not
   committed yet, delay summary publication or use a batched GPU summary, not
   four synchronous tensor_get calls per layer for every old page.
   Add a typed read-only host-page view with generation/lifetime checks if
   missing; do not reach into unrelated VBR artifacts by unowned raw pointer.
4. Batch all summary deltas. Acquire inventory once per changed wave, update
   changed (layer,head,logical_page) entries without copying the whole store
   for every input. Prefer indexed stable entries and one immutable snapshot
   publication per wave; retain old readers until fence. Avoid per-entry sort,
   scan and rebuild_accounting. Reconcile deletions only for actual invalidated
   identities. No ignored mismatch/error path to fake the optimization.
5. Keep scalar/debug full rebuild as a small test oracle, not a production
   periodic scan. Preserve head-zero sampling semantics for now; expanding
   cold routing/head coverage belongs to 25-11.
6. Reuse 25-02 inputs. Measure 2K/4K/8K if the baseline was previously slow;
   compare summary calls/bytes and host time per new page with old page count.
   Complete one short native-MTP generation, profile OFF for headline pp/tg.

## Checks / acceptance

Extend test-kv-pager and test-kv-routing-summary: sealing unchanged clean pages
twice produces no second payload read/build; adding a page doesn't rebuild
old ones; tail advance refreshes just it; overwrite after speculative rollback
refreshes changed rows; reused physical slot never aliases another generation;
resident-table epoch changes leave content summaries intact. Account for
reconcile work once, not once per layer/page.

Acceptance is changed asymptotic behavior with focused tests and a live
before/after receipt. A disappointing remaining speed is input to 25-04, not
grounds to repeat full-context attempts. Record evidence/SPEED25_03_INCREMENTAL.
