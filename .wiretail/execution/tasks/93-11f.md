## Exact benchmark contract

Use only the canonical prompts, with exact bytes and punctuation:

1. `write a python function that merges two sorted lists into one sorted list, with docstring.`
2. `explain the difference between mmap and read for loading large files, one paragraph.`
3. `write a bash script that watches a directory and prints new files as they appear.`

For **each prompt, in each geometry**, issue exactly one discarded warmup with
a 40-token output limit, then exactly three measured requests with a 400-token
output limit. Use greedy `T=0` and reasoning/thinking mode **off**,
the normal chat-completions route, and no added context/filler. Do not use
`--one-case`, `--one-trial`, the `large` variant, shortened generation, or a
reduced measured-run count. The expected complete matrix is 2 geometries × 3
prompts × (1 warmup + 3 measured) = 24 requests.

## Runtime configuration

- Canonical model: Qwen3.8-27B UD-IQ4_XS; record its resolved SHA-256.
- Build one immutable CUDA candidate from the checked-out task source and use
  that exact binary for both geometries. Verify endpoint PID, executable
  realpath/SHA, model realpath/SHA, and full live command before requests.
- Run `--mode selective`, `--page-size 256`, `--context 8192`,
  `--kv-hot-pages 16` (4096 target tokens), `--kv-pin-recent 4096`, and
  `--kv-vram-budget auto --kv-host-budget auto`. This is the deliberately
  small 8K-total/4K-hot iteration point. Context and actual target GPU-hot KV
  must each remain at or below 49,152 tokens (48 Ki tokens); 8K/4K is the
  starting point, not a required minimum capacity.
- MTP is **always on** for all warmup and measured requests: pass
  `--mtp native`, retain `draft_n_max=2`, require draft KV device `gpu`, and
  require Turbo4 for target K/V and draft K/V. Do not run an MTP-off speed row
  or silently move any of these caches to CPU.
- Set and record actual `-b/-ub` as 1024/256 for the primary run and 512/128
  for the secondary run. All other settings, including context, hot-page
  limit, prompt bytes, candidate, model, sampler, and MTP settings, must match.
- Start with context 8192 and 16 hot pages. If startup fails for a measured
  configuration reason, preserve that raw failure, correct the cause, and
  repeat; if measured CUDA headroom requires it, lower context/hot pages in
  256-token-aligned steps, then repeat **both** geometries at the same actual
  context/hot limit. Never exceed 49,152 tokens, silently relabel geometry,
  reduce `-b/-ub`, or proceed with only one geometry. Keep at least 512 MiB measured
  VRAM headroom after peak scratch; if not, lower H/C and repeat both rows.
- Use the established managed lifecycle and `sudo -n` only. Do not launch a
  second Qwen CUDA server or touch port 8092. Keep a successful tested profile
  loaded for the following task; restore only on failed-start recovery or an
  explicitly requested control/revert.
