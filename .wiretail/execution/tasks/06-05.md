# 06-05 — Implement the exact page-wave reference

## Objective

Provide an explicit exact mode in which all logical Turbo4 target pages participate, using bounded GPU
staging and online-softmax state merging. This is a correctness and selective-quality oracle, not a
selective-mode throughput requirement.

## Read

- `CONTRIBUTING.md`, any current `AGENTS.md`, task README, and plan sections 2, 8.4–8.8, 9.4–9.5,
  10–12, and 16.
- Final selective acceptance evidence and handoffs from 03-01 through 06-04.
- Existing dense/Turbo4 FA online-softmax implementation, page-table operator, native-position masks,
  host catalog, upload scheduler, and numerical reference tests.

## Exact-mode contract

- `--kv-pager exact` includes every valid logical token position exactly once, including cold pages.
- Keep the normal hot set resident. Stream remaining host Turbo4 pages through a separately budgeted,
  bounded staging ring in deterministic waves; never gather/dequantize the full cache into F16.
- For every query/head/layer, each partition produces online-softmax state `(m, l, o)` where `m` is the
  local maximum, `l` is the shifted exponential sum, and `o` is the shifted weighted-value sum. Merge
  states with the numerically stable associative formula and normalize only after all partitions.
- Preserve native logical positions, causal/window masks, valid rows in the tail, GQA mapping, and
  Turbo4 K/V decoding. Page order and wave size must not change semantics beyond declared floating-point
  tolerance.
- CPU processing of cold pages is optional and must not be used until a separately tested CPU Turbo4
  attention primitive exists. The mandatory first backend is GPU page-wave staging.

## Implementation steps

1. Add internal partial-attention state/output support without changing feature-off dense execution.
2. Run resident pages as one or more partitions and stream every cold page exactly once through staging.
3. Overlap uploads and compute with double buffering where safe, but keep a serial deterministic mode
   for diagnosis.
4. Merge partition states on GPU when practical; any CPU merge must transfer only bounded partial state,
   not K/V or attention matrices, and must be justified by measurements.
5. Add exact-mode ledger/logging for pages visited, duplicates/misses, waves, bytes, waits, peak staging,
   and numeric comparison.

## Tests and acceptance

- Unit-test the merge formula against direct softmax, including highly unequal maxima, empty/tail
  partitions, and randomized partition/order splits.
- Compare dense existing Turbo4 FA, selected-all-pages, and exact waves at bounded contexts for outputs
  and logits within a predeclared tolerance.
- Test one page, non-multiple tail, permuted slots, logical gaps, 304+ pages, wave sizes 1/many, and both
  serial/double-buffer schedules. Assert no missing or duplicate logical positions.
- On the reference system, run exact at 256K if feasible and preserve time/memory/transfer evidence. If
  runtime makes the full quality corpus impractical, a full-context deterministic checksum/logit fixture
  plus bounded quality comparisons is acceptable only when clearly disclosed.
- Compare selective answers/logits against exact on the predetermined focus/needle/churn corpus and add
  the quality delta to final evidence without retuning thresholds afterward.

## Stop conditions

Block on a full-context GPU allocation, full-cache F16 gather, missing/duplicate page coverage, unstable
merge numerics, or silent fallback to CPU Q8_0. Slowness alone is not a correctness blocker; report it.

## Handoff

Record the merge equations/tolerances, page coverage proof, staging ledger, dense comparisons, exact vs
selective quality delta, raw CUDA artifacts, and any optional CPU-path decision.
