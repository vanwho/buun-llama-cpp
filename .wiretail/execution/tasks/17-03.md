# 17-03 — Make the benchmark adapter contract-safe

## Objective

Ensure the pager adapter validates the complete run without leaving a failed
candidate loaded or confusing a harness defect with a runtime result.

## Read

- Cluster `17a-harness-contract`, handoffs 17-01 and 17-02, the canonical
  profile runner, adapter, contract validator, and V2/V3 evidence schemas.

## Work

1. Separate canonical-run exit status from adapter post-run validation status.
2. On adapter-owned failure (missing telemetry, identity mismatch, unhealthy
   service, bad authentication setup, or malformed records), explicitly invoke
   the established restoration path and verify the resulting profile/PID/health.
3. Preserve the default keep-loaded policy only when the complete requested
   run is valid; expose an explicit `--restore-control` path for controls.
4. Make the adapter report a precise failure class and retain raw records,
   lifecycle state, and configuration without changing expected answers or
   thresholds.
5. Add a portable dry-run/mock contract test that covers missing `queue_us`,
   `mtp_backend=not_present`, HTTP 401/403, candidate mismatch, and successful
   keep-loaded behavior.

## Acceptance

Run Python compilation, contract tests, and a controlled short probe. A
post-validation failure must restore the prior profile; a complete successful
probe must remain loaded. The adapter must never call a missing service or
print a key.

## Deliverable

Create `handoffs/17-03.md` and the adapter/tests/docs required for the later
benchmark tasks.
