# 17-13 — Produce and validate physical pager pressure

## Objective

Demonstrate real canonical CPU backing and VRAM promotion/eviction under a
contract-valid long context, with Turbo4 target KV and GPU Turbo4 native draft
KV, or repair the runtime path that prevents those counters from advancing.

## Read

- Cluster `17f-context-pressure`, handoff 17-12, pager residency/transfer
  code, metrics exporter, and the phase-17 soak/performance raw telemetry.

## Work

1. Run contexts at or above the V4 ceiling with prompt payloads that actually
   reach those lengths and span early, middle, tail, and cold pages.
2. Derive a deliberately constrained benchmark VRAM budget from the runtime
   ledger so host pages are required; do not introduce a fixed production hot
   token count.
3. Verify nonzero host residency, promotion/eviction/fault or transfer
   counters, H2D/D2H bytes, queue/copy/wait timing, and page-table epochs.
4. If counters remain zero, trace the full request-to-transfer path and repair
   the generic runtime/telemetry boundary; add deterministic tests for the
   observed failure.
5. Keep native draft Turbo4 KV outside the target pager victim set and record
   its realized rows/bytes/placement.

## Acceptance

At least one long-context selective/churn segment has raw evidence of physical
page movement, or a precise implementation blocker with a focused regression
and remediation direction. Metadata-only host pages do not pass this task.

## Deliverable

Create `handoffs/17-13.md`, runtime/tests if needed, and a hashed raw pressure
probe.
