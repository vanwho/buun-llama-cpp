# 101-17 — Fence prefill at real ownership pressure, not every page

that current U256 prefill is pipelined.

## Selected ownership design

1. Trace `prefill_page_wave_boundary` (~1890) and its synchronize call in
   `llama_context::decode` (~7932), `process_ubatch`, mctx apply/next/finish,
   graph result reset/allocation, `synchronize` (~2405), submitted write commit,
   host snapshot acquire/recheck/release and the existing capture worker.
   Make a compact owner table identifying which buffers/versions each fence
   protects. Separate explicit API/logit/checkpoint/MTP read fences from the
   pager-added page-count fence.
2. Implement a bounded prefill submission wave for the ordinary one-sequence
   contiguous path. Derive wave length from requested B/U, admitted free or
   reusable page slots, staging bytes and graph/input/source lease capacity.
   B1024/U256 may admit up to four microbatches; that is a fixture example,
   not a fixed production four-page rule. Kernel Q tiling remains unchanged.
   Unknown/multi-sequence layouts keep the safe existing boundary initially.
3. Each submitted page/version retains its source slot/allocation generation
   and graph/input owners. Record producer-ready on the actual compute
   stream after K/V writes; a bounded host copy stream waits on that event,
   copies encoded Turbo4, and records copy-done. Host_valid advances only
   after copy success and identity/version recheck. GPU consumers retire
   separately from host copies. An event does not itself pin its source.
4. Consecutive compute on the same stream is ordered without a host-wide
   synchronize. Mutable sideband uploads and scratch/graph reuse obey the
   101-16 lease rules. Do not call scheduler reset while a prior graph still
   uses its allocation. Use retained graph slots or proven ordered reuse;
   bound the retained allocations in admission. Never reuse the same host
   metadata vector/device descriptor while an earlier graph reads it.
5. Poll ready graph/page/copy completions at wave boundaries without globally
   waiting. Wait for the **specific oldest blocking lease/event** only when
   the next ubatch lacks a safe slot/owner or a real query/checkpoint/host-read
   boundary requires completion. Do not introduce a hidden fence in
   `mctx->next`, backend reset, host-summary publication or metrics to replace
   the removed one. Keep public llama_synchronize fully synchronous.
6. Separate write-frontier dirtiness from a final-query catalogue refresh.
   In `seal_kv_pager_pages`, generic pager_policy_dirty must not cause all
   provisional pages to run summary/selector maintenance at each page fence.
   Coalesce completed-page summaries; run cold selection/promotion at the
   final-user query boundary, or bounded capacity-driven evictability work
   needed to continue ingest. Preserve a pending mailbox's wakeup, query
   replay and frozen history during MTP generation. Physical eviction still
   requires canonical host bytes, not necessarily an immediate global rerank.
7. Extend the small CUDA host/pager fixture with at least two consecutive
   page submissions before a host-wide completion, delayed producer/copy,
   exact encoded bytes, tail rollback/cancel, ring exhaustion, overwritten
   slot rejection, and later clean eviction/promotion. Assert bounded lease
   peaks, necessary pressure waits, and no per-page global completion on
   the admitted multi-page path. Keep test-cuda-kv-promotion's no-generation
   history-H2D invariant. No CPU inference/whole L allocation in the fixture.
