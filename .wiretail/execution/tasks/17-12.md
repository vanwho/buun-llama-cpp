# 17-12 — Make acceptance context and soak inputs dynamic

## Objective

Remove the accidental 16K acceptance boundary. Keep small contexts only for
explicit startup diagnostics; make quality, performance, and soak contexts
derive from the immutable corpus ceiling or an explicit measured target. All
target and native draft KV paths used by these runs must be Turbo4.

## Read

- Cluster `17f-context-pressure`, phase-17 manifests, V4 corpus validator,
  `run-quality-corpus.py`, `run-pager-profile-benchmark.py`, and
  `run-pager-soak.py`.

## Work

1. Replace the soak script's fixed context default with `derived` resolution
   from the corpus ceiling or require an explicit `--context`; record the
   resolved value and whether it is diagnostic-only.
2. Reject acceptance runs below the V4 ceiling (currently 22,016 tokens)
   unless an explicit diagnostic flag is supplied. Never silently shorten a
   request or call a sub-ceiling result final evidence.
3. Ensure the launcher passes the resolved context consistently to target KV,
   native draft KV, prompt generation, and telemetry. Draft rows remain
   context-sized and Turbo4/GPU.
4. Add tests for derived resolution, sub-ceiling rejection, explicit
   diagnostic mode, odd tails, and provenance fields.

## Acceptance

The harness has no implicit 16K acceptance default; a dry run prints the
corpus-derived context and mode. A lower context is visibly diagnostic-only.

## Deliverable

Create `handoffs/17-12.md`, portable harness/tests/docs changes, and raw dry-run
evidence.
