# 93-03 — Repair the diagnosed MTP invariant with a minimal code change

Revision: `hotpath-v10-20260914`. Amendment: `repair93-mtp-fast-20260922`.

Cluster: `repair93-mtp-diagnostics-v10`.

## Objective

Implement only the repair proven necessary by `93-02`, preserving the fast
GPU-native attention route and avoiding new per-token telemetry or reference
fallbacks in production.

## Work

1. Read the `93-02` first-bad-rung and root-cause table. Do not invent a new
   architecture or change acceptance thresholds.
2. If the defect is dispatch, fix route selection so automatic selected mode
   chooses only eligible GPU-native direct/packed paths; keep reference
   dispatch behind an explicit diagnostic option.
3. If the defect is page/state parity, fix the exact page-table snapshot,
   immutable submission, Turbo4 stride/head mapping, or publication fence
   identified by the probe. Ensure draft and target see the same logical
   positions for resident pages.
4. If the defect is rollback, repair the sequence cursor/KV write checkpoint,
   rewind ordering, and page-table epoch publication at the identified call
   site. A rejected draft batch must leave the next target token identical to
   MTP-off control.
5. If the defect is dense MTP or Turbo4 kernel parity, isolate it from paging
   and repair the relevant speculative-decoding or CUDA kernel code. Do not
   weaken verification or accept mismatched tokens.
6. Add a focused regression test for the exact failure, build only the affected
   CPU/CUDA targets, and run the four-rung harness again. Keep all commands,
   hashes, and raw outputs in the handoff.

## Acceptance

The minimal repair compiles, the focused regression passes, and the diagnostic
shows either restored high acceptance in the dense control and resident paged
case or a new, precisely localized defect. No long-context run is permitted in
this task.

## Deliverable

Create `handoffs/93-03.md`, `evidence/V10_93-03.json`, the regression test,
and the implementation commit reference. Preserve a null result if the repair
does not yet restore acceptance; do not relabel it as success.
