# 25-11 — Implement cheap attention-aware selection and bounded cold prefetch

Scope revision: speed-first-20260911. Recommended model: Luna High.
Phase 25; cluster `25d-decode-routing`; depends on `25-10`.

## Objective / hypothesis

Attention selection must save more GPU work than its scoring/transfers cost.
Keep a large reusable hot pool H while choosing a smaller A per attention
layer/phase. Enable actual cold recall, not just resident attention EMA.

## Implementation recipe

1. Store compact summaries on GPU updated only for changed page content.
   Prefer4 representative vectors/head as currently supported; initially
   rotate/sample heads or retain head-zero with explicit coverage label.
   Both query and summaries must share native RoPE/Turbo transform coordinates.
   Do not sum incompatible rotated vectors or dequantize full K on CPU.
2. Build per-layer selected lists from current block/recent pages + attention
   EMA retained pages + GPU query-to-all-page-summary candidates. Include a
   small bounded cold exploration slot; unseen cold pages have no resident
   mass and cannot be recalled by EMA alone. Cold query scoring runs before
   QK on the relevant attention layer, not from an unrelated CPU token vector.
3. Keep A independent of H. Test two/three selected fractions for prefill and
   decode at the same H. All current causal query rows must participate;
   select historical rows around them. Production budgets derive from byte
   ledger and selected policy, not a hardcoded77K target or testH.
4. Sample attention mass on a few heads/last query rows rather than outputting
   a per-query/head/all-page matrix. Reduce on GPU to layer/page EMA. Choose
   one cadence from short tests (e.g.every8 or32 decode steps and once per
   prefill wave); skip index/selection updates when contents/query policy
   don't justify them. These are tuning candidates, not universal constants.
5. Add hysteresis/minimum hold and transfer-credit budget. Prefetch a bounded
   number of pages into free slack on a transfer stream, publish only after
   events. Current request never reads inflight pages. Reuse packed A across
   stable steps; measure repack cost on selection changes.
6. Start with existing grouped all-layer residency. Record useful layer bytes
   vs transferred grouped bytes. If grouping is a material cost, extend
   existing residency keys to (sequence,layer-group,logical-page,content
   version), promote only selected layers, retain per-layer strides/tables
   and host versions; avoid an unrelated new cache subsystem. A short bounded
   experiment decides whether this extension belongs in the active path.
7. Run one4–8K natural distant-context query after deliberate eviction and
   changed focus; record GPU summary rank, layer/page selection, real H2D and
   consumption. Answer mismatch is a quality finding, not a failed speed
   experiment, but selection must genuinely be query/attention-dependent.
8. Compare total selector+copy+attention time for the A/cadence candidates.
   Retain an explicit recent-only diagnostic ablation, never headline as
   attention-aware historical recall.

## Checks / finish

No future rows, no protected/current page eviction, nonzero cold page recall,
bounded scan/summary bytes and no old-K re-read regression. Unit-test EMA and
candidate ranking with different queries, hysteresis and invalid versions.
Receipt evidence/SPEED25_11_SELECTION includes layer coverage, A/H, approximation
settings, natural recall, transfer amplification and paired pp/tg.
Quality tuning, full-head optimal scoring and long focus-shift corpus are
options; never substitute them for implementing the cheap working selector.
