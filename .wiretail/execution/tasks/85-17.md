## Outcome

Establish how much hot history fits after real full-L GPU draft and scratch,
and what actual context can be occupied performantly.256K allocation is not
256K occupied proof. Do not rerun a creeping27 tok/s frontier indefinitely.

## Bounded sequence and decisions

1. Read only85-16 speed artifact/handoff and current memory ledger. If small
   target correctness/MTP/cold chain regressed, repair/retest its reproducer
   before scaling. If small-path slowdown guard is violated without a resolved
   explanation, record `scale_deferred_for_named_speed_repair` and the exact
   measured blocker/next source action; do not fill a huge context. Review
   must schedule the repair, not declare full goal success.
2. With a working small path, run32K logical/16K hot pilot (actual C>H using
   cached bounded appends), one final64-token generation with native MTP and
   actual cold promotion. Derive A, safe B/U from measured settings; preserve
   optional larger-U ingest profile if faster and fits. No full three-prompt
   comparison repeated at each C, and no longCPU control needed for iteration.
3. Profile memory at prompt peak, native verify, rejection/checkpoint and warm
   decode. Ledger: weights, full-L Turbo4 draft, target H, recurrent state,
   A workspace, catalogue/row maps, graphs/Q scratch, copy ring, reserve. Measure
   at two safe U values and two L values to distinguish L-, H-, A-, U-dependent
   memory; do not fit one linear slope to all. Account recurrent state/graph
   fixed overhead. Choose maximal H leaving observed safety reserve, not70K.
4. Assess128K then262144 logical allocation with full-L GPU Turbo4 draft.
   Shrink H/A/U to preserve draft and scratch as needed; no draft clipping,
   CPU draft or codec change. Admission/startup success is one claim. Add a
   brief request with enough room for verification and recorded headroom before
   attempting occupancy. An OOM within recoverable layout is a config repair,
   not terminal capacity failure; stop owned restart loop and retry corrected.
5. Once pilots are fast, perform ONE resumable cached-ingest traversal toward
   actual262144 capacity, reserving output tokens so the last measured request
   is legal. Each append is token-counted and prefix-preserving; persist raw
   requests/responses and frontier only after successful commit. Measure phase
   times and promotions at chosen intervals; don't regenerate six separate
  200K prompts. Final requested20K/40K/60K/100K/175K/256K curve is a reporting
   campaign at the end, not every step's acceptance gate. Reuse checkpoints/
   frontier if valid across the same bundle; never reuse state from a different
   binary/config silently. Exact C must be reported (L minus output reserve at
   final capacity), not falsely round occupied history to262144.
6. Use calibrated request/time budget and no-progress watchdog. At a >4x
   matched-small/pilot slowdown, take one short profile, identify whether
   selected A grew, dense/global scan leaked, CPU fallback, weight/scratch
   pressure or transfers dominate; fix an obvious local/config cause and retry
   that interval. Otherwise stop larger work with precise finding/remediation,
   not hours of progress-only polling. Context-dependent attention costs are
   measured; guard is a trigger for attribution, not arbitrary performance pass.
7. Record meaningful batching tradeoff: smaller U reduces scratch but can
   lower prefill matrix efficiency; API chunks/queued prefill may use all
   context over many turns without allocating scratch for a200K single batch.
   No claim that reducing input chunk length reduces full-L draft memory.
   YaRN beyond256K remains stretch work only after native target goal.
