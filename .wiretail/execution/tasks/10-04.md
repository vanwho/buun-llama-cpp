# 10-04 — Implement bounded selected Turbo4 prefill and transition to decode

## Objective

Make prompt ingestion operate across compact pages without allocating target GPU attention/scratch for the
full logical context, and hand off safely to direct paged decode.

## Read

- Task README, cluster `10b-live-prefill-exact`, plan 22 step 6.
- Handoffs 03-04, 09-03–09-05, 10-01–10-03.
- Batch/ubatch graph construction, Qwen prefill attention, KV writes/seals, selected reference/direct
  routes, graph allocator and prompt-cache/checkpoint ingestion.

## Implementation

1. Define prefill chunk semantics for `off|observe|selective|exact`: write/query ranges, required causal
   pages, retrieval timing, page sealing, and first-decode table.
2. Implement a bounded Turbo4 selected prefill path. Start with the selected reference route if necessary,
   then optimize supported query blocks without building a full-context F16 K/V buffer.
3. Bound Q/query scratch plus selected K/V rows by configured batch/ubatch and `H`; stream/seal completed
   pages and release obsolete graph resources between chunks.
4. Preserve native positions, causal masks, odd tails, attention/recurrent hybrid order, MTP frontier, and
   generation fences. Handle cancellation or seal failure atomically.
5. Reuse graph shapes when safe; report rebuild and allocation high-water.

## Tests and benchmark

One-page, boundary-crossing, many-chunk, odd-tail, prompt longer than `H`, table change between chunks,
cache reuse, checkpoint restore, cancellation, first decode, and feature-off. Compare final logits/tokens
against dense where it fits. Run five-trial prompt-throughput/TTFT checkpoint at multiple prompt lengths;
record scratch/VRAM and page seal/transfer time.

## Acceptance

Long prompt ingestion crosses hot capacity, produces authenticated host pages, remains within device
ledger, matches dense on bounded cases, and enters direct decode without stale graph/table state.
