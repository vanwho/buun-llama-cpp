## Implement

1. Create a build-time receipt in each new candidate bundle. Build the actual
   server target and transitive project DSOs first. Include full source HEAD,
   tracked index/worktree diff fingerprint and relevant untracked source,
   toolchain/configuration fingerprint, executable plus project DSO relative
   paths, size, SHA256 and build IDs. Exclude .wiretail/results/build outputs
   from source fingerprint. Bundle with runtime library lookup bound to it;
   finalize immutable receipt only after successful build/copy. Do not hash
   the receipt into itself. Unknown build source is `unknown`, never current HEAD.
2. `write_bundle_manifest()` must ingest and verify that immutable receipt;
   it must not invent source_commit from the invoking checkout. Store current
   checkout separately as `invocation_source`. Refuse comparative benchmark
   claims if required repair source fingerprint is not the built fingerprint.
   A read-only old binary is not proof it includes a new repair.
3. Verify loaded executable and project DSOs by **endpoint-owning process**,
   using the existing site runner's managed MainPID/socket identity, hashes
   and resolved paths. Do not use first `pgrep llama-server`, inspect unrelated
   8092 as provenance, or print process environment secrets. Portable adapter
   receives observations through its existing runner boundary.
4. Distinguish requested/effective L,C,H,A,B,U/page size, target+draft type,
   draft capacity/device, source identity and measured request tokens. Derive
   H from hot pages*page_tokens if that is observed; reject contradictory
   observations. Tokens already cached and newly evaluated are separate. A
  30-token request with `--context 6144` must fail a C6144 campaign assertion.
5. Fix pair aggregation: mode is the intentional difference, q index/token
   digest/config identity form the pair key. Keep all trials. Missing matched
   q1/q2 controls => null ratios. Use raw `timings.*_per_second` consistently;
   expose separate wall metrics, no128/127 interval convention mixing.
6. Separate tiny launch/readiness smoke from actual C>H test. Repair parameter
   propagation so the long-prompt helper creates/tokenizes the requested
   occupied prefix, not simply sets maximum context. Require observed cache
   reuse on append. Use structured error codes for identity/token/placement
   mismatch before performing a large test.
