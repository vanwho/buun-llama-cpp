   manager, identify the first rejected proposal on each path. Compare the
   target's verification logits/probability (top 8 sufficient), the draft's
   proposal/sampler inputs, absolute token/position, recurrent/GDN state

   diagnostic switch; never dump whole logits or synchronize a GPU per token
   in normal operation. Check if incoming sampled-proposal/dual-graph changes
   altered the meaning of `drafted` versus `accepted` before comparing ratios.
2. Reproduce one first-divergence case deterministically in
   `tests/test-speculative-mtp-state.cpp` plus the CUDA owner if needed: same
   query replay changed/unchanged histories, accept/reject, rollback, next
   proposal. Assert draft full-L Turbo4 GPU placement, no stale provisional
   target/draft tokens, exact target and draft position/frontier, MTP carry
   restore and proposal-accounting denominator. A CUDA fixture must test
   Turbo4 computation; CPU float oracle tests only state bookkeeping.
3. If resident (a) differs from feature-off/dense native-MTP control with
   identical tokens/sampler, repair the *first* position/carry/graph/state
   owner. If (a) is sound but (b) drops, compare target selected-view mask
   versus draft full-L logits. If target/draft distributions genuinely differ,
   record `sparse_target_dense_draft_mismatch`, do not falsify acceptance or

   explored only if it preserves full-L resident KV and is measured to improve
   both acceptance and net decode. If (b) differs even when selected view and
   target logits match, repair replay/cancel/graph input ownership first.

   repair. The three-prompt 400-output median belongs to 100-03i. Low but
