## Exact files and changes

1. In `src/llama-kv-router-job.h` add `llama_kv_router_layer_plan` plus an
   owned page descriptor type. Fields: query identity, compact attention layer,
   model layer ID, explicit probe_capture_generation, borrowed GPU
   probes/validity/resident-K tensors, original
   page_tokens, Q/KV heads, key dimension, actual attention scale/softcap,
   resident/cold candidate descriptors and cold-reader holders. Each descriptor
   includes immutable candidate, valid_rows, stream, physical_slot if resident,
   first absolute row, page/content/summary generations and key-side unit ID.
   This is host metadata of size H+K, NOT another encoded-key copy.
2. In cache add `prepare_router_query_layers(seq,turn,plans,error)`; factor
   the authentication part of `complete_router_query_job` into this real
   production method. Use `pager_->turn_state`, `pager_->exact_page_records`,
   `pager_->residency`, `pager_coarse_shortlists_`, `pager_query_accumulators_`
   and `pager_->snapshot().geometry` as existing inputs. Keep capture identity
   generation and final-user position checks. Do NOT require owner ready here.
   The capture uses model layer ID; shortlist uses compact layer index. Map via
   geometry.model_layer_ids explicitly instead of assuming model layer==index.
3. Resident keys come from the matching cache `layers` entry, same tensor and
   strides as production attention. Preserve flattened[D*KVheads,rows,streams]
   layout and slot addressing; no reshape that interprets streams as heads.
   Derive scale and logit_softcap from the actual model attention configuration
   used to build attention, including any softcap predivision convention:
   rerank expects raw scale and applies `cap*tanh(dot*scale/cap)` itself.
   Freeze these values in the plan; no fixture constants in production.
   `build_kv_page_select` currently passes literal1.0f to ggml_kv_page_rank;
   replace that probe-mode argument with the same model-derived raw scale.
   Coarse min/max is still an approximation; exact rerank applies softcap.
4. Pool contains EVERY eligible incumbent historical resident page, plus the
   authenticated bounded cold shortlist (K from existing coarse algorithm).
   Deduplicate exact page identities per layer. Current/query/tail/pinned pages
   are structural policy protections, not historical competitors to evict.
   Reject stale identities, content or summary versions individually; an invalid
   entire layer returns typed setup/stale error, not silent legacy fallback.
   Valid no-cold input still completes resident-only ranking. A zero-record
   shortlist must be representable as a completed participating layer; change
   retain_coarse_shortlist/decoder bookkeeping accordingly. Do not equate
   nonempty vector count with completed layer count.
5. For each cold descriptor obtain an immutable canonical host view using the
   SAME full-identity/bundle fallback as the `find_host_page` lambda inside
   `apply_pager_live_policy`. Inspect the actual catalog return type in this
   checkout (do not assume another VBR catalog class). In that copied view find
   `page.units` key side, matching geometry.unit_descriptors logical_unit_id
   and compact/model layer; validate representation type, row_bytes and
   valid_rows. `vbr_selected_page_unit_descriptor::bytes` is the immutable
   `shared_ptr<const artifact_segment_chain>`; retain it, never raw temporary
   catalog pointers. Read only K through its existing `read` API.
6. Add a small owned reader-context object retained through
   `llama_kv_rerank_stage_source.page_holder`. It stores copied identity,
   version, key unit descriptor and shared chain. `read` delegates to chain
   with byte offset `row_offset * unit.row_bytes`; bounds-check multiplication,
   offset+size and complete encoded rows. `recheck` validates frozen version
   and cache currency before submission, not merely version==constant. A source
   becoming stale during flight is rejected again before terminal adoption.
   No all-layer bundle copy and no reading V for the reranker.
7. Make reader/source lifetime explicit: plan owns sources until queued reader
   tickets own them; cache detach/reset/rollback aborts plans only after reader
   events retire. Query probes and resident-K remain borrowed from the cache;
   target final-user fence retires before reading them. Don't free their owning
   context while the dedicated ranking backend can still read them.
