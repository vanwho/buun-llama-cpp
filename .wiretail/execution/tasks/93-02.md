# 93-02 — Localize MTP versus paged-K/V divergence with parity probes

Revision: `mtp-diagnostic-v10-20260922`. Amendment: `repair93-mtp-fast-20260922`.

Cluster: `repair93-mtp-diagnostics-v10`.

## Objective

Use the bounded rungs from `93-01` to identify exactly where acceptance first
diverges. This is a source-level diagnosis, not another long benchmark.

## Work

1. Compare MTP-off dense against MTP-on dense first. If dense MTP is already
   low, inspect draft model invocation, draft/target logits, sampling/seed,
   speculative token positions, and rewind/rollback in the server MTP path;
   do not blame paging. Capture the first differing token/logit position.
2. If dense MTP is healthy but selected/all-pages-resident MTP is low, compare
   target and draft route records for the same request. Verify both use the
   same logical token positions, page-table epoch, page contents, Turbo4
   block dimensions, head/group strides, and causal mask. Inspect the route
   plan and execution functions in `src/llama-kv-attention-execution.cpp` and
   the server context/speculative-decoding call sites.
3. Check rollback and rewind at every rejected draft batch. Confirm that the
   target sequence position, KV write cursor, page-table publication epoch,
   and draft sequence position return to the same pre-verification state.
   Add temporary debug assertions or test-only structured logging rather than
   printing whole tensors.
4. For any mismatch, add a deterministic focused CUDA regression fixture that
   compares the first differing position and records expected/actual route,
   epoch, dimensions, and position. Do not hide the mismatch by falling back
   to `selected_reference`.
5. Classify the result as one of: `dense_mtp_defect`,
   `paged_state_or_route_defect`, `turbo4_kernel_defect`,
   `rollback_defect`, or `harness_setup_defect`, with source file/function and
   exact state transition cited.

## Acceptance

The handoff identifies the first failing comparison rung and a concrete code
location/state invariant explaining it. A zero-acceptance result without a
first-difference diagnosis is incomplete.

## Deliverable

Create `handoffs/93-02.md`, `evidence/V10_93-02.json`, focused test/log output,
and a short root-cause table linking each observed mismatch to source code.
