# 13-02 — Optimize direct Turbo4 paged decode

## Objective

Reduce the dominant paged-attention decode costs identified by 13-01 while preserving direct Turbo4
storage, output tolerance, telemetry semantics, and dynamic capacity.

## Read

- Task README, cluster `13a-kernel-transfer-opt`.
- Handoffs 10-02, 10-03, 11-03, 13-01; CUDA profiles/resource logs and current Turbo4 FA loaders.

## Work

1. Reproduce the baseline microprofile before editing.
2. Test profile-supported candidates one at a time: compact/aligned descriptor layout, host-to-device table
   update elimination, logical-run coalescing, metadata cache, vectorized Turbo4 loads, head/block mapping,
   register/shared-memory balance, launch fusion, and page-mass reduction fusion/cadence.
3. Retain only changes with repeated statistically meaningful end-to-end or kernel improvement and no
   material regression in other frozen shapes.
4. Preserve generic runtime dispatch/capability checks. Specialized templates may use validated geometry,
   but no context/hot count or machine assumption.
5. After each retained group run dense/reference/direct parity, tails/permutations/gaps, backend ops,
   memcheck/racecheck, resource usage, and MTP acceptance smoke.

## Acceptance

Meet the task-specific kernel/total-token budget from 13-01 or document and test at least three distinct
profile-driven hypotheses before a genuine block. No selected page, telemetry output, or quality check is
removed to create speedup. Preserve before/after raw results including rejected variants.

## Deliverable

Create `handoffs/13-02.md` with each hypothesis, code delta, repetitions, confidence/noise, kernel resources,
parity/sanitizer results, and cumulative improvement.
