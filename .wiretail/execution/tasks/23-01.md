# 23-01 — Reserve late CUDA allocations before automatic hot-page admission

Recommended model: **Luna High**. Phase 23; cluster `23a-runtime-repair`.
Depends on: `22-01`.

## Measured gap and hypothesis

Phase 21 showed 175K recurrent-state allocation failures, 262K compute-buffer
allocation failures, and an automatic 262K hot-page OOM that recovered with four
pages. Hypothesis: automatic admission samples or charges VRAM before reserving
the late recurrent, graph/compute, native-MTP, and allocator-guard allocations,
so target slots consume their headroom. Owner: `llama_context::init_kv_pager`,
the cache-budget admission planner, context allocation order, and graph reserve.

## Minimal reproducer and implementation

1. Reproduce one 175K and one 262,144 startup using the same release inputs,
   `auto` hot pages, unchanged Turbo4 codecs/MTP rows, and allocation-category
   tracing; retain the fixed-four-page run only as a control.
2. Give the pure planner explicit measured/estimated charges for recurrent
   state, full GPU MTP, worst-case compute graphs, routing/tables, staging,
   allocator granularity, external use, and safety reserve before it admits a
   target slot. Use checked arithmetic and monotonic retry from I1; unwind each
   failed attempt and fingerprint tried tuples.
3. Reconcile estimates with post-warmup allocations without increasing the hot
   set beyond verified headroom. Never shrink context/MTP rows or encode four
   pages as a production answer.
4. Add deterministic planner/allocation tests for late charges, exact-fit,
   deficit rounding, retry termination, shared-buffer accounting, and zero legal
   slots. Run the two startup probes and a bounded request.

## Measurement change and deliverables

`auto` must report its complete byte ledger and start at 175K and 262,144 with a
nonzero budget-derived target pool, resolved MTP rows, and post-warmup headroom;
otherwise emit the smallest failed category and tuple. Produce
`handoffs/23-01.md` and `evidence/PHASE23_ADMISSION.json/.md`. Run focused tests,
state validation and `git diff --check`; keep a successful candidate loaded.
