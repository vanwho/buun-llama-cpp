## Ordered implementation / experiment

1. Launch the feature-off ordinary CPU-KV control with GPU model/recurrent execution, Turbo4 K/V and independent full-size Turbo4 GPU MTP. Record actual placement and supported attention backend.

2. Distinguish unsupported CPU Turbo4 ops from OOM, auth and timeout. If the required existing CPU op lacks Turbo4 support, add a minimal correct generic reference path with backend tests rather than silently substituting F16 or all-CPU inference.

3. Verify a short same-prefix all-GPU versus CPU-KV control for correct outputs, including native MTP; record numerical differences and backend execution details.

4. Measure a small and a pressured occupied context to estimate realistic long-control run times. Persist resumable control configs and sampling/cache settings for phase 21.

5. Verify the safe all-GPU Turbo4+MTP maximum independently with a memory ledger; contexts where it cannot fit get an explicit unavailable denominator, not a smaller-context ratio.

6. Keep this task scoped to a valid comparison, not optimizing the CPU baseline to match the pager or expanding CPU cold-exact requirements.

## Concrete execution recipe

Read `EXECUTION_COOKBOOK.md` sections C1/C2/C3/C4/C5 and `IMPLEMENTATION_CONTRACTS.md` sections I6. These are shared context; reuse them within the cluster.

Verify the existing independent draft-placement flags before adding code:
ordinary target CPU KV plus --spec-draft-kv-device gpu, native MTP and all four
Turbo4 cache types. Inspect actual backend buffers and graph placement.
A launcher label or low VRAM use does not prove the intended CPU-KV control.

If a CPU Turbo4 attention op is missing, first make the smallest known-shape
CPU numerical reference from actual decoded Turbo4 values/domain with backend
tests. Reuse the existing type/transform code, not a codec substitution. Keep
model/recurrent execution on the intended GPU path and record unavoidable
scheduler moves explicitly; all-CPU model execution is a different ablation.

Run two purpose-appropriate occupied lengths and the same-prefix driver.
Export tested baseline argv, actual placement, pp/decode estimates and supported
limit for phase 21. An unsupported control yields an explicit implementation
blocker, not a 42 tok/s all-CPU number relabeled as ordinary KV offload.
