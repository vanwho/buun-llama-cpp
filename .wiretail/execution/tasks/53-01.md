# 53-01 — Repair VBR scratch reservation at the full-L request boundary

Revision: `hotpath-v10-20260914`. Cluster: `53a-vbr-scratch-v10`.
Model: Luna High; first retry High. Prerequisite:52-01.

## Objective

Fix the measured boundary-accounting defect that lets the first
`L262144/H30208/B128/U128` request reach `kv_dequant_scratch()` and abort while
growing a 512 MiB VBR f16 buffer. This is a production repair, not permission
to reduce L, move draft KV off GPU, or replace Turbo4 FA.

## Bounded source and contract

Work around `ggml/src/ggml-cuda/fattn.cu::{kv_dequant_scratch_try,
kv_dequant_scratch,ggml_backend_cuda_kv_dequant_scratch_reserve,
ggml_backend_cuda_kv_dequant_scratch_memory}` and the boundary callers in
`src/llama-kv-cache.cpp` at the existing reserve/preflight path. Derive K/V
scratch from the actual submitted view and charge both representations and
alignment before graph execution. A successful boundary reserve must leave all
bytes needed by the request mapped; a failed reserve must return before graph
submission without partial pager/sequence mutation. Growth remains outside
capture and scratch epoch invalidation remains truthful.

## Fixture and numerical test

First preserve the smallest failure from
`/srv/ai/paged-kv/results/v10/51-04/20260914T-256k-h30208`. Add or extend a
focused CUDA scratch test to request the observed K/V sizes (including the
512 MiB side), assert `physical_if_reserved >= required_bytes`, and exercise a
retry after recoverable reserve failure. Then run one live 1200-token request
at exactly `L262144/H30208/B128/U128`; assert no mid-graph scratch abort,
`C > 0`, and unchanged Turbo4/GPU draft placement. Verify graph replay after
the eager reserve.

## Stop condition and receipt

Stop at the first remaining allocation or ownership mismatch; do not tune
throughput or begin 256K occupancy if the fixture still aborts. Required proof
is `vbr_scratch_boundary_repair`, with a hashed raw test log in
`V10_53-01.json`; record the before/after discriminator and exact live result
in handoff `53-01.md`.
