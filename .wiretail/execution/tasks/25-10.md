## Objective / hypothesis

Make changing KV contents cheap graph data updates. First measure actual CUDA
graph behavior; do not infer it from the pager's graph_capture_count counter.

## Implementation recipe

1. Export actual capture/instantiate/update/launch counters and CPU durations
   behind cheap optional diagnostics; label admission counters separately.
   Measure a fixed-shape decode span and one selection change.
2. Separate immutable shape/codec/layout/address identity from mutable
   descriptor contents, native position values, page IDs and content epochs.
   Use preallocated double-buffer descriptors with generation/fence ownership.
   Table changes should upload O(changed pages) compact records, not expand
   all logical native positions on CPU every token.
3. For ordinary sequential pages, derive row native position from
   page.position_begin+row; keep an exception path for genuinely irregular
   rows. Avoid hotset-sized reference F32 scratch accounting on direct routes
   that never allocate it. Prove which route actually needs each buffer.
4. Bucket query/selected-page extents only where masked padding preserves
   causality and memory safety. Reuse executable graphs when legal, update
   eligible parameters/data otherwise. Keep real graph recapture if address/
   op topology/scratch changed. Do not hide generations to fake cache hits.
5. Move allocation, host descriptor validation and function-attribute setup
   out of the per-token CUDA capture region. Lifetime of device table,
   staging data and graph users must be explicit.
6. Compare normal graph use vs graph-disabled diagnostic at same settings
   (only existing supported switch or test hook). Record real launches,
   updates and CPU gaps; do not require a new public graph flag.

## Checks / acceptance

Tests change content with stable shape, swap physical page generation, change
query bucket, resize scratch, finish old readers before table reuse, and
poison stale masks. Same small pressure request remains correct.
Evidence/SPEED25_10_GRAPHS records actual backend events and total throughput.
If actual capture already is amortized, implement only measured descriptor/
allocation reductions and document capture as not the bottleneck.
