# 21-02 — Remove serialized three-token paged prefill

Recommended model: **Luna High**. Phase 21; cluster `21a-quality-curve`.
Depends on: `21-01`.

## Objective

Make selective Turbo4 prefill fast enough to measure. The current path caps
Qwen paged prefill at three query tokens and synchronizes after every chunk;
this causes CPU-heavy graph orchestration and sub-20-token/s prompt rates.
Replace that safety workaround with bounded page-wave batching while keeping
page writes and eviction correct.

## Implementation

1. Trace `llama_context::prefill_ubatch_size`, `process_tokens`,
   `prepare_kv_attention`, and the selected CUDA graph path. Confirm the current
   chunk size, synchronization count, route, and page reservation behavior with
   a deterministic fixture before editing.
2. Add a page-wave planner that chooses a configurable query tile (start with
   16 or 32, reduce only when the physical page budget or workspace requires)
   and submits multiple tiles without a device-wide synchronize between each
   tile. Policy updates may occur at page boundaries; they must not force one
   graph per token.
3. Extend the Turbo4 paged CUDA attention kernel/metadata for query tiles larger
   than three, or implement an equivalent tiled GPU path. Keep causal masking,
   page gaps, tail pages, grouped-query head ratio, and online-softmax state
   exact across waves. Do not gather the entire cache into F16 scratch.
4. Retain a bounded fallback for unsupported geometry, but expose a route
   counter and reason. A fallback must not be silently reported as direct
   Turbo4 execution.
5. Add CPU/unit and CUDA tests for 1/3/16/32-query tiles, page boundaries,
   partial tails, logical gaps, and parity against dense attention. Add a
   regression asserting synchronization count is wave-bounded rather than
   proportional to token count.
6. Benchmark one 4K and one 8K prompt with pager off/observe/selective using
   the same binary. Record prompt rate, GPU utilization, graph launches,
   synchronization time, and route fractions; do not start a corpus campaign.

## Acceptance

The focused tests pass, direct or intentionally bounded reference routing is
observable, and the selective prefill diagnostic shows a materially larger
query tile without numerical regression. If the direct kernel cannot yet be
extended, leave a tested page-wave reference path and create a concrete owner
for the remaining CUDA optimization; do not claim the speed goal.
