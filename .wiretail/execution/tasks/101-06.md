# 101-06 — Encode current KV once and append packed rows by GPU byte copy

Revision: `hotpath-v10-20260914`. Amendment: `gpu-execution-101-20260930`.
Cluster: `gpu101-storage`. Implementation/assessments: gpt-6-luna High.
Dependency: 101-05. Read SPEED101, TESTING and handoff101-05 only.

## Ownership decision

Canonical **resident GPU** cache writes produce the encoded current K/V once.
The packed attention workspace consumes those bytes; canonical host capture
later consumes the same bytes. No CPU attention, dequantized gather, second
Turbo4 SET_ROWS quantization, or host staging of packed current rows.

## Code sequence

1. llama-graph.cpp::build_attn (~5255) currently appends with a second
   ggml_set_rows into packed_k_owner/packed_v_owner. Trace cache_k_write and
   cache_v_write dependencies and the indexed physical destinations. Build
   a graph-ordered encoded scatter/copy using byte counts
   ggml_row_size(type,cache_head) per KV head, actual layer nb[] and mutable
   physical-source/packed-destination row descriptors. Never use GET_ROWS
   on Turbo4 expecting an encoded copy; it is a dequantization operation.
2. Reuse existing packed history copy machinery (~1040 and ~4650) for contiguous
   runs. For noncontiguous current rows, add the narrowest generic encoded
   KV row-copy ggml/CUDA operator if existing byte CPY cannot express the
   dependency and index mapping. Put reusable declarations/shape checks in
   ggml, GPU implementation beside existing copy/set_rows kernels, and CPU
   implementation as **byte storage copy only**, not TurboQuant inference.
   The operator must explicitly depend on canonical write results; tensor
   alias order in a graph is not sufficient without a dependency.
3. Preserve K/V domain names, codebook/mean/scales and padding exactly. Do
   not reconstruct K/V from floats. Verify byte parity of current append
   vs canonical encoded row, including the V rotation/mean convention that
   caused prior packed/native differences. Standard quant/F16 rows use the
   same generic bytes where their physical layout supports it.
4. Delta history refresh copies only inserted/changed page-version spans;
   immutable unchanged rows are not repacked each decode. Keep packed row
   index and native token positions distinct. Snapshot/pin source and owner
   identities for async readers, retire them on completion, and invalidate
   provisional current rows on rollback without touching committed history.
5. CUDA fixture covers one page/tail, fragmented source slots, native gaps,
   Q3 verify, acceptance1/2 and rejected provisional rows, plus byte equality
   and attention equality after append. Test the source-write dependency
   with nondefault streams using existing backend event semantics; no host
   fence per row. CPU tests validate only descriptor bounds/byte copies.
6. One matched operation timing for duplicate-encode vs encoded-copy at
   U256/H4096 and Q3; retain the simpler existing path if layout aliasing
   makes a safe byte-copy slower, with actual timing and an explicit reason.
   This disposition must not be based on an unrelated 27-token request.
