1. Inspect `ggml_cuda_graph_get_key/update_required`,
   `ggml_backend_cuda_graph_compute`, `ggml_cuda_graph_diagnostics_log` in
   ggml-cuda.cu (~4030/4090/8250), `llm_graph_result::can_reuse`,
   `llm_graph_input_mem_hybrid::can_reuse`, and ordinary attention reuse in
   llama-graph.cpp. Existing101-05 already fixed some hybrid checks and
   admitted packed capacity. Do not recreate those fixes from an old packet.
2. Use101-13 actual driver capture/launch evidence. If compatible Q256
   prefill and Q1/2/3 verify calls already warm/replay correctly and launch
   CPU time is <5% of isolated prefill, do not invent a new graph cache. Prove
   changed descriptor content survives a real graph replay in the existing
   CUDA fixture and record the measured no-change disposition.
3. Otherwise record the **first changed property** defeating warmup: node
   shape/stride/op params, src pointer, scratch epoch, allocation generation,
   sequence layout or route. Fix that owner, not the memcmp/uid safety guard.
   Keep admitted page/row/packed capacity and device addresses stable through
   a compatible call family; vary active row/page/tail lengths via the
   existing device_control. Separate Q256, short final-Q and verify widths;
   do not compute over full L or mask unsafe padding to fake reuse. Changes
   of representation/allocation/head/sequence layout still invalidate graphs.
4. Audit `llama_kv_cache_context::set_kv_page_select_inputs` (~18521),
   `set_kv_query_accumulate_inputs` (~18723), and
   `llm_graph_input_attn_kv::set_input` (~800). CUDA tensor_set already uses
   `ggml_cuda_upload_async` for small writes. Do not blame synchronous copies
   without the fallback/wrap data. If those waits matter, coalesce changed
   contiguous page-sideband runs and reuse one epoch-bound inventory across
   layer inputs instead of allocating/reducing/walking it separately per
   layer. Keep tiny disabled-query controls ordered and skip equal values.
5. Any new async path must own host staging until copy completion and order
   graph reads after upload, **and uploads after the prior graph's reads** if
   the same device input is reused. Stack page_data/controls and temporary
   vectors cannot simply become asynchronous source pointers. Use the
   existing pinned ring/backend events or an admitted graph-input lease;
   no naked cudaDeviceSynchronize or new model-wide upload queue.
6. Extend test-cuda-fattn-paged-turbo4/test-kv-attention-execution or the
   existing graph fixture with same-shape content changes, page permutation,
   tail growth, sparse causal gaps, alternate verify widths and scratch-owner
   changes. Test graphs enabled, no forced unsafe capture, and compare to
   the uncaptured CUDA computation on exactly the same encoded pages.
   `cudaDeviceSynchronize during capture` is a real source-owner defect;
   graphs-disabled parity alone does not prove this named behavior.
