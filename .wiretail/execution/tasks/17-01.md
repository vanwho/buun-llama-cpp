# 17-01 — Repair benchmark lifecycle cleanup and runtime identity

## Objective

Make every benchmark attempt leave an unambiguous, usable server state. A
successful accepted run remains loaded by default, but a failed or
post-validation-rejected run must restore the prior profile (or record a known
stopped state) before the next attempt. Runtime evidence must identify the
actual binary, PID, profile, context, pager mode, and MTP placement rather than
trusting only the persisted profile name.

## Read

- Task README, cluster `17a-harness-contract`, and handoffs for 15-03,
  16-02, and 16-03.
- `/srv/ai/benchmarks/run-profile-benchmark.sh` and the pager benchmark
  adapter, but keep site-specific paths outside product code.
- The profile activation script and current systemd lifecycle behavior.

## Work

1. Trace both success and failure paths, including adapter validation failures
   that occur after the canonical runner itself returns success.
2. Ensure cleanup is idempotent and runs for startup failure, HTTP/telemetry
   contract failure, timeout, interruption, and explicit control/revert runs.
3. Preserve `keep-loaded-on-success` for dependent tasks. Do not restore merely
   because a successful benchmark completed.
4. Record candidate and active runtime identity in lifecycle JSON and fail
   closed when the observed process does not match the requested binary or
   configuration.
5. Add a preflight that detects an already-loaded incompatible candidate before
   measuring, without touching the unrelated 8092 service.

## Acceptance

Use mocked or shell-level lifecycle checks plus the existing server lifecycle
test target. Demonstrate: successful run remains loaded; failed run restores;
adapter-owned validation failure restores; repeated cleanup is safe; and the
next run sees the intended profile/binary. Never record credentials.

## Deliverable

Create `handoffs/17-01.md`, portable lifecycle/identity changes, and raw or
deterministic test evidence. Do not alter acceptance verdicts yet.
