# 05-03 — Integrate server slots and request lifecycle

## Objective

Make one-slot server use safe across prompt reuse, cancellation, teardown, and new request generations.

## Read

- Task README; plan section 8.9.
- `tools/server/server-context.*`, prompt cache lifecycle, VBR artifact catalog/adoption, cache leases,
  cancellation, and issues #109/#115 history.

## Implementation

- Initial authority is `-np 1`; reject unsupported multi-slot selective mode.
- Mint new session/sequence generation before a reused slot can accept page completions.
- Drain/cancel transfers at request abort and teardown without blocking under server locks.
- Allow immutable VBR prompt artifacts to seed host page backing only after full identity validation.
- Seal mutable pages before publishing as reusable artifacts.
- Include page/host/MTP/recurrent bytes in server accounting and debug output.
- Preserve ordinary prompt cache behavior in off/observe modes.

## Tests and acceptance

Cover cold start, same prompt, divergent prompt, cancellation at every transfer phase, slot reuse with a
late event, clear/reset, shutdown, invalid artifact, and host budget pressure. No stale page can publish
into a new request generation.
