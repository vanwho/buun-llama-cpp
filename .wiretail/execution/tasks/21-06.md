# 21-06 — Prove 256K allocation, population, and continuation

Recommended model: **Luna High**. Phase 21; cluster `21b-controls-soak`.
Depends on: `21-05`.

## Objective

Prove that the target can hold a full 262,144-token logical context while
using canonical CPU Turbo4 target KV, a budget-derived GPU hot set, and fully
GPU-resident Turbo4 MTP. This is a functionality checkpoint; speed is measured
later.

## Ordered work

1. Perform an allocation-only 262,144 startup smoke with actual resolved
   target and draft rows. Record memory ledger and leave output headroom.
2. Separately populate near-full context with tokenized accounting, recording
   occupied tokens, host-valid rows, physical pages, and MTP rows. Do not call
   allocation alone a full-context proof.
3. Ask known early, middle, late, and recent facts, then run one focus shift and
   a short continuation. For each answer correlate the selected logical page,
   host checksum, promotion event, route, and MTP placement.
4. If a point fails, reduce only the occupied workload while preserving the
   262,144 logical capacity, identify whether failure is allocation, population,
   movement, attention, or model output, and stop further large attempts.

## Acceptance and deliverables

Create `handoffs/21-06.md` and `evidence/PHASE21_FULL256K.json/.md`. The
receipt must distinguish allocation, population, retrieval, continuation, and
MTP results. It must state whether the base goal is demonstrated; no shorter
context substitutes for a missing result.

Use resumable checkpoints and keep the successful profile loaded. Run focused
tests, state validation, and `git diff --check`; do not start the speed curve
until this receipt is complete.
