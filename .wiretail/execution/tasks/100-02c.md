## Decisions and implementation

1. Build incremental candidate; verify/reload the single managed service.
   Profile ONE ~5.2K fresh p0 request crossing H4096, max128 output, then one
   cached <=256 fresh-token append. Both use L8192/B1024/U256/GPU Turbo4 MTP.
   This is attribution, not canonical speed. If admission still fails, repair
   its first refusal before profiling; do not consume a full campaign.
2. Attribute CPU dispatch, GPU model/GDN compute, KV append, dirty packed copies,
   FA, graph rebuild, Q-summary/selection, checkpoint/replay, D2H seal/H2D/waits.
   Use existing counters plus CUDA events/Nsight in an explicit profile only;
   do not add fences to production just to produce a statistic. Compare cold
   fresh vs cached rates using actual newly processed tokens. Preserve timings
   and exact routes, GPU utilization and bytes, not an unbounded trace in context.
3. Preserve measured dense-contiguous/packed/direct dispatch. For packed views,
   keep the immutable historical prefix in its reusable GPU owner. Stable
   page identity+generation+destination+row count+content version means NO
   repeat copy. An unchanged frozen history must not become dirty merely
   because table/descriptor epoch advanced for output. Reuse buffers and graph
   owner across decode/verify while shape/capacity remains compatible.

   **Fix the concrete view-policy inconsistency before attributing MTP quality:**
   prepare_kv_attention_graph currently defaults kv_attention_tokens to H/2,
   takes selected_attention_pages from the first full-attention layer, and
   clears the working selection when a routed page does not fit. During
   generating/query_replay the authoritative base is the committed frozen
   historical IDs/versions, not that provisional recent/advisory fallback.
   In the existing shared logical-page pool, build a deduplicated committed
   union across selected layers and expose it through llama_kv_cache_context;
   include required query/current output rows without silently dropping any
   committed historical page. Use explicit per-layer subsets only if the
   graph actually consumes and validates them; do not assume first-layer
   metadata represents all layers. No full-L enumeration is needed.
   An explicit A limit smaller than mandatory committed-view demand must be
   reconciled at query admission (trim optional selection there) or rejected,
   not silently changed during decode. Auto A derives from the admitted view
   and measured scratch, not a hardcoded half-H attention truncation. Include
   this packed capacity in the memory ledger; use existing slot allocations
   and descriptor refresh, not an unbounded second copy of L.
4. For a mutable tail, distinguish append rows from rewritten speculative
   rows. Copy the actual dirty suffix/current verify packet on GPU, not all
   selected H rows or the entire tail on every token. The existing invalid
   version sentinel currently invalidates a full slot; add a bounded dirty row
   interval with accepted/rollback content identity if the profile confirms
   this cost. On rollback, recopy invalid suffix; never falsely mark stale rows
   current. coalesce adjacent intervals; avoid one launch per row/layer/page.
5. Physical packing must preserve original token positions and causal masks.
   Stable slots/owner capacity must not alter the attention denominator or
   discard required query pages. Graph rebuild only on actual shape/allocation
   changes; descriptor refresh handles legal content/position changes. Keep
   ccc61f525's packed capacity mismatch guard.
6. Seal completed target pages once per immutable content version across all
   attention layers, on the existing bounded copy stream/staging owner. Pin
   until copy completion, publish exact host bytes and summary version, drain
   ready events at chunk boundaries. Skip unchanged sealed pages. Avoid full-L
   scans, per-layer global waits, CPU dequantization or synchronous summary
   readback. Do not add another worker when the existing queue suffices.
7. Query checkpoint contains bounded GDN/convolution/tail/MTP carry, not full-L
   target/draft payload. Historical changed-map replay runs ONLY final user
   span, not fixture prefix. Whole-user Q reduction stays on GPU. Preserve
   exact token accounting; a packed route label alone does not prove efficiency.
8. Implement measured unnecessary work at these owners and run focused cache/
   append/rollback/event regressions. Repeat only the two attribution rows.
   Receipt records before/after stage costs and remaining bottleneck; a valid
   still-slow result sends an exact source cause to100-03, not another full fill.
