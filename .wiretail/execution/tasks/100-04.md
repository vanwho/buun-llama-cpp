## Exact implementation and test sequence

1. Freeze the final candidate identity after 100-03: source SHA + dirty hash,
   CUDA build flags, executable/loaded DSO hashes, model SHA, endpoint PID and
   start time, effective argv, L/H/page/B/U, Turbo4 target/draft and native MTP.
   Reuse the loaded service only on exact identity; otherwise reload the one
   managed Qwen process. Never load a second Qwen process or touch port 8092.
2. Add or finish one deterministic CUDA fixture which starts from the same
   GDN/recurrent state, canonical host-backed historical bytes and MTP carry.
   Run path A: provisional final-user query, commit selected history, restore,
   replay the query once and generate no more than a few tokens. Run path B:
   install the exact same final history before processing the same query once.
   Compare target logits using the repository's existing Turbo4 tolerance;
   require exact equality of logical KV frontier, GDN state identity/content,
   MTP carry, accepted/drafted accounting, query side-effect count and committed
   historical page IDs/content versions. Assert replay count is 1 for changed
   history and 0 for unchanged history. Assert the selected CUDA attention
   route, not the diagnostic selected_reference path, consumes the final map.
3. Add one focused cancellation case at each meaningful boundary: before
   publication and after H2D completion but before query replay. Cancellation
   must not publish a partial target, lose the previous complete map, duplicate
   provisional tokens, leak a pinned slot/event or corrupt MTP/GDN state. A
   subsequent request on the same slot must proceed and match its clean control.
   Keep fixtures small (1–3 pages); do not add broad fault/churn matrices here.
4. Require natural promotion to be present in the same frozen candidate's
   evidence: a cold host-backed page is nominated from an actual user query,
   admitted, H2D-completed, published, and used by target attention after replay.
   First reuse 100-02's bounded recall records if they bind the exact identity
   and page/content version. If not, run one minimal changed/unchanged request
   pair at L=8192/H=4096 with native GPU Turbo4 MTP, B=1024/U=256 and normal
   answer budget. No forced page IDs, filename-only answer gate, retry loop,
   full 3-prompt suite or full-context input. Record answer quality separately.
5. Build only affected CUDA targets, run the named fixtures once, then the
   minimal live pair only if the existing identity-bound evidence cannot prove
   the natural chain. On a mismatch, preserve the failing case, identify the
   first state boundary, make the smallest code repair and rerun only its
   focused fixture plus one affected live pair. Do not restart from 95-03 or
   regenerate already valid speed rows.
