## Implementation / experiment sequence

1. On primary at fixed C,H,A and bundle, measure -b128/-ub64 as the starting point. Compare -b64/-ub64 to isolate B, then -b256/-ub64 and -b256/-ub128 to isolate U. Screen U256 only if prefill improves or profiling shows underfilled GPU kernels. Do not make a Cartesian product of all L/H/A/B/U.
2. For each viable candidate, record stage peaks at startup, maximum admitted prefill wave, MTP verify/rejection, cold promotion and settled decode. Include target/draft physical scratch, graph/activation/output buffers, pack duplication, recurrent state and transfer overlap. Read actual observed B/U, not metadata-only flags. Primary remains fixed H4096 so batch-speed comparisons are matched.
3. Repeat cheap allocation+small-turn probes at L32768 and L131072 at fixed modest H to classify capacity-dependent MTP/fixed buffers separately from C/A-dependent buffers. No long fill yet. Compare measured deltas to the analytic 16896*H target and ~1056*L draft payloads; explain residual allocations, rounding and shared ownership. Do not fit a confident linear B slope from one mixed historical pair.
4. Run a same-process grow/settle experiment with a bounded larger-U request, then restore U where supported (otherwise explicitly restart). Report retained scratch high-water: idle free space may not recover without releasing allocations. If useful, implement safe scratch reclaim at an idle boundary with event/graph invalidation. Do not shrink underneath captured or concurrent MTP consumers.
5. Derive safe auto H only after target/draft scratch reservations and measured safety headroom. Reserve page slots for append, verification and promotion overlap, rather than letting all H become pinned history. Solve budget in pages with checked geometry; distinguish H capacity from current occupied/attended rows.
6. Exercise each offered H using a short prefill/verify/promotion warmup that triggers actual worst admitted shapes. If late allocation fails, capture category, reduce H by a justified page delta, and retry at most a small documented bracket. Never silently reduce L or draft rows. Cap offered H to logical pages; at 128K the physical store must still leave real cold history when C>H.
7. Choose a conservative normal-use B/U profile that preserves useful H and adequate decode, plus an optional bulk-ingest profile ONLY if a measured prefill gain merits its smaller H. Report primary speed versus B/U and predicted/observed maximum-H capacity separately; larger H is not automatically larger A. Compare a bounded A change on primary if attention scanning cost makes H/A decoupling valuable.
8. Persist site launch profiles/overrides in /srv/ai and generic allocation/benchmark changes in the fork. Never hardcode 70K/77K, GPU model or per-server byte budgets in library defaults.
