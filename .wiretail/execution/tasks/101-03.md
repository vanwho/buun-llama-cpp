# 101-03 — Batched compressed Turbo4 attention without full-range F16 expansion

Revision: `hotpath-v10-20260914`. Amendment: `gpu-execution-101-20260930`.
Cluster: `gpu101-attention`. Implementation/assessments: gpt-6-luna High.
Dependency: 101-02. Read SPEED101, TESTING and handoff101-02 only.

## Chosen implementation

Extend the existing MMA Turbo4 loaders, not a new scalar page kernel. Queries
are tiled over grid.z; the model's U256 remains unchanged. Reuse the batched
direct-paged MMA implementation in fattn-paged-turbo4.cuh/fattn-mma-turbo.cuh
where possible. For contiguous packed K/V, add legal multi-tile dispatch to
fattn.cu::ggml_cuda_flash_attn_ext_mma_turbo_switch_ncols1; its Q<=4 assert and
extern/template-instance list currently make a mere guard lift invalid.

## Exact procedure

1. In fattn-mma-turbo.cuh, inspect the paged launch's query-tile calculation
   (~231–350), flash_attn_ext_f16 typed loaders, and the contiguous launch
   (~353–528). Map contiguous encoded storage to the same loader interface or
   use its existing tiled generic launch. Use initially ncols1*ncols2<=32
   (already instantiated 16/1,8/2,4/4,4/8); tile arbitrarily large Q instead
   of declaring a 256-query shared-memory tile. Check actual grid.z coverage
   and mask offsets. Larger tiles are a bounded tuning experiment only after
   this works. No explosion of every mixed-codec template instance.
2. Add only missing matched-Turbo4 D128/256 instances and extern declarations
   in template-instances and fattn-mma-turbo.cuh. Reuse GGML_CUDA_TURBO_FA CMake
   routing. Preserve CPU builds and builds with the option disabled. Avoid
   model/card-specific conditionals; hardware capability and head geometry
   choose the route. Chunk scratch/split-K state must fit admitted A/FA budget.
3. Compute query rotation once per query tile/input graph with the exact
   existing Turbo4 convention; dequantize K/V tiles in registers/shared
   memory. Do not allocate an attended-range F16 K/V mirror. Guard all padding
   with native positions and per-query causal masks; padded capacity rows
   must contribute zero mass. Handle tails Q31/33/255/256/257 correctly.
4. Extend the CUDA fixture with Q1/3/32/256 plus one nonmultiple tail,
   fixed encoded bytes/permuted pages/native gaps, including C>H masks.
   Compare selected direct, selected packed-fused and GPU materialized oracle
   *for identical rows*, not dense all-history. Assert finite logits/outputs,
   position correctness and scratch bounds. Existing direct probability-mass
   telemetry is off unless requested; no per-layer CPU reduction/readback.
5. Use one CUDA operation timing harness, warmup then a few GPU iterations,
   at attended rows1024/4096 and Q32/256. Include view prep/current append cost
   when selecting production policy. In planned_route and context capability
   checks, choose the measured faster validated native route by coarse shape,
   not a hardcoded universal packed preference or a timer on each token.
   Standard non-Turbo quants continue to use their mature GPU FA path.
6. Retake just the 101-01 selected 4K/80-output row after the material change.
   Report matched fresh prefill and scratch deltas and whether graph/matmul/GDN
   now dominates. Keep materialize-MMA as an explicit GPU correctness/control
   route for unsupported shapes, not a silent selected_reference fallback.
