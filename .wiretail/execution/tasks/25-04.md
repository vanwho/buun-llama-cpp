# 25-04 — Reuse fast Turbo4 Flash Attention with an amortized compressed hot view

Scope revision: speed-first-20260911. Recommended model: Luna High.
Phase 25; cluster `25b-prefill-kernels`; depends on `25-03`.

## Objective / alternatives

Recover Buun's optimized Turbo4 attention performance without requiring the
bespoke serial paged kernel for every request. Implement a no-copy eligible
all-fit route and measure an amortized compressed-Turbo4 hot view for selection.
This is the strongest low-complexity alternative to another custom kernel.

## Implementation recipe

1. Add an explicit eligibility predicate: correct codec/domain/stride,
   physically contiguous selected rows, valid tail and native causal ordering.
   Off/observe remain unchanged. When eligible, route the SAME stored Turbo4
   rows through existing fast FA; retain canonical-host publication, target
   hot-cap bound and MTP. No second full logical GPU KV allocation.
2. For noncontiguous selection, implement/reuse a bounded GPU copy of raw
   Turbo4 blocks into a compact view ordered by native position. Copy only A
   selected rows. Do not dequantize KV to a giant F16/F32 buffer, nor gather
   from host for every query. Count pack bytes and time separately.
3. Cache the compact view by (layer, selected IDs, content versions, format).
   On decode update only changed tail/new/promoted rows. Prefer compact
   physical-slot ownership/in-place safe reorder; if a duplicate view is
   simplest initially, debit it from H's byte ledger BEFORE allocation.
   Record whether repack cost amortizes under focus changes.
4. For historical selected pages all before a contiguous current query block,
   prove bottom-right causal alignment with the compact past + current block.
   If that predicate is false, use explicit native-position masking or the
   direct paged path. Preserve original RoPE coordinates and WHT domain;
   compact indices are storage indices only.
5. Feed the dense kernel required tensor extents/strides and graph transforms
   exactly once (Turbo V inverse/mean restoration especially). No duplicate
   Q/K transforms. Tail poison outside valid rows must never affect output.
6. Measure same Q/K/V/selected list against the direct oracle at query counts
   1, 3, 64, 256 with a small KV prefix, then one live 2–4K native-MTP request.
   Compare total attention + packing + maintenance and end-to-end pp/tg.
   Keep this route only for shapes/cadences it wins; record dispatch criteria.
