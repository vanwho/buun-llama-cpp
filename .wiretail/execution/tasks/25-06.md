# 25-06 — Restore useful whole-model prefill batching and bulk page admission

Scope revision: speed-first-20260911. Recommended model: Luna High.
Phase 25; cluster `25b-prefill-kernels`; depends on `25-05`.

## Objective / hypothesis

Restore GPU-efficient model batching now that an attention primitive can
process B>64. Increasing only -ub or a header constant does not achieve this.

src/llama-context.cpp prefill_ubatch_size, bounded_pager_prefill path in decode,

tools/server/server-context.cpp/.h prompt admission; common/speculative.cpp
process boundaries; existing server-prompt-cache and attention-execution tests.

## Implementation recipe

1. Separate requested B, physical-write capacity and CUDA tile Q in config and
   telemetry. Remove the Q=64 clamp from whole-model splitting only after
   25-05/25-04 can handle larger batches. Use min(requested B, safe writable
   rows, graph/scratch capacity), not min(..., CTA tile).
2. Reserve all write pages for the next B before submission. Keep old selected
   prefix, query-block current pages and transfer slack within H. Query rows
   written during the graph must be visible to causal attention without being
   exposed as committed host state prematurely. Bulk reserve/publish descriptors.
3. Fence at a safe multi-page wave or actual reuse dependency, not one global
   synchronize per tile/page by default. Keep GDN sequential state/order across
   waves and final logits aligned. Clear/reject paths must not publish
   speculative tail rows as committed.
4. Ensure MTP process receives every target batch exactly once in token order,
   including the shifted target-hidden pending row. Do not rerun a complete
   prefix per chunk. Explicitly count processed target and draft rows.
5. Exercise requested B=256 then512; 1024 only if measured scratch admission
   allows it. Keep n_batch large enough not to reclamp ubatch in the server.
   Match dense control B; record actual target and MTP sub-batches.
6. Use short native-MTP all-fit and deliberately bounded-H prefill (no cold
   recall claim yet). Capture matmul/GDN GPU utilization, launch count and
   pp/s. If H is too small for B, shrink B or diagnostic pins with a logged
   formula; never overwrite pinned/inflight slots.
