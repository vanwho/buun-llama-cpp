# 13-05 — Calibrate quality-speed policy and lock release-candidate defaults

## Objective

Use only the frozen calibration split to select capacity-relative routing, retention, telemetry and
prefetch defaults that maximize speed while maintaining the frozen quality floors.

## Read

- Task README, cluster `13b-system-opt`, plan 23–24.
- Handoffs 08-04, 11-01–11-05, 13-01–13-04; frozen corpus manifest and exact calibration evidence.

## Work

1. Define a bounded sweep over recent/history/transient ratios/minima, summary representation/top-K,
   exploration, attention EMA/peak/frequency/recency weights, hysteresis, sample cadence and prefetch depth.
2. Run replay first, then live trials only for Pareto candidates. Keep admitted `H` fixed per run from the
   live ledger; do not compare by secretly changing capacity.
3. Measure exact-answer/task score, routing/top-page recall, captured exact attention mass, perplexity/KL
   sample, MTP acceptance, warm decode, cold/focus/churn latency, faults, bytes, overlap and CPU overhead.
4. Perform component ablations for structural pins, recent, summaries, exploration, attention retention,
   hysteresis and prefetch. Reject a faster setting that violates any frozen calibration floor.
5. Select deterministic `auto` ratios/minima/functions, document rounding and small-capacity behavior, and
   hash the complete release config, corpus and binary. Do not inspect held-out answers/results.
6. Run an integrated checkpoint against same-context CPU K/V. If below 3x, test at least three bottleneck-
   driven repairs across tasks 13-02–13-04 before blocking.

## Acceptance

Defaults contain no fixed hot page/token count, meet calibration quality floors, maximize the recorded
Pareto objective, and achieve the 3x checkpoint or remain genuinely blocked with three preserved repairs.

## Deliverable

Create `handoffs/13-05.md`, calibration/Pareto JSON and markdown, ablation table, release config hash,
integrated speed result, and raw paths.
