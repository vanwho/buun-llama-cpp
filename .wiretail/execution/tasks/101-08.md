## Source defect to repair

llama-context.cpp::decode exports every h_nextn microbatch to host embd_nextn.
common/speculative.cpp::common_speculative_impl_draft_mtp::process (~2852)
still fills host verify_h/pending_h. set_embeddings_nextn_device (~3822)

## Chosen design and instructions

1. Provide a bounded, context-owned GPU h_nextn staging owner for one logical
   target batch plus one carry row (size <=n_batch*n_embd*sizeof(float),
   ledger charged). Each target microbatch writes into its batch offset via
   graph-ordered D2D, or lets the draft consume that completed microbatch
   before recycling it. Prefer the batch owner because the existing server
   calls process once per assembled batch. Preserve offsets independent of
   graph arena; store valid rows, seq/position interval and generation version.
   Lifetime includes the draft consuming stream's completion event.
2. Extend the device handoff API to bind this owned batch interval, not the
   last graph's transient output. Use backend same-device copy/event APIs;
   no host intermediate when supported. Unsupported multi-device layouts can
   keep the existing explicit fallback with a typed reason; the single-GPU
   production setup must not silently fall back. Keep CPU output APIs working
   via lazy materialization when actually requested by a CPU consumer.
3. In MTP process, preserve the shift exactly: token at p is conditioned on
   target hidden at p-1. First row consumes the prior committed carry, later
   rows consume preceding staged target h. Advance draft every processed
   prompt token/position, including all earlier microbatches. Latest carry
   is the last committed target row, not last drafted row or provisional row.
   Verify current begin/end, pending_h_lifecycle and rollback_guards before
   changing them; don't remove target-only recovery until correct restored
   device carry exists. Do not clear full draft history on an ordinary turn.
4. Keep only bounded actual verification rows for reject/rollback, not an
   unbounded host mirror of prompt h. A device verify owner with positions,
   tokens and predecessor carry must survive accept/reject; synchronize only
   for the normal accepted decision boundary or a real checkpoint read.
   Checkpoint query replay restores/invalidates the carry and staged versions
   consistently, then rebuilds them from the replayed final-user query.
5. Use existing common initialization: same loaded model/weights, target and
   MTP draft contexts separate KV, draft n_ctx equals resolved L on GPU with
   Turbo4 K/V. Don't set draft size to H or create a second model allocation.
   No follower storage/cache-size reduction in this phase.
6. Extend test-speculative-mtp-state and one CUDA owner test: B>U with four
   microbatches, shifted rows matching a host oracle, first row/carry, reject
   0/1/2, changed/unchanged replay, cancellation, graph-slot alternation and
   stale source generation refusal. One short prompt1 live request verifies
   full draft frontier and positive actual proposals. Don't require a MTP
   percentage from a four-token fixture.

Named proof: `mtp_device_prefill_handoff_and_carry_parity`.
Report actual hidden D2H/H2D bytes and fallback reason alongside finite logits.
The target's normal sampler still may copy small logits; no claim of zero
total PCIe is required, only no unnecessary prompt-hidden/history transfers.
