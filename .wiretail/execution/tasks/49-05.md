# 49-05 — Make first overflow and batch write admission progress safely

Revision: `hotpath-v10-20260914`. Cluster: `49c-residency-proof-v10`.
Model: Luna High; first retry High. Prerequisite:49-04.

## Source and smallest reproducer

Inspect `src/llama-kv-cache.cpp` call to `begin_write_batch` and message
`KV pager batch write reservation failed`,
`src/llama-kv-pager.cpp::{begin_write,begin_write_batch,seal_ready_pages}`,
`src/llama-kv-residency.*` transaction/pin code, and packed graph owner
completion in `src/llama-graph.cpp`/attention-execution. The graph may still
lease old pages and new tails may not be host-ready when a batch requests
more writable slots. `no_victim` must distinguish transient in-flight pressure
from genuine all-pinned capacity.

## Implement

1. Add a deterministic fill-to-H then one-page-crossing test. Dump only bounded
   slot status (logical id, pin reason, dirty/host-ready/event pending, owner
   graph epoch). Find the exact unreleased owner rather than increasing H or
   retrying long input. Verify graph owners are released after completion and
   D2H-completed pages become host-clean even if no next request arrives.
2. Preflight the current microbatch's distinct writable pages plus mandatory
   current/MTP-verification rows and in-flight promotion reserve. Chunk work
   at the next legal page frontier if all requested write pages cannot be
   admitted together. Preserve B logical scheduling; enforce U<=B and a
   bounded U allowed by writable slot/graph capacity. New chunks can reap
   completion and seal before reserving more. Do not replay processed prefix.
3. Reap completed events without device-wide sync. If all legal destinations
   wait on an actual submitted transfer, one wait for that specific event at
   the capacity boundary is allowed; no per-token unconditional wait. If no
   producer can release capacity, return precise all_pinned/invalid-budget
   error before launching another retry loop. Dirty pages cannot be discarded.
4. Account scratch and promotion reserve explicitly within resolved physical
   allocation. H reported as usable target history excludes explicitly
   budgeted staging/slack; total physical bytes include both. No hidden extra
   unbounded pages and no promise to fill every slot if A+mandatory rows
   leaves no legal progress reserve. Record resolved maximum selected pages.
5. Native-MTP rejection/cancel/checkpoint paths must release write tickets,
   cancel stale publications and preserve committed tail bytes. No host
   canonical writes for rejected speculative rows. Never shrink draft context
   or move draft KV off GPU as a recovery.

## Tests and mandatory small CUDA check

This is admission proof, not a full recall/throughput campaign.
