# 101-14 — Build each changed page's routing summaries once

Revision: `hotpath-v10-20260914`. Amendment: `prefill-owner-101-20261001`.
Cluster: `gpu101-summary-owners`. Dependency: 101-13. gpt-6-luna High.

Read PREFILL101, TESTING and handoff101-13. This fixes an algorithmic cache
locality mismatch; it is not another vector-copy-only patch.

## Exact code changes

1. In `src/llama-kv-pager.cpp::seal_ready_pages`, keep `groups(configs.size())`
   and per-configuration publication, but change **provider collection** to
   page-major: for each changed page needing a summary, request all its
   configurations consecutively, then advance to the next page. The existing
   one-page cache in `llama-kv-cache.h::pager_summary_cache` then serves every
   head from one all-layer decode. Do not add an unbounded page cache/map.
2. On any configuration failure, set that page's summary_ok=false and retain
   its maintenance entry. Remove/exclude **all** already collected inputs
   for that failed page from every pending_group before publication. Publish
   only complete page/config batches; never advance summary_content_version
   for partially published layers. Preserve generation/content-version and
   host-valid authentication. A fail/retry must not leave a missing head
   permanently skipped or admit incomplete summaries to selection.
3. In `pager_routing_summary_build`, retain move-once input ownership from
   101-12c. Make cache compatibility explicit for form, vector_dim,
   subblock_tokens and coordinate/representation identity as well as page ID
   and version. Head/layer is the item lookup, not a reason to rebuild all
   heads. Retry of a consumed item or a changed page/version rebuilds safely.
4. Add truthful **opt-in physical work** accounting: increment decoded bytes/
   rows and rebuild count where host bytes are actually read/dequantized,
   not for each returned head. Charge a rebuild once even if the first caller
   requests a nonzero head/layer; the current first-item source_bytes=cost
   convention can hide rebuilds returned through other items. Keep logical
   store accounting distinct from physical rebuild diagnostics.
5. Extend `tests/test-kv-pager.cpp` with two and three queued changed pages,
   at least two configs, then all model-derived configs. Use a faithful
   one-page caching provider that counts page rebuilds, and test the real
   provider's encoded read/decode seam with legal Turbo4 geometry where
   available. P pages must cause P all-layer rebuilds, not P*N. Verify ranges/
   means equal the old scalar oracle, nonzero-head-first order, repeated
   consumed request, changed version, different summary geometry, a middle
   config failure, successful retry, and zero work on unchanged seal.
   Hardcoded64 belongs only in the old fixture, never new production logic.
