# 01-02 — Implement pure page identity and residency table

## Objective

Implement CPU-only internal primitives for 256-token logical pages and bounded physical slots.

## Read

- Task README and `.wiretail/execution/design/SEMANTICS.md`.
- Plan sections 8.2–8.3 and 9.1.
- `src/llama-vbr-generation-types.h`, `src/llama-vbr-generation.*`,
  `src/llama-vbr-occupied-replacement.*`, and the salvage-matrix destination rows.

## Implementation

- Reuse `VBR_GENERATION_PAGE_CELLS` as the one 256-cell geometry constant.
- Add internal `llama_kv_*` page ID/record/table/snapshot types in KV residency ownership. Do not name
  them as VBR representation tiers or put page-policy authority in `ggml_vbr_vmm_pool`.
- Maintain a checked forward logical→physical map and reverse physical→logical map.
- Track session/sequence/page mutation/representation/table epochs, state, dirty/host flags, pins, and
  native-position range/digest.
- Provide pure plan/publish/rollback operations; a table is immutable to graph consumers.
- Reject duplicate logical pages, duplicate physical slots, bad tails, out-of-range positions, ABA,
  stale epochs, and replacing pinned slots.

slots, gaps, table snapshot lifetime, all-pinned failure, and stale publication.
