# 101-07 — Event-driven host sealing and bounded hot-loop metadata work

Revision: `hotpath-v10-20260914`. Amendment: `gpu-execution-101-20260930`.
Cluster: `gpu101-storage`. Implementation/assessments: gpt-6-luna High.
Dependency: 101-06. Read SPEED101, TESTING and handoff101-06 only.

## Preserve the authority, remove avoidable barriers

CPU RAM is inclusive encoded page storage. GPU computes/quantizes; completed
committed pages copy out once. Do not reintroduce traditional GPU-to-host
eviction copying or reselection per output token. The measured ~3% sealing
duration is not evidence that every current fence is necessary or cheap.

## Exact directions

1. Trace llama-context.cpp::decode page_wave_boundary (~7610), synchronize
   (~2399), and llama-kv-cache.cpp::seal_kv_pager_pages (~2915), submitted
   write tracking and host capture hooks. Mark which fence protects graph
   storage, host logits/hidden reads, current writes, summary readiness or
   victim reuse. Do not remove a global fence used by another owner blindly.
2. At completed-page write submission, retain a lease keyed by sequence/session,
   logical page, content version, source slot/allocation generation and valid
   row count. Record compute-ready on its real compute stream. D2H copy stream
   waits that event, transfers encoded K/V into a bounded pinned ring, then
   records copy-done. Poll copy-done without blocking; copy ring bytes to
   canonical pageable backing and mark host_version only after successful
   completion. No CUDA API calls from signal handlers or CPU inference kernel.
3. Queues are bounded by admitted in-flight pages/staging bytes. A clean
   host-backed victim drops its GPU map without D2H. A dirty/in-flight victim
   stays pinned until its exact copy completes; wait only the necessary event
   when allocator pressure actually requires that victim. Submit next chunk
   compute while prior copy runs when graph/source leases permit it. Retain
   original synchronous API semantics for user llama_synchronize/checkpoint
   readers. On backends without events, keep explicit safe fallback behavior.
4. Sealing/policy loop currently obtains residency snapshots and scans pages
   to find current state even when no routing work is needed. Cache current
   page/slot in mutation ownership, use dirty/complete queues and epoch-bound
   lookup maps. Idle generation bookkeeping must scale with changed pages,
   not L. Query catalogue updates upload changed summaries, not every historic
   page each token. Never drop a ready mailbox solely because policy_dirty
   was false; preserve authenticated nomination -> admission -> publication.
5. Routing and H2D promotion remain at final-user query boundary. Freeze
   historical membership through output and MTP verification. Only output
   ring changes and committed-page D2H can occur during generation. Assert
   no historical H2D/selector graph on decode, with metrics read once at end.
6. Focused fixtures: seal-once, delayed event, stale rollback version,
   cancellation before/after copy, ring exhaustion backpressure, clean drop,
   source slot not reused early, successful later query promotion. Use existing
   pager/host-store/residency tests and a small CUDA stream test; no 24-case
   live campaign. One 1K ingest+short-generation row verifies overlapping
   compute/copy only if the earlier trace identified avoidable waits.

Named proof: `bounded_async_seal_and_no_decode_history_pcie`.
Report queue maximum/bytes, actual waits and lossless encoded backing, not
lifetime transfer counters alone. No-change on already-safe async owners is
allowed only with operation-level evidence; do not rewrite them for statistics.
