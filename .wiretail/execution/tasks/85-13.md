# 85-13 — Publish persistent GPU summaries and eliminate repeated host maintenance

Revision: `hotpath-v10-20260914`. Amendment: `repair85-20260921`.
Cluster: `repair85-maintenance-speed-v10`. Prerequisite:85-12.
Model: Luna High; first retry High.

## Outcome

Canonical storage still captures new Turbo4 page versions once. Routing
summaries and catalogue maintenance no longer decode GPU KV on CPU or walk/
copy the complete catalogue in the token critical path. Reuse the already
implemented GPU summary operator rather than add another subsystem.

## Exact source/change directions

1. `llama_kv_cache::pager_routing_summary_build` (~3699) currently obtains
   `host->pages()`, finds a page, reads all-head encoded rows and dequantizes
   all heads for EACH configured head. `routing_summary_configs` and
   `llama_kv_pager::seal_ready_pages` (~1830–2050 pager.cpp) repeat per-layer/
   head summaries and copy stores. Remove this work from CUDA production
   commit/synchronize. Keep CPU helper as offline reference only. No fallback
   synchronous `ggml_backend_tensor_get` for absent host data during a token.
2. Reuse `llama_kv_cache_context::build_kv_page_select` (~16600 cache.cpp),
   `ggml_kv_page_summary`, `ggml/src/ggml-cuda/kv-page-summary.cu` and
   `tests/test-cuda-kv-page-summary.cpp`. Existing GPU op already computes
   Turbo4 min/max, but its graph-sized output copies cold/unchanged catalogue
   and recomputes marked resident pages. Make a persistent per-layer/head
   logical catalogue with stable capacity and explicit content-version tags.
   Update only completed/changed page IDs via a compact dirty-ID queue; no
   kernel grid over every historical row on every refresh.
3. Produce a sealed page's K bounds on compute stream after its last K write
   and before slot recycling. Persist those GPU bounds independently of the
   physical slot; cold eviction must not delete them. Publish valid tag after
   bounds complete. If existing host validation/diagnostic catalogue needs
   them, copy only compact per-page summaries once asynchronously, not KV
   back to CPU for recomputation. Owner-thread generation checking from85-11
   applies to summary and canonical bytes independently; neither must falsely
   validate the other before its completion.
4. Reuse indexed storage rather than `host->pages()` and `auto current = *store`
   full copies. Add/update by stable logical ID/content version, with immutable
   snapshot lifetime only when a consumer actually submits. Metadata may grow
   by capacity reservation but page events update dirty ranges. A cold page
   promoted without content change needs a membership update, NOT a new K
   decode or D2H capture. Cache layer geometry outside per-token callbacks.
5. Keep Q routing domain consistent with `ggml_turbo_wht(...,2)` and active
   scales. In summary CUDA bounds use real outward half rounding (e.g.
   `__float2half_rd` for lower /`__float2half_ru` for upper where supported),
   not float-nextafter followed by nearest half, which is not guaranteed
   conservative. Invalid active K must yield invalid metadata/diagnostic,
   not fabricated zero bounds that look eligible. Add tiny rounding/poison
   fixtures, not a quality corpus.
6. In `seal_kv_pager_pages`/`apply_pager_live_policy` and
   `can_reuse_kv_page_select`, put O(1) pending/generation/cadence tests BEFORE
   residency inventory snapshots. Maintain queued flags/counters instead of
   scanning all pages to ask whether work exists. Prompt ingest refreshes at
   meaningful completed-page/U boundaries; don't emulate8 individual decode
   refreshes within each prefill batch. Decode cadence counts accepted target
   tokens and completion-ready mailbox wakes independently of new scoring.
   Skip means no catalogue upload, summary traversal, selector kernel or
   full-Q host copy; draining an already queued event remains permitted.
7. One `(page,content generation)` canonical capture, bounded ring chunks.
   23 new pages legitimately cost99,483,648 bytes on the recorded geometry.
   Optimize hash/catalogue publication and small-copy overhead on the worker,
   reuse immutable buffers, and coalesce adjacent compatible ranges where
   safe. Don't remove data-integrity checks globally or fake zero D2H. Clean
   eviction and promotion of an unchanged host-backed page need no D2H.

## Minimum tests

Extend existing GPU summary, routing-summary/retrieval and pager maintenance
fixtures with new seal, same generation, changed generation, eviction,
promotion, rollback, cold validity and skip cadence. CUDA results match CPU
reference from encoded K; conservative min/max bounds contain every valid
coefficient. After warmup a no-change decode step has zero summary rebuilds,
full catalogue uploads and CPU KV-dequant work. Per new version capture byte
sum equals actual encoded payload once (chunks may differ). A delayed
completion cannot overwrite a newer summary. Confirm cold selector still
works; don't optimize it away to hit zero-work counters.

One short cached65-token append at already safe L4096/C~3072 only if needed
for live timing attribution. No corpus/scaling. Required proofs:
`gpu_summary_version_cadence`, `canonical_capture_once_per_version`.
Write `evidence/V10_85-13.json` and handoff with actual dirty update/copy
sizes and which host work is no longer in the critical path.
