# 84-03 — Attribute speed overhead and freeze the efficient benchmark recipe

Revision: `hotpath-v10-20260914`. Cluster: `84c-speed-v10`.
Model: Luna High; first retry High. Prerequisite:84-02.

Do not run a long context curve or a broad q0/q1/q2 matrix. Use q0 only at
the stable C≈6143 coordinate, one warmup and three measured trials, with a
64-token cached append and 64 committed decode tokens. Compare, using identical
prompt/template/seed/output settings: all-GPU feature-off, all-GPU native MTP,
CPU-main-KV with GPU native MTP, selected feature-off, and selected native
MTP. Use B=U=128 as the primary coordinate; repeat U=64 only as a causal
secondary row when the primary row is valid. Keep every row's binary/model and
full command identity immutable.

Record server rates plus metrics deltas from the existing pager/attention
metrics snapshots; use `src/llama-kv-attention-execution.cpp` counters and
the existing Turbo4 CUDA dispatch timing rather than adding a per-token host
callback. Capture queue, wait, graph construction,
graph rebuild/replay, summary/catalogue build/read/upload, selector score/rank,
descriptor preparation, Turbo4 kernel time, H2D/D2H, staging, faults,
evictions, and scratch high-water bytes. Capture GPU timing only through the
existing bounded diagnostics. Separate cold prefill, cached append, and decode;
do not divide a total wall time by tokens when the server timing field is
available.

Produce an overhead table that attributes the selected-vs-all-GPU gap to
reference/packed route work, host transfer, graph churn, selector/catalogue
work, MTP rejection, or scratch/shape limits. State which single change is
expected to improve speed and which measurements would falsify it. A setup or
MTP failure produces null speed ratios, not a claimed result.

Required proof: `phase84_speed_attribution`.
