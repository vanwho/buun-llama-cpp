## Objective / coverage obligation

Inspect the whole model after pager fixes so the next “optimization” is not
aimed at a tiny fraction of elapsed time. Resolve material remaining compute,
CPU and transfer bottlenecks rather than assuming all loss is attention.

## Read / source owners

ggml CUDA graph/op dispatch, MMQ/cuBLAS paths, Qwen GDN/fused-op graph,

No generic-code machine paths or fixed RTX architecture.

## Work, in priority order

1. Compare matched dense GPU and current pressure-pager traces at useful B.
   Rank target quantized matmul, GDN/recurrent kernels, attention, Turbo
   transforms, MTP, host metadata/copies, sampling and launch idle gaps.
   Use measured wall critical path, not the sum of overlapping kernels.
2. Confirm all intended weights/full-attention/GDN/MTP compute on GPU; detect
   unsupported-node CPU fallbacks or implicit F32/gather copies. Fix one
   fallback with existing backend support or supported configuration first.
3. Check GDN/linear-attention fused operations and large-B implementation,
   quantized weight MMQ versus cuBLAS dispatch, CUDA architecture build,
   effective n_batch/n_ubatch and batch/decoding CPU threads. Test at most
   two promising switch/config alternatives, then use code only if a clear
   profiler-owned defect remains. Do not rewrite all model kernels.
4. Locate duplicate Q/K WHT, V inverse/mean or quantize/dequantize passes,
   repeated scratch allocation/zeroing, whole-vocabulary logits on unused
   rows, CPU sampler synchronization and unnecessary per-token metrics/logs.
   Fuse/remove only demonstrably redundant work with small regression checks.
   Make optional diagnostics off by default on the timed profile.
5. Disable optional checkpoint snapshots, prompt-save/idle-slot caches,
   speculative debug logging and recurrent-state copies not needed for one
   live sequence. Keep essential native-MTP reject state. These are explicit
   speed-profile settings, not permanent removal of user features.
6. Read PCIe negotiated link speed/width, measured pinned-copy bandwidth,
   GPU utilization/clocks/thermal throttle, competing GPU processes and CPU
   NUMA locality. If material, test bounded site-local affinity/first-touch/
   thread placement; don't modify unrelated8092 or overclock hardware.
   Record OS/driver limits honestly; settings stay in /srv/ai only.
7. Consider VMM only if real allocation/address churn or pack duplication
   remains costly after 25-10. Stable slabs need no VMM rewrite. Calculate
   CUDA mapping granularity waste and record a go/no-go with evidence.
8. Publish every material coverage item as improved, measured_nonmaterial,
   configuration_selected, or remaining_gap with owner. For a newly found
   blocking source defect, insert a small repair before 25-14; do not bury it
   in a vague recommendation or launch final curves with a known fallback.
