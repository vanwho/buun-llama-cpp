# 13-04 — Optimize prefill, graph reuse, scratch, and allocation churn

## Objective

Improve prompt throughput/TTFT and remove graph/allocator overhead that prevents decode from realizing the
kernel/transfer gains, while keeping GPU memory bounded by physical rows or exact wave size.

## Read

- Task README, cluster `13b-system-opt`.
- Handoffs 10-03–10-05, 12-03, 13-01–13-03; prefill/graph profiles and memory ledgers.

## Work

1. Profile short, medium, long-over-`H`, odd-tail and checkpoint-restored prefills plus first decode.
2. Sweep runtime-derived chunk/ubatch settings, selected prefill dispatch, descriptor/table reuse, graph
   key granularity, graph capture/replay, allocation pools, seal scheduling and scratch reuse.
3. Eliminate per-token/per-layer host allocations and unnecessary graph invalidations. Preserve table/page
   pins and generation changes that genuinely affect execution.
4. Reconcile projected versus peak graph/dequant/scratch bytes and feed measured requirements back into
   admission; do not conceal a larger peak by lowering `H` silently.
5. Benchmark at least five trials before/after for pp, TTFT, first-token latency, steady decode and memory.
   Re-run dense/selected/exact parity, prompt cache/checkpoint, cancellation and feature-off tests.

## Acceptance

Meet 13-01 prefill/graph budgets or test three profile-driven hypotheses; preserve bounded allocation and
correctness; no unexplained full-context GPU allocation; measured scratch feeds deterministic admission.

## Deliverable

Create `handoffs/13-04.md` with profiles, sweeps, retained changes, admission updates, parity/lifecycle
tests, pp/TTFT/decode deltas, and raw paths.
