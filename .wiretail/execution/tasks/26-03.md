## Implementation sequence

2. Add a minimal reproducer crossing hot capacity and multiple page boundaries with partial final page, then append another turn and generate. Test lengths immediately below/at/above P multiples and L minus output reserve. Reproduce the old long 'context exhausted' condition at small L if it is a counter/frontier bug; if not reproduced, instrument the exact server error branch instead of guessing it is OOM.
3. Trace rendered prompt size, slot n_past/next position, target committed position, draft processed/committed/pending position, retained page range and available append pages. Fix incorrect use of physical H, repeated processing counts, unreleased pins or duplicated speculative pending rows. Do not bypass real L checks, enable context shift, discard old logical pages, or reduce MTP capacity.
   Crucially, server-context.cpp currently maps n_batch==1 && ret==1 to 'Context size has been exceeded', while llama_context::decode returns1 after LLAMA_MEMORY_STATUS_FAILED_PREPARE / failure to find a memory slot. prepare_with_slots can return empty on scratch reserve failure too. This is NOT proof of C reaching L. Carry a structured last-failure reason through the memory/cache boundary without breaking public return-code compatibility. Distinguish logical_capacity, scratch_oom, all_pinned, pending_copy and invalid_frontier in server diagnostics. Retry smaller batches only for a plausibly batch-dependent failure; poll a bounded pending event only when that event can free a slot. Add a regression that a low-C scratch/pin failure never claims logical context exhaustion, and a genuine C+input+reserve>L still does.
4. Reserve ceil(physical write wave/P), tail, verify/rollback and transfer slack before submit. Mandatory sink/recent pins plus append must fit H. H=1/all_pinned was an invalid pressure configuration, not a useful runtime tuning endpoint. Provide clear minimum-required pages when refusing.
5. Finish canonical host publication asynchronously and only mark host-clean after its event. Evict clean pages by dropping mappings; never lose a dirty/inflight source, reuse pinned staging early, or schedule duplicate copies for the same content version. Cheap unchanged-page checks should not rebuild summaries.
6. Use one deterministic cold-page diagnostic at primary L8192/H4096 with native GPU Turbo4 MTP enabled, C around6144, and >=128 committed outputs. Prove at least one actual eviction/promotion and byte identity for the diagnostic. It is a transport/lifetime proof, not yet natural attention selection.
7. Repeat with 512–1024-token incremental turns reusing the live prefix, and a small near-L-minus-reserve case that transitions to output. Complete any26-02 pressure scratch stage previously prevented by this task's frontier/pin defect; record actual requested/physical target and draft scratch across prefill/decode/verify/promotion. Leave the successful primary candidate loaded. Long 200K prefill is not an allowed way to reproduce this task.

Inspect the existing slot/frontier/checkpoint/carry path for a matching conversation continuation. Preserve the correct recurrent and draft state at the reusable boundary; use an existing bounded last-turn checkpoint if needed rather than disabling all cache facilities for a misleading benchmark. Record any replayed tail and checkpoint transfer/VRAM cost. Do not reconstruct the full history each normal turn, claim processed=append when it was replayed, or reuse a recurrent state from a later token position. This narrow interactive continuation proof is required; broad restart/soak remains out of scope.
