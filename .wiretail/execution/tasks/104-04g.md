## Cache call-chain changes

1. `src/llama-kv-cache.cpp::complete_router_query_job(seq,turn)` currently
   checks ready without ever creating it. Replace that control flow:
   validate provisional turn -> prepare_router_query_layers ->
   job.execute_query -> obtain actual completed exact batch. Cache stores
   typed outcome and terminal batch, not just a boolean. Repeated same turn
   reuses the terminal result; aborted/stale query never returns ready.
   Do not let a prior turn's nonempty exact_candidates satisfy this turn.
2. Wire this inside `commit_kv_pager_query` after final target fence and before
   policy. Source final fence is caller/context owned; inspect its existing
   boundary rather than adding cudaDeviceSynchronize. If asynchronous coarse
   mailbox isn't decoded yet, retire this query's capture/rank event and decode
   it before preparing layers. Never wait for a job that nobody submitted.
   Synchronous and async decoders share retention into the same job plans.
3. Invoke policy only with terminal exact-mass batch, including resident-only
   and zero-history completion. Missing/stale/error returns an actionable
   error with stage/layer/identity and preserves incumbent mapping. A source
   error is not unchanged-selection success. No infinite pending poll on
   failed work. Policy/commit callbacks must not recursively start execute_query
   during its own drain or ordinary synchronize/breathe operations.
4. Query replay/generation/MTP verification never prepare/submit a new job.
   Guard by pager turn phase and identity, not only query token count. End/reset/
   abort cancels unfinished query, clears cache exact batch, preserves valid
   published pages. Completed batch remains usable until04-05's publication
   gate consumes it; then frozen history is the generation authority.

## Correct policy competition, not forced cold quotas

5. Inspect `apply_pager_live_policy` region that builds resident_by_layer,
   cold_bundles, resident_attention_limit and attention_by_layer. Current code
   reserves cold slots before comparing resident and cold strengths. For
   probe_rerank ONLY, build one authenticated bounded historical bundle table
   from all exact records. Structural query/current/tail/pinned pages are
   separately protected and consume real capacity, never evicted as history.
   Keep legacy branch unchanged. Do not feed coarse probe_softmax to policy.
6. Aggregate across participating layers: bundle peak=max layer peak, mean
   =sum layer mean / number of participating layers (missing/not-nominated
   layer contributes zero), support=count eligible positive layer support.
   Do not divide by support alone and thereby reward a page present in one
   layer above consistently useful pages. Sort via existing
   llama_kv_prefetch_ranked_bundle_better: descending peak, mean, support,
   then ascending logical ID; retain immutable identity/content versions.
