# 85-11 — Make canonical publication and graph lifetimes safe and asynchronous

Revision: `hotpath-v10-20260914`. Amendment: `repair85-20260921`.
Cluster: `repair85-lifetime-mtp-v10`. Prerequisite:85-10.
Model: Luna High; first retry High.

## Outcome

Reuse the capture ring/worker with immutable metadata and valid stream
dependencies. No CPU synchronization against an event still in CUDA capture,
no worker/graph wait cycle, no publication of stale bytes. Only completed
canonical capture makes a page clean/evictable; protect sources until then.

## Code-directed changes

1. Fix `llama_kv_cache::seal_kv_pager_pages` (~2580): evaluate
   `changed = pager_->seal_ready_pages(publish_catalogue)` before combining
   `pager_policy_dirty_ || changed != 0`. The current short-circuit skips
   sealing when dirty is already true. Audit nearby `dirty || work()` patterns.
   Add dirty-already-true + newly complete page regression: one version must
   still be captured and become host-ready. Dirty is not a reason to stop work.
2. Read `llama_kv_pager_host::{enqueue,prepare,worker_main,execute,drain,wait}`
   (~475–675 src/llama-kv-pager.cpp), `pager_host_prepare` and
   `pager_host_snapshot_{acquire,recheck,release}` (~3604/3851 cache.cpp), and
   `vbr_pinned_chunk_ring::stream_ranges_impl` (~1900
   src/llama-vbr-artifact-capture.cpp). Worker prepare currently reaches mutable
   cache metadata. On the cache owner prepare an immutable descriptor: stable
   logical page/content generation, layer offsets/lengths, source buffer owner,
   source pin, stream and write-completion dependency. Queue that small
   descriptor, not an instruction to traverse mutable cache vectors later.
3. Reuse existing dedicated transfer backend if already allocated; verify it
   differs from target compute and has a single owning worker. Otherwise create
   one per device before use, not per page. Trace `host_backend`, ring lanes
   and CUDA `event_record/event_wait/event_synchronize`. Queue locking alone
   does not make sharing a backend/allocator with the target safe.
4. Compute→D2H: reuse an already completed scheduler boundary; if asynchronous,
   record write-ready after graph launch, OUTSIDE capture, and stream-wait on
   transfer stream. Copy-done is recorded on transfer stream. Poll/query ready
   events on owner thread at an existing boundary. H2D→publication follows
   the same discipline. No cudaDeviceSynchronize or per-token blocking fence
   added for statistics, and no wait on a captured-but-unlaunched event.
5. Worker snapshot callbacks must not read mutable owner state unsafely. Check
   immutable descriptor locally; owner-thread completion drain checks current
   content generation before marking host-valid. Cancellation/stale completion
   must not revalidate a reused slot. Release source/reader pins exactly once
   on success/failure/cancel. Retain tensor/buffer owners through copies.
6. `llama_context::synchronize`, `prepare_kv_attention`, execution-owner graph
   completion and `llama_kv_pager::apply_live_policy`: separate completed reader
   pins from pending host-copy pins. Release graph reader refs independently
   of summary publication. Protect mutable/speculative tails. Admit bounded
   staging/reserve slots before H so promotion/sealing cannot require eviction
   of their own pinned source to make progress.
7. Bound queued descriptors/staging. Backpressure only at full ring or lack of
   required clean slot, not every token/page. Drain completed queue before
   waiting; never hold owner/queue mutex while waiting for worker/CUDA. Avoid
   a graph fence waiting for a worker that needs that same graph fence.

## Minimal proof

Extend `tests/test-cuda-kv-promotion.cpp`, existing pager/residency tests and
`test-kv-attention-execution` with tiny2–3-slot CUDA Turbo4 flow:
write→D2H→host-ready→evict→H2D→publish→completed attention. Capture/replay,
dirty-already-set, stale generation, cancellation and slot reuse. Delay
completion in fixture only; prove pins, canonical bytes, output and bounded
queue, not just counters. No27B corpus. One small C>H model request only if
needed to reproduce the previous completion hang. Retain failing fixture first.

Required proofs: `cuda_capture_publication_lifetime`,
`dirty_seal_and_stale_completion_regression`. Write `evidence/V10_85-11.json`
and compact handoff with ownership/event sequence. Historical seal/chunk counts
are not proof of duplicates: count `(page, content generation)` and actual bytes.
