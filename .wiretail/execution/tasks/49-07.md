# 49-07 — Make native-MTP acceptance a hard benchmark precondition

Revision: `hotpath-v10-20260914`. Cluster: `49d-mtp-evidence-v10`.
Model: Luna High; first retry High. Prerequisite:49-06.

## Why this task exists

Phase36's server logs prove that native MTP was initialized with Turbo4 GPU
KV, but later controls recorded `0/126` accepted drafts and phase47 sometimes
started with `--spec-type none`. The canonical three-prompt runner can report
`mtp` zeros when its journal scrape misses a line, which is indistinguishable
from genuine zero acceptance. Placement/reservation evidence alone is not a
measured acceptance percentage. Fix the evidence boundary before speed claims.

## Exact implementation

1. In the portable adapter/contract, add strict native-row validation. For
   every successful measured record when MTP is requested, require explicit
   `mtp.draft_tokens` (or canonical normalized equivalent) as an integer >0,
   explicit accepted integer >=0, accepted<=draft, and a finite acceptance
   percentage equal to100*accepted/draft within a documented rounding
   tolerance. `accepted=0` with draft>0 is valid evidence for genuine0%.
   Missing/null/0 denominator is `mtp_observation_missing`, not a populated
   zero. Feature-off records must explicitly say MTP off and skip this gate.
2. Validate effective runtime identity for native mode: command includes
   `--spec-type draft-mtp`, positive `--spec-draft-n-max`,
   `--spec-draft-type-k turbo4`, `--spec-draft-type-v turbo4`,
   `--spec-draft-kv-device gpu`; startup log/telemetry includes GPU draft
   backend, Turbo4 K/V and reserved rows/bytes. Reject `--spec-type none`,
   launcher-only estimates, or a profile name without these observations.
3. Repair the canonical shell runner's per-request extraction. Under its
   lifecycle lock, capture authenticated Prometheus counters immediately
   before sending each request and after the response:
   `llamacpp:spec_decode_num_draft_tokens_total` and
   `llamacpp:spec_decode_num_accepted_tokens_total`. Store the raw snapshots
   and calculate the delta; use journal `draft acceptance = ... (accepted /
   generated)` as corroborating raw text, not as the only source. No unrelated
   request may run under the lock. Counter deltas must never go negative; a
   counter reset is an observation failure requiring a fresh baseline.
4. Include `mtp_source`, before/after counter values, deltas, journal excerpt
   hash, request start/end and request/case key in each record. Remove any
   default assignment that turns an absent journal/counter into 0/0. Retain
   valid zero accepted values. If server metrics are unavailable, fail the
   native row with a named authentication/observation error rather than
   silently continue.
5. Keep startup placement checking separate from request acceptance. A native
   campaign can fail setup before requests if draft context is absent, but a
   successful native campaign cannot finish without positive denominators for
   each requested measured prompt. Do not require acceptance >0; model behavior
   can genuinely reject every proposal and must then be diagnosed honestly.
