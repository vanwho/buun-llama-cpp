## Ordered implementation / experiment

1. Trace the real projected/positioned query tensor at each supported full-attention layer and the actual Turbo4 key coordinate system. Do not reuse layer-0/head-0 statistics as though they described every layer.

2. Maintain bounded GPU summaries for every canonical host page, including cold pages, with versioned model/codec/position/generation identity. Update only committed changed pages.

3. Implement GPU candidate scoring from actual query tensors; compare representative keys and min/max-key summaries on held-out dense attention traces. Project/rotate the query consistently with summaries.

4. Feed selected cold candidates into the production transaction boundary, with mandatory sinks/current tails/caller pins and an explicit layer-group union. A manual page list is only a diagnostic, not completion.

5. Separate selection budget from residency budget: pages may remain resident but be skipped by a layer, and selected pages must become ready before that layer uses them. Budget summary/table bytes.

6. Test a cold fact that becomes relevant after a focus change even though it received no recent resident attention; validate query dependence by changing only the question.

## Concrete execution recipe

Read `EXECUTION_COOKBOOK.md` sections C1/C3/C4/C5 and `IMPLEMENTATION_CONTRACTS.md` sections I4/I5/I6. These are shared context; reuse them within the cluster.

Implement the complete-inventory validation first: a host-only page with
physical_slot=UINT32_MAX must be a legal authenticated candidate, not missing
because it is absent from the resident snapshot. Retain summaries on clean
eviction; invalidate on changed content/codec/position identity instead.

Checkpoint A: one attention layer/group, actual projected/transformed Q, GPU
summary scoring and small candidate result. Checkpoint B: use the fresh graph
boundary from I5 to promote the selected cold page before that layer's attention.
Checkpoint C: all runtime attention ordinals/groups with bounded per-layer
tables and explicit union/slot scheduling. Reuse 19-06's proven graph split/
lifetime mechanism rather than recursively forwarding the model in a callback.

Start with existing representative summaries and compare CPU score reference.
Min/max scoring is a subsequent measured refinement, not a prerequisite to
wire a real query. Test first-answer cold recall after changing only the
question. Export query freshness, summary identity/layout, producer/consumer
symbols and evidence from score to upload to attention to answer.
