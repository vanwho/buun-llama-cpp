# 26-02 — Measure affordable matched CPU-KV and GPU controls

Scope revision: speed-first-20260911. Recommended model: Luna High.
Phase 26; cluster `26a-fullcontext-controls`; depends on `26-01`.

## Objective

Measure the gain over ordinary CPU-KV offload without spending hours on a
full CPU matrix. Same Qwen weights stay GPU and native Turbo4 MTP stays GPU.

## Work

1. Read 26-01 result and 25-15 short baseline. Choose one short all-fit occupancy
   and one pressure occupancy (4–8K typically) already proven by the candidate.
   Pin exact original question(s), input IDs, logical L, generation budget,
   sampling and effective B.
2. Compare feature-off GPU target KV and ordinary CPU target KV
   (--no-kv-offload or its currently supported equivalent) with independent
   --spec-draft-kv-device gpu and Turbo4 draft types. Verify actual weight/
   target attention placement; record whether ordinary CPU KV also sends KQ/V
   compute to CPU. That's a real baseline characteristic, not the pager.
   If ordinary Turbo4 CPU attention is unsupported, record that fact, retain
   the attempted raw result and use only an explicitly labeled supported
   alternative; never label a different codec an all-Turbo4 paired result.
3. Measure the same candidate pager under forced pressure, same H/A/config as
   comparable short evidence. The all-GPU result fits at this short context;
   it is not full 262K all-GPU evidence.
4. One measured request per mode initially. Do not re-run unchanged qualifying
   candidate cases. If CPU control is so slow it exceeds its declared budget,
   preserve processed-token/time bounds and null full-result ratio. Use a
   smaller matched point for a completed comparison, preserving the same
   intended pressure relation via test H. Don't start the six-point CPU curve.
5. Include pp/s, accepted tg/s, wall latency, native-MTP time/acceptance, selected
   rows, copy bytes and memory; optionally one observe sample only if it
   answers a measured instrumentation-overhead question. Ratio denominator
   must have the same workload; do not compare4K CPU with 256K pager.
6. Restore the selected candidate only because this task intentionally ran
   controls; keep that candidate loaded for 26-03, verify exact identity.
