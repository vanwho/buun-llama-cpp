## Implementation sequence

1. Instrument requested/physical/projected scratch per backend owner and context role, with route, K/V materialized row counts, B/U and relevant tensor dimensions. Reuse allocator queries; global free VRAM is not an allocation-owner measurement. Distinguish virtual reservation from mapped physical bytes.
2. Audit the inherited cap to pool.wm_cells+n_tokens. That field is grow-only VBR mapping, and the multi-stream code can overwrite the cap. Replace the assumption with a producer/consumer reservation contract: direct paged kernels declare tile/partial-state scratch; packed/dense declare their actual bounded materialized view; MTP and feature-off declare their own full valid view. The upper bound must be available before execution, including route fallback and maximum admitted verify shape.
3. Do NOT simply clamp allocations below bytes the consumer reads. Make graph construction, view dimensions and reservation agree, with checked arithmetic and tests. An unsupported route either pre-reserves its true requirement or returns an explicit pre-launch refusal; no in-kernel OOM abort as ordinary admission handling.
4. The target selected path must not charge cold L rows to F16 scratch merely because positions are high. But native MTP may legitimately attend its full valid history. Preserve full-L GPU draft KV and charge its temporary F16 buffers separately. Do not infer target H is a valid MTP scratch bound.
5. Account for allocator rounding, prior high-water allocation, packed duplicates, concurrently live target/draft pools, and graph/transfer overlap. A scratch address move invalidates only its owning captured users after in-flight completion. Feature-off and VBR representation paths must remain correct.
6. Fix admission to reserve late target and MTP compute/scratch before offering remaining H. Do not double-count shared pools. Return a structured allocation failure with owner, requested delta and current headroom.
7. Run primary L8192/H4096 B128/U64 across <=2K all-fit input, then attempt C>H pressure input, decode and native-MTP verification. Compare requested and physical scratch before/after each reached stage. Also do a cheap L32768/H4096 allocation+short request with same B/U to distinguish capacity-only buffers from target attention width; this is not the later scale speed test. If the independently owned frontier/pin defect from26-03 prevents a pressure stage, preserve its concrete trace and validate the same scratch view in the CUDA fixture. This narrowly transfers that known runtime defect to26-03; it does not claim joint pressure success or waive live all-fit scratch/placement checks. Re-run the full pressure scratch stages in26-03 after that repair. A scratch failure itself must be fixed here.
