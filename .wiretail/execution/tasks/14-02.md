# 14-02 — Run the dynamic context, MTP, capacity, and teardown ladder

## Objective

Prove on the real model/GPU that all resource dimensions are dynamic and reconciled from small context
through the model maximum.

## Read

- Task README, cluster `14a-correctness-quality`, plan 21 and 24.
- Handoffs 08-02–08-05, 09-02, 12-02, 13-04–14-01; release config/hash.

## Runs

1. Capture active profile/service/GPU baseline and build/hash the release server.
2. Run contexts selected by rule: smallest supported all-pages-fit, at least two increasing intermediate
   values, one odd/non-page tail, and GGUF maximum. Include explicit auto-fit and fixed-context variants.
3. For each record requested/resolved target context, MTP rows/types/backend/bytes, logical pages, runtime
   page bytes, every admission term, derived `H`, selected rows, host catalog/RSS/pinned bytes, VRAM by
   category, scratch peaks and safety remainder.
4. Verify MTP rows exactly equal resolved context, all MTP K/V buffers are GPU, target device storage
   follows `H`, all sealed target pages have host backing, and no production output is constant across
   contexts unless mathematically justified.
5. Exercise explicit safe hot-page caps, headroom/budget changes, too-small refusal, and repeated startup/
   teardown. Verify memory returns to baseline and health restores.

## Acceptance

Every ladder point through model maximum either passes as expected or a deliberately unsafe request fails
before partial serving. Ledgers reconcile within allocator granularity; no trained-context MTP floor,
fixed hot capacity, hidden full target GPU cache, leak, or service restore failure. Cannot be deferred.

## Deliverable

Create `handoffs/14-02.md` and `evidence/DYNAMIC_CAPACITY_LADDER.md/json` with raw directories, pass/refusal
tables, resource equations, and teardown evidence.
