# 85-14 — Optimize GPU page traversal, short-query MTP attention and prefill batching

Revision: `hotpath-v10-20260914`. Amendment: `repair85-20260921`.
Cluster: `repair85-maintenance-speed-v10`. Prerequisite:85-13.
Model: Luna High; first retry High.

## Outcome

Correct fast kernels for prefill and native MTP, O(1) page-row addressing,
reusable graph inputs, and a short cost attribution showing what still limits
speed. Do not add permanent synchronization/extra attention for statistics.

## Specific changes

1. `ggml_cuda_fattn_mma_paged_turbo4_policy::find_row` currently linearly
   searches all pages for every compact row; `load_mask` repeats it per query,
   and K/V tiles repeat it again. Add an explicit device compact-row lookup
   (page descriptor index + in-page offset, e.g. uint2) built once per selected
   table/content layout generation, not per Q/head. Alternatively equivalent
   constant-time tile mapping is acceptable ONLY if arbitrary page tails/gaps
   are still represented; don't divide compact index by256 when partial pages
   break that relation. Use stable admitted-A capacity and dirty updates.
   Account lookup bytes in admission. Loads use this map; causal/native-mask
   and selected-head predicates remain per query. Padded rows never read K/V.
2. `ggml_cuda_flash_attn_ext_paged_turbo4` (~2441 fattn.cu) selects MMA only
   for Q>=16 and no page_mass/split-state. Extend corrected fused policy to
   efficient Q1/2/3/4 shapes using existing ncols/GQA tile machinery, with
   register/shared-memory occupancy measured by tiny fixture. Compare to
   existing cooperative/vec path on identical data. Default to whichever
   **correct** kernel is faster for short-query shape; no blind requirement
   to use MMA when a vector kernel wins. Add a shape dispatch table with
   deterministic supported/fallback reasons; code never keys on test/model name.
3. For Q>=16 prefill keep tensor-core path, Q transformed once, K/V decoded
   in tiles, V inverse once, no gather/full-L floating buffer. Reuse existing
   CUDA architecture capability checks and admitted workspace. Short native
   verification must not perform a separate full selected attention pass to
   produce page-mass telemetry. Normal page_mass off; optional diagnostics
   cannot silently change timed routes. Telemetry-only slower routes are
   labeled outside performance runs.
4. Reuse graph owner, stable physical slab, row-map/table capacity and Q
   scratch. Update active counts/tail/membership data without rebuilding
   operators or recapturing on ordinary content changes. In context execution
   cache key distinguish capacity/shape from data epochs. Shape/batch changes
   can require graphs, not every table epoch. Preserve reader/version pins
   and graph dependencies from85-11, never reuse stale addresses for speed.
5. Take ONE short warm CUDA-events/Nsight trace with ordinary diagnostics off
   at L4096, H2048, C~3072. Attribute wall time to host graph/setup, CUDA model
   ops (including recurrent blocks), paged FA, canonical capture, summary/
   selection, H2D waits and MTP checkpoint work. A zero unimplemented timing
   is null/unknown, not zero cost. Check scheduler placement for unexpected
   CPU attention/recurrent/matmul operators. If one is CPU because backend
   support/layout is missing, reproduce/fix that operator or its view support
   and compare its CUDA result; don't call GPU startup proof of all-GPU work.
6. Safe batch tuning: start matched B128/U128. After above fixes compare ONE
   larger option B256/U256 or B512/U256 if ledger/headroom permits, same tokens
   and A. Reserve measured scratch before H. If larger U wins pp while keeping
   decode/VRAM healthy, retain it as documented optional ingest profile, not
   a hardcoded GPU/model default. If allocation fails, correct H/A/batch and
   rerun matched pair, don't mark speed failure from setup. Record pp vs
   scratch/headroom; very small U sacrifices matrix efficiency and is not
   automatically the best production choice.
7. If a remaining dominant cost is recurrent checkpoint/full-state memcpy,
   reuse accepted-frontier incremental native checkpoint support and avoid
   copying unaffected attention history. Preserve required rejection rollback.
   If weight streaming or CPU scheduling dominates, report/fix that measured
   cause before extra pager micro-optimizations. Don't run another slow long
   frontier in lieu of this one trace.
