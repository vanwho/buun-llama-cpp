# 23-04 — Prove attention-driven cold promotion with physical correlation

Recommended model: **Luna High**. Phase 23; cluster `23b-paging-acceptance`.
Depends on: `23-03`.

## Measured gap and hypothesis

The phase-21 pressure run had 26 logical pages and four resident pages, yet all
H2D/D2H/fault/eviction counters were zero and the route stayed
`selected_reference`. The earlier multi-cold-page policy fix never received live
proof. Hypothesis: committed pages are host-valid, but production prefill/decode
does not invoke the fresh-query policy transaction before constructing the
attention table. Owner: `finish_pager_batch`, `apply_live_policy`, host sealing,
the query split, residency transport, and selected-table publication.

## Minimal reproducer and implementation

1. Use a 6K–8K tokenized prompt, 256-token pages, and an explicit four-page test
   cap. Place one uniquely answerable fact on a known host-only early page and
   query it after the resident set has moved late. Record the table/policy epoch
   before changing code.
2. Trace query projection/rotation through the per-layer selector, transaction,
   D2H seal/H2D promotion, event completion and table publication. Wire the
   missing production boundary or fix the first stale identity/fence rejection;
   do not select from resident inventory alone.
3. Add deterministic cold-only candidate, clean/dirty eviction, stale
   generation, cancellation, slot reuse, partial tail and multi-layer tests.
4. Rerun early, middle, late and recent needles plus one focus shift. For the
   deliberately cold row correlate logical page and representation generation,
   canonical host checksum, transfer bytes/event/fence, physical slot, selected
   route, answer and post-request counters.

## Measurement change and deliverables

At least one known cold page must show useful H2D, a completed promotion and a
same-operation selected route with a correct answer; otherwise identify the
first rejected boundary. Produce `handoffs/23-04.md` and
`evidence/PHASE23_RESIDENCY.json/.md`. Keep host truth lossless, GPU slots
bounded, MTP untouched, and run focused tests/state validation/diff check.
