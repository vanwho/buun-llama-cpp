## State and selection recipe

1. Connect an owner-lifetime query retrieval job tagged by sequence/session/
   turn/query/content identities. Stages: coarse_pending -> keys_pending ->
   rerank_pending -> promotion_pending -> ready. Callback/event completion
   updates this job; no pointers to freed graph nodes. Repeated boundary calls
   are idempotent, stale completions are discarded, cancel waits only for owned
   resource users before reuse. No replay-triggered duplicate retrieval.
2. Preserve current final-user sync. At commit boundary complete the compact
   shortlist, queue104-04 staging and GPU work, consume finalized compact mass
   records, then build the existing live-policy retrieval input. If the owner
   needs a drain, wait on the final event once at this boundary; do not insert
   a fence per page/layer or process another generated token while incomplete.
   No extra per-microbatch ranking/host scan. Existing graph reserves retain
   this owner and its probe/rerank job, just as103-02a retains the pager.
3. Aggregate bundles with the canonical logical ID, exact content identity and
   separate layer provenance. Primary=max peak probability over layers;
   secondary=mean of mean probabilities across participating layers;
   tertiary=number of supporting layers; last tie=logical ID. Use actual
   masses, not 1/(rank+1). Reranked resident/cold candidates share this score
   convention. Reserve structural/current/pinned/query/generation slots first.
4. Fill the allowed historical set with highest-ranked eligible candidates.
   A cold candidate wins only if in that set. Limit actual cold promotions by
   available history slots, existing max_h2d_pages (eight), upload-ring bytes
   and actual candidates; candidate width K may be larger. Retain useful
   resident winners. A cold winner cut by transfer capacity is recorded as
   budget_limited; keep the valid incumbent mapping for omitted winners.
   No fabricated residency/no forced answer-page inclusion.
5. Use existing transaction policy/H2D host key+value units and completion
   publication. Do not mark ready or freeze until successful publication and
   authenticated query result are consumed. The103-02a H200 queued-without-
   publication finding must be exercised by a controlled transaction fixture
   here. If it exposes an actual transaction owner bug, repair that precise
   transition; do not bypass required copies or treat ranking as its fix.
6. Changed mapping invokes existing pre-query checkpoint restore and one
   query replay, including GDN/conv/frontier/MTP carry. Unchanged mapping skips
   replay. Freeze keeps historical pages constant during decode and MTP
   verification. Slot release clears ranking job without invalidating live
   published pages; reset/cancel prevents prior-query result adoption.
7. Expose compact optional metrics: router mode, valid probe count, shortlist
   width, key-only H2D bytes, stage durations, chosen/published cold IDs and
   memory ledger. No per-token stdout logging, full query/score arrays, or
   mandatory telemetry gate for ordinary speed rows. Enable mode only when
   config, backend ops and the whole job can run; fail setup before a request
   for unsupported opt-in rather than silently use CPU/reference/legacy.
