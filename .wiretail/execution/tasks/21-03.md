## Ordered implementation / experiment

These are matched **final campaign** controls, after the system's functional
prerequisites are demonstrated. Earlier control qualification and development
tests use context suited to their own purpose; they do not run this whole curve.
If the target curve could not start because functionality is broken, retain
any existing qualified control receipts and route the failure to repair before
spending the full long-control budget.

1. Run ordinary CPU Turbo4 KV with GPU model/recurrent compute and full GPU Turbo4 MTP on matching tokenized prompts, context, sampling, output budget and cache condition.

2. Use the primary three-prompt protocol, then extend selected representative points to ten trials only when useful to estimate variance. Long CPU prefill is allowed to progress and resume with its own ETA.

3. Run dense all-GPU Turbo4+MTP at safely fitting same-context coordinates. Record why larger points cannot fit instead of comparing against a shorter context.

4. Use observe and MTP-off only as clearly labeled overhead/speculation ablations; preserve full Turbo4 and do not let ablations stand in for the required baseline.

5. Report per-question paired decode and wall-time ratios, medians/dispersion, raw sample counts and comparable conditions. Annotate historical 3x/5x/70% goals without gating task completion.

6. Identify break-even occupancy and explain the latency decomposition: compute, target KV attention, draft/verification, transfers, routing and prefill. If data are missing, name the missing segment; do not extrapolate a claimed ratio.
