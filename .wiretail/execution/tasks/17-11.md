# 17-11 — Consolidate phase-17 benchmark evidence for review

## Objective

Create a compact, machine-readable summary containing only the phase-17
implementation provenance and benchmark results needed by the final reviewer.

## Read

- Cluster `17e-benchmark-soak`, handoffs 17-08 through 17-10, their three
  manifests, and the current task state.

## Work

1. Verify all three benchmark manifests use one coherent model, tokenizer,
   binary, profile, corpus, and resolved-context policy.
2. Summarize quality parity, speed ratios, MTP placement/acceptance, pager
   residency/transfer counters, soak resource bounds, and every blocked or
   missing sub-gate.
3. Link raw roots and hashes; do not copy giant logs or historical phase
   narratives into the summary.
4. State explicitly whether the overall goals are demonstrated, undemonstrated,
   or contradicted by the evidence. Do not change thresholds or manufacture a
   pass.

The JSON summary must contain `schema_version`, `phase`, `provenance`,
`quality`, `performance`, `soak`, `goal_checks`, `raw_roots`, and
`blocked_reasons`. Each goal check must include `status`, `observed`,
`threshold_or_requirement`, and `evidence_pointer`; use `null` for an
unmeasured value rather than zero.

## Acceptance

JSON parses, every pointer exists, summaries agree with raw records, and the
  summary is small enough for a fresh review session to load directly.

## Deliverable

Create `handoffs/17-11.md`,
`evidence/PHASE17_BENCHMARK_SUMMARY.json`, and
`evidence/PHASE17_BENCHMARK_SUMMARY.md`.
