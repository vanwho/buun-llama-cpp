# 17-11 — Consolidate the initial phase-17 benchmark baseline

## Objective

Create a compact, machine-readable baseline for the corrective 17f–17i
benchmark tasks. This is not the final phase-18 review package: it must make
the known context, pressure, oracle, denominator, and lifecycle gaps explicit
so the next tasks can repair and measure them without rereading old phases.

## Read

- Cluster `17e-benchmark-soak`, handoffs 17-08 through 17-10, their three
  manifests, and the current task state.

## Work

1. Verify all three benchmark manifests use one coherent model, tokenizer,
   binary, profile, corpus, and resolved-context policy.
2. Summarize quality parity, speed ratios, MTP placement/acceptance, pager
   residency/transfer counters, soak resource bounds, and every blocked or
   missing sub-gate.
3. Record the V4 corpus context ceiling and clearly label 16K/8K runs as
   diagnostic-only when they cannot cover the corpus or create page pressure.
4. Distinguish host-page bookkeeping from physical transfer/fault/eviction
   evidence, and distinguish HTTP success from exact semantic correctness.
5. Link raw roots and hashes; do not copy giant logs or historical phase
   narratives into the summary.
6. State each goal as measured, unmeasured, or contradicted in this baseline.
   Do not declare the overall goal reached and do not change thresholds or
   manufacture a pass; the revised 17-18 summary is the input to 18-01.

The JSON summary must contain `schema_version`, `phase`, `provenance`,
`quality`, `performance`, `soak`, `goal_checks`, `raw_roots`, and
`blocked_reasons`. It must also identify itself as an initial baseline and
name `17-12` as the next corrective task. Each goal check must include
`status`, `observed`,
`threshold_or_requirement`, and `evidence_pointer`; use `null` for an
unmeasured value rather than zero.

## Acceptance

JSON parses, every pointer exists, summaries agree with raw records, the
baseline status is not a final acceptance verdict, and the summary is small
enough for a fresh corrective session to load directly.

## Deliverable

Create `handoffs/17-11.md`,
`evidence/PHASE17_BENCHMARK_SUMMARY.json`, and
`evidence/PHASE17_BENCHMARK_SUMMARY.md`.
