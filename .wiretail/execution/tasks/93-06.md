# 93-06 — Repair selected prompt-trim recovery after rejection

Revision: `hotpath-v10-20260914`. Amendment: `repair93-mtp-fast-20260922`.

Cluster: `repair93-mtp-diagnostics-v10`.

## Objective

Make the selected/paged prompt path recoverable when a live suffix removal is
rejected. The 93-04 resident and cold runs both reached the trim rejection and
then crashed, so this is the first implementation gate before another live
MTP run.

## Work

1. Trace and repair `tools/server/server-context.cpp` in
   `server_cache_live_range_drop_impl`,
   `server_cache_transient_seq_rm_impl`, and the prompt trim/recovery block
   around `slot.prompt.tokens.pos_next()`.
2. Check the paired implementation contracts in
   `src/llama-memory-hybrid-idx.cpp::{seq_rm,seq_rm_attn,seq_rm_transient,seq_rm_attn_transient}`
   and `src/llama-kv-cache-dsv4.cpp::llama_kv_cache_dsv4::seq_rm`.
3. Preserve the invariant that a rejected partial trim is an explicit failure:
   target and draft memory, token ledger, checkpoint/cache-plan deliveries, and
   slot lifecycle must remain coherent; fallback must not assert, dereference
   invalidated state, or leave target and draft out of sync.
4. Add the smallest deterministic regression at the memory/server seam and
   keep the existing dense MTP controls unchanged.

## Focused verification

`cmake --build build-cuda --target test-kv-pager-model test-mtp-minimal-repair -j2 && build-cuda/bin/test-kv-pager-model && build-cuda/bin/test-mtp-minimal-repair`

The regression must also exercise the rejected positive trim followed by the
full recovery path and prove process survival; a unit test that only returns a
false `seq_rm` result is insufficient.

## Acceptance

The focused test passes and the selected server path no longer crashes after a
measured trim rejection. No MTP, promotion, long-context, or speed claim is
made by this task.
