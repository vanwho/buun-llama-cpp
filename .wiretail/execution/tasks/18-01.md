## Ordered implementation / experiment

1. Build the current CUDA server incrementally without a blanket 240s bound. Capture build exit and configure options. Freeze executable and all loaded project DSOs in an immutable candidate bundle outside source; record hashes/build IDs and a source-diff hash if dirty.

2. Capture the exact named service MainPID, /proc/exe/maps, model, effective context, four Turbo4 codecs, GPU draft placement, and transient overrides. No broad pgrep; credential values stay unread in logs.

3. Reproduce the prior 22,016 startup with the immutable bundle, first one idle health/props/metrics check, then one short generation. Use sudo -n for lifecycle operations and do not touch 8092.

4. If SIGSEGV recurs, capture the first fault with a matching-symbol debugger/core and identify the triggering endpoint. Check shared-library ABI mismatch, snapshot/string lifetime and format types as hypotheses, not established causes. Add the smallest regression and fix the actual cause; don't unpack unrelated old cores.

5. Make one lifecycle owner use bounded wall-clock locks/probes, stop restart storms and restore the exact prior healthy runtime/overrides only on failure or explicit control. Ensure adapter validation failure cannot leave its own healthy-but-wrong candidate falsely labeled restored.

6. Keep a correct candidate loaded; record startup, idle, authenticated metrics, generation, one explicit failed-start recovery and identity after restoration.

## Acceptance

One reproducible coherent bundle starts, survives telemetry/generation, and has trustworthy exact restoration. A nondeterministic historical crash may be classified resolved by coherent-bundle reproduction only with repeated evidence; an ongoing crash must be fixed, not deferred.

## Failure routing and restart behavior

Read the smallest failing record and named source owner, state a falsifiable
hypothesis, change one causal variable, and rerun the minimized case before a
full matrix. Follow `BENCHMARK_PROTOCOL_V5.md` for sizing, capability probes,
progress-aware timeouts, provenance and resume. Repeated setup failure is not
quality evidence. Keep an attempt fingerprint and changed-variable list.
Do not copy a known failure into another giant handoff or silently downgrade
Turbo4, MTP, logical context or measurement protocol. If an unplanned prerequisite
is needed, add a bounded, fully specified task/dependency through the normal
assessment/state workflow, preserving current task order and completed evidence.
Do not renumber tasks just to reset the same exhausted retry.

For site lifecycle operations use passwordless `sudo -n`; capture exact runtime
identity and keep a healthy tested candidate loaded. Restore only for declared
controls or failed-start recovery. Never touch the unrelated service on 8092 or
kill unowned clients/runner display processes.
