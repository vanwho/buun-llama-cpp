# 93-11l — Route on the final causal query row

Revision: `hotpath-v10-20260914`. Amendment: `repair93-selector-promotion-20260925`.

Model and all retry assessments: `gpt-6-luna`, High.

## Objective

Correct the selector query chosen for prompt prefill. Current code hard-codes
row 0 in `llm_graph_context::cb`, rejects every other row in
`llama_kv_cache_context::build_kv_page_select`, and writes `ubatch.pos[0]` as
the query position. Thus a multi-token microbatch scores the first token, not
the final causal token that conditions the next generation step. Use the last
valid Q row and its matching KV position, with graph-reuse sidebands updated
consistently.

## Required implementation

1. Confirm tensor layout from the graph: the selector kernel indexes query
   rows through `q->ne[2]`/`q->nb[2]`; verify this equals the corresponding
   `ubatch` token-position axis for supported single-sequence selector graphs.
   Do not assume a row mapping if dimensions disagree.
2. Compute `query_row = q->ne[2] - 1` (equivalently the last valid token row)
   only after validating `q->ne[2] > 0`, `q->ne[3] == 1`, and the row count
   matches the ubatch positions. Pass that row to `ggml_kv_page_select` rather
   than literal `0`. Preserve the current one-sequence/one-query-head-layout
   safety restrictions; unsupported shapes must return no selector result,
   never index out of bounds.
3. In `set_kv_page_select_inputs`, set the query-position sideband to the
   position paired with the same final row (`ubatch.pos[query_row] + 1`, using
   the repository's actual position mapping and overflow-safe arithmetic).
   Keep sequence/page generation and refresh fields unchanged. If query-row
   metadata must be passed explicitly for shape safety, update the interface
   and all memory/hybrid/ISWA forwarding implementations together.
4. Ensure graph reuse calls `set_kv_page_select_inputs` with the current
   ubatch's final-row position on every enabled refresh. Cadence-skipped
   refreshes must retain the prior valid result. This change must not add an
   extra device synchronization, attention-matrix readback, host page scan on
   skipped cadence, or selector launch per token.
5. Add a deterministic selector regression with at least two Q rows: row 0
   scores an unrelated resident/distractor page highest; the last row scores a
   valid cold host-backed target page highest. Assert that last-row selection
   returns the cold target and that query-position eligibility uses the
   matching final-row position. Add a one-row decode case to prove behavior is
   unchanged when `n_tokens == 1`, plus a future-page/invalid-shape rejection.
   Run CPU and CUDA backend coverage when configured; do not treat an
   unsupported CPU Turbo4 model architecture as failure if the op-level CPU
   contract is supported and CUDA is the production backend.
6. Use the smallest relevant CTest targets; compile the server and focused
   selector/promotion tests. No live Qwen campaign in this task.
