# 93-11m — Trace selector decisions through promotion policy

Revision: `hotpath-v10-20260914`. Amendment: `repair93-selector-promotion-20260925`.
Cluster: `repair93-selector-promotion-v10`.
Model and all retry assessments: `gpt-6-luna`, High.

## Objective

Make one failed natural-promotion attempt diagnostically decisive. Add opt-in,
bounded evidence at the existing selector refresh/scheduler-fence boundary so
the target page can be classified as ineligible, eligible-but-not-top-k,
selected-but-not-read back, mailbox-dropped, rejected by policy/transfer, or
successfully promoted and consumed. Never infer selector nomination from the
success-only `natural_proof` record.

## Required implementation

1. Add an explicitly opt-in diagnostic path (prefer the existing pager debug
   switch or a narrowly named `LLAMA_KV_PAGER_SELECTOR_TRACE` equivalent).
   It must be off by default and emit/update state only when a selector refresh
   is already due or at the already-existing scheduler fence. No per-token
   log, full attention matrix, full-page-table copy, new synchronous CUDA
   fence, or unbounded log stream.
2. At each diagnostic refresh, record the query generation, selected row,
   query position, sequence/page-table epoch, raw cold shortlist (bounded by
   `k_cold`, currently at most 2), and whether asynchronous readback was
   submitted/completed. Preserve the raw returned IDs before mailbox decoding
   can discard them.
3. For one optional diagnostic target logical page (provided only through the
   debug/test path, not production policy), record a compact reason code and
   the values needed to explain eligibility: resident membership, valid
   length/position, sequence/page generation, content version, routing-summary
   content version/readiness, and host backing. Do not make this target ID a
   selector input or force its score/selection.
4. At the policy boundary record whether the exact candidate identity was
   authenticated and, if not admitted, one reason from the actual branch:
   stale/invalid identity, no host source, mandatory/pinned/current capacity,
   policy target omission, slot/admission, transfer-plan rejection, async
   transfer failure, or publication failure. If admitted, record slot,
   H2D queued/completed bytes/event, new table epoch, and later target-graph
   consumption. Keep counters bounded and request-correlated.
5. Add deterministic tests that drive a valid naturally selected cold
   retrieval candidate through the ordinary live-policy/transaction path and
   assert victim → H2D → mapping publication → target use. Add negative tests
   for stale summary, future/invalid page, missing host source, all-pinned or
   no-victim policy, and transfer rejection; assert each yields its distinct
   diagnostic outcome without corrupting the prior target. Tests may inject
   synthetic Q/K-summary inputs but must not call the forced-page production
   hook and then call that natural selection.
6. Update the file-promotion receipt validator/tests so `selector_nominated`
   and each stage are accepted only from direct stage evidence. An empty
   `natural_proof` means `promotion_chain_incomplete`, not
   `selector_nominated=false`. Require raw selector output or an explicit
   `selector_not_run`/`no_eligible_cold_page` reason before assigning those
   labels. Keep answer correctness, MTP acceptance/placement, and page movement
   independent.
7. Add the new 93-11n receipt checker to `validate.py`, with positive and
   negative fixtures for every stage boundary and immutable candidate/page
   identity. Keep it compact: checks and hashes only; never embed request
   transcripts in task state or handoff.
8. Run focused Python validator/driver tests and the smallest relevant C++
   pager/promotion CTests. No live Qwen request in this task.
