# 25-12 — Optimize full-context native-MTP execution and hidden-state handoff

Scope revision: speed-first-20260911. Recommended model: Luna High.
Phase 25; cluster `25e-mtp-integration`; depends on `25-11`.

## Objective / hypothesis

Keep full-context GPU Turbo4 MTP while removing avoidable draft prefill and
decode overhead. Draft cache allocation alone is not proof the draft actually
contains the full processed history or improves committed-token throughput.

## Source anchors

common/speculative.cpp native draft-MTP process(), draft(), accept/pending
hidden-row lifecycle and common_speculative_init_from_params;
common_base_params_to_speculative, target embedding nextn accessors;
tools/server/server-context.cpp target/verify batch loop and sampler;
model Qwen nextn graph; existing native-MTP and server tests.

## Implementation recipe

1. Time target prefill, draft catch-up, target-hidden D2H/host memcpy/H2D,
   draft proposals, target verification, sampling and rejects separately.
   Count target/draft rows processed. Spot full-prefix replays or default
   per-token draft catch-up even when B supports a batch.
2. process() currently copies nextn embeddings through host. Add/reuse a
   device-owned contiguous target-hidden -> native-MTP embedding handoff
   when both contexts share a compatible GPU/backend. Retain only the one
   pending boundary row and required verify/reject slice. Owner/fence prevents
   reuse before draft consumes it. No host pointer masquerading as device.
   Keep correct portable CPU/mismatched-device fallback.
3. Preserve token shift, pending_h, nextn transform/vocab mapping, per-sequence
   positions and rejected-token truncation. Consume each prefill target row
   once; do not clear/reinitialize full MTP history to recover a routine
   batch boundary. A restore-induced fallback is not final full-MTP evidence.
4. Optimize unnecessary logit materialization and CPU synchronization using
   existing GPU sampling/features where supported. Target verification must
   still validate every accepted draft token. Never count unverified drafts.
5. Compare n-max 1/2/4 on one short stable prompt/128-output request each,
   holding target H/A and full draft allocation constant. Actual EOS output
   length is recorded, not padded to fabricate timing. Optional MTP-off
   diagnostic isolates overhead and is never the target final configuration.
   Select n-max from accepted tok/s, not acceptance percentage alone.
6. Preserve target/draft Turbo4/GPU and MTP allocation rows exactly L at two
   diagnostic contexts. At longer histories its one full-context attention
   layer may become material; measure it separately and route through mature
   Turbo FA. Do not sparsify/offload MTP to hide that cost in this revision.

## Checks / acceptance

Short token-order/batch-boundary test, some accepted and rejected proposals,
tail at context boundary with generation reserve, native-MTP history occupancy
advancing with target (allow documented one-row lag), and matching old/new
handoff outputs within existing tolerances. No full restart/checkpoint suite.
Evidence/SPEED25_12_MTP reports host copy savings, draft/target time and the
chosen speculative parameters; end-to-end performance may select a smaller
draft count while keeping MTP enabled.
