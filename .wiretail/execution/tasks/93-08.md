# 93-08 — Re-run the small resident and real cold-promotion controls

Revision: `hotpath-v10-20260914`. Amendment: `repair93-mtp-fast-20260922`.

Cluster: `repair93-mtp-diagnostics-v10`.

Execution model is pinned to `gpt-6-luna` at High reasoning for this task and
all retry assessments. Use only `gpt-6-luna` for this project; do not use
another model family.
Any successor tasks must carry the same exact model and assessment pins.

## Objective

Using the single repaired candidate, prove that dense MTP still works, selected
resident MTP survives prompt reuse, and an old Turbo4 page can be promoted and
consumed after a newer document displaced it. This is a short functionality
gate, with initial timing observations only.

## Preconditions

- Tasks 93-06 and 93-07 are done; deterministic trim recovery and harness
  contract tests pass.
- Use Qwen3.8-27B UD-IQ4_XS, exact current CUDA candidate SHA, target K/V
  Turbo4, native draft placement GPU with draft K/V Turbo4, one slot, `-b 128`
  and `-ub 64` (lower `-ub` only if the logged safe-headroom preflight requires
  it). `draft_n_max=2`, output limit 16.
- Ensure the candidate identity matches the handoff. Continue the already
  loaded process only when its PID/start time, executable/model path and hashes,
  full rung settings, and `continue_loaded=true` all match; otherwise reload
  through the canonical profile lifecycle. There must be only one Qwen CUDA
  process.
- All phase-93 target hot-page configurations are at most 49152 tokens, with
  safety headroom set to `auto`. Use 16 pages (4096 tokens) for resident
  control and four pages (1024 tokens) for the cold probe. Do not raise either
  value to fill available VRAM.
- Keep dense/resident `-c=4096`; use `-c=8192` only for the three-step cold
  sequence. No context above 16384 and no measured input above 16384 rendered
  tokens, including retained prefixes. Record the exact tokenizer count before
  each request. Never truncate a prompt to fit.

## Work

1. Build the final candidate once and save SHA-256 for server, model and source
   revision. Do not rebuild between rungs.
2. Run, in order, one request for each of:
   - dense MTP off;
   - dense native MTP on;
   - selected/paged native MTP with all 16 pages resident.
   Reuse the exact paired short prompt, greedy sampler, seed, output limit,
   target/draft Turbo4 types and command geometry from the 93-04 control.
3. Only if all three requests complete and have valid request-local telemetry,
   run the cold probe as exactly three prefix-preserving requests in the same
   slot: A fact; append B and ask a B fact; ask the earlier A fact again.
   Verify before the third request that A's identified page is host-backed and
   nonresident. For request three require A's same logical page generation and
   content version to be selected, H2D-completed, published to the page table,
   and consumed by both target attention and MTP verification. Record the
   first two request results even if the third fails.
4. For every MTP-on request record `draft_n`, `draft_n_accepted`, denominator,
   acceptance percentage, verification steps, target/draft positions,
   rollback/rewind counters, and target/draft GPU Turbo4 placement. Compare
   selected-resident acceptance with its paired dense MTP request. Missing
   evidence remains null and makes that capability unproven.
5. Preserve prompt timing if the harness reports it, with its exact input
   token count. These short diagnostic prompts are not a prefill speed result.
   Do not run a separate input above 16384 tokens. Save VRAM before/after,
   `--kv-safety-headroom`, scratch high-water, page movement, route and
   lifecycle identity for each request.
6. If an OOM/configuration failure occurs, stop the failing candidate through
   the managed lifecycle, reduce only the relevant `ubatch` or hot-page count,
   record the changed geometry, and rerun that same rung once. Do not relabel
   the failed geometry or count it as an MTP/promotion result. If the same
   candidate still crashes after config correction, preserve logs and mark the
   capability false for 93-09.

## Bounds and stop rules

The diagnostic harness remains bounded to at most three requests per rung,
except the cold sequence which is exactly its required three requests. Do not
run repeated polling loops, 20K+ prefill, 256K occupancy, or a long soak. Stop
on the first failed prerequisite rung and do not spend a live run on later
rungs. Preserve the successful candidate/service loaded after completion.
