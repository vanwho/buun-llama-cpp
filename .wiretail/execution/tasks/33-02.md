### Turbo4 versus TCQ CPU-test classification (mandatory)

`GGML_TYPE_TURBO4_0` is the required 4-bit Turbo4/PolarQuant representation
for both the target pager's canonical host pages and the GPU target cache.
`GGML_TYPE_TURBO3_TCQ` is a different 3-bit trellis-coded format; its accurate
quantize/dequantize implementation is CUDA-only and its CPU reference routines
are stubs. Therefore a CPU-only `test-llama-archs` failure or refusal that
specifically names `turbo3_tcq` and an unavailable TurboQuant/CUDA backend is an
expected backend-fixture limitation, not a merge failure and not evidence that
the Turbo4 pager must be changed to F16, Q8_0, or standard q4_0.

Classify that exact limitation in `V9_INTEGRATION.json` and continue. Do not
hide any failure that names `turbo4`, a Turbo4 host capture/round-trip, CUDA
Turbo4 attention, page transfer, native-MTP placement, or a memory/lifetime
error. Run the desired-path checks with `GGML_TYPE_TURBO4_0`: verify the host
capture preserves encoded Turbo4 bytes and verify the CUDA Turbo4 page/attention
test consumes them. F16/Q8_0 are controls or CPU-attention fallbacks only, never
the pager's canonical representation.
