# 23-02 — Serialize compact paged KV checkpoints by physical identity

Recommended model: **Luna High**. Phase 23; cluster `23a-runtime-repair`.
Depends on: `23-01`.

## Measured gap and hypothesis

The second equal-work 6,401-token pressure request aborted in
`llama_context::state_seq_get_data` from `server_slot::prompt_save` with
`offset + size <= ggml_nbytes(tensor)`. Hypothesis: checkpoint serialization
uses dense logical-row offsets against compact physical-slot tensors after the
first request advances/reuses slots. Owner: sequence-state serialization,
`llama_kv_cache` paged views, and server prompt-cache save/restore.

## Minimal reproducer and implementation

1. Reproduce exactly two equal-work requests at 6,401 occupied tokens with 26
   logical pages and a four-page diagnostic hot cap. Capture requested tensor,
   logical range, physical slot/generation, offset, size, and tensor bytes at
   the assertion boundary.
2. Serialize committed sequence state through an explicit pager-aware iterator
   over logical identity and canonical host/physical bytes. Never apply a
   logical context offset to a compact slot tensor. Preserve partial tails,
   Turbo4 representation metadata, recurrent state, accepted speculative state,
   generations and transaction fences.
3. Add deterministic save/restore tests spanning page wrap, noncontiguous slots,
   partial tails, eviction, cancellation, slot reuse and insufficient output
   buffers. Compare restored selected-all logits/state with the pre-save state.
4. Rerun at least three equal-work cycles plus checkpoint restore and a short
   continuation; retain the original stack fingerprint as the negative control.

## Measurement change and deliverables

The second request must no longer abort; save/restore byte counts remain within
each backing tensor and restored state preserves answers, page identities and
MTP recovery. Produce `handoffs/23-02.md` and
`evidence/PHASE23_CHECKPOINT.json/.md` with stack/raw IDs and focused test/live
results. Validate state and `git diff --check`; do not touch port 8092.
