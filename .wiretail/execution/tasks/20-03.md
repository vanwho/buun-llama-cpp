## Ordered implementation / experiment

1. Profile the synchronous correctness baseline first: host staging, queued/copy/wait times, useful/aligned bytes, copy batch sizes and compute gaps.

2. Add bounded staging/upload queues, coalesce adjacent segments where identities/layout permit, use a dedicated upload stream and GPU event dependencies, and avoid whole-device synchronization.

3. Use previous-query/layer prediction only as lookahead; actual current-query selection remains authoritative. Measure hit/usefulness and bytes wasted by wrong predictions.

4. On an essential page not ready, wait safely or use documented exact/expanded fallback; don't silently skip it to improve timing. Revalidate epochs before publication and cancel stale speculative requests.

5. Never evict pinned write/draft pages or overwrite an in-flight/read slot. Backpressure must bound events, descriptors, pinned bytes and queue latency.

6. Compare synchronous versus async on identical cold-focus/churn histories; report actual overlap from event/profile timelines, not the existence of two streams.

## Concrete execution recipe

Read `EXECUTION_COOKBOOK.md` sections C1/C3/C4/C5 and `IMPLEMENTATION_CONTRACTS.md` sections I2/I5. These are shared context; reuse them within the cluster.

Keep the synchronous 19-03 adapter as an explicit baseline. Implement bounded
upload queue/ring and event completion first; one submit ticket owns a page
identity, host span, destination slot, epoch and completion/cancel state.
Only completed valid tickets become graph-visible.

Add two-buffer lookahead using real previous-query evidence. Timeline receipt
for one promotion must contain enqueue, copy begin/end, needed-by layer/token,
wait and consumption. If needed before ready, wait or the recorded safe
fallback; do not count skipped attention as overlap. Cancellation checks
identity before and after transfer, and slot reuse waits for all readers.

Test ring saturation and out-of-order completion with deterministic fake events,
then a real CUDA transfer timeline. Report useful versus wasted prefetch bytes,
warm zero-copy behavior and CPU/GPU wall impact. Merely using two streams or
asynchronous API names is not completion.
