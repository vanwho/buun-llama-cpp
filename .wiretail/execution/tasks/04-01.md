# 04-01 — Build all-page routing summaries

## Objective

Give cold pages a bounded GPU-resident representation that can be scored before their full K/V is loaded.

## Read

- Task README; plan section 8.6; semantics/policy docs.
- Qwen3.8 K storage/rotation code, existing top-k operators, and Phase 03 native-position plumbing.

## Implementation

- Start with a versioned experimental summary: 4–8 representative rotated K vectors per logical page
  for a documented subset of full-attention layers/heads.
- Build/update the summary when a page is sealed or mutated; bind it to page/representation generation.
- Store all 1,024 page summaries in a separately accounted GPU buffer if budget allows, otherwise fail
  the selective configuration.
- Score all valid summaries from the available query, reduce to one logical-page score, and return a
  deterministic top-K plus score state.
- Use existing radix top-k only after verifying shape/latency suitability.
- Do not expose the provisional summary format publicly.

## Tests and acceptance

Test construction/update/invalidation, tail pages, stale summary rejection, deterministic top-K, native
positions, empty/invalid pages, and memory charge. Report exact summary bytes and scoring latency. Use
synthetic cold needles to show the router can choose a nonresident page; do not claim task quality yet.
