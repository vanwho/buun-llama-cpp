# 25-05 — Optimize direct paged prefill tiles and compare against packed Turbo4

Scope revision: speed-first-20260911. Recommended model: Luna High.
Phase 25; cluster `25b-prefill-kernels`; depends on `25-04`.

## Objective / hypothesis

Provide an efficient paged prefill path where packing/contiguous reuse loses.
A query tile is a GPU scheduling unit, not the whole model's microbatch.
Use tiled QK/softmax/PV rather than row-serial scalar attention for large Q.

## Implementation recipe

1. Preserve the serial <=64-query primitive as an oracle. Add query-base/count
   to the launch/descriptor contract so grid.z or an equivalent grid dimension
   covers ceil(n_query_tokens / tile_q). Q/K/V output strides remain explicit.
   Support arbitrary qualified B via tiles; don't allocate B*256 shared memory
   in every block or simply raise the current 64 constant.
2. Integrate a page-aware K/V tile loader into the mature Turbo FA MMA path
   where possible. For each KV tile map compact rows to logical/physical pages,
   load compressed Turbo4, dequantize into bounded shared/register tiles and
   use GPU matrix instructions. Reuse K/V across query tiles/GQA heads where
   resources permit. No runtime third-party dependency.
3. Carry online-softmax max/sum/weighted-V per query across KV tiles. Preserve
   GQA heads, original native positions, tail mask, causal future mask and
   existing transform domain. Handle the all-masked partition without NaNs.
   Build mask on tile boundaries; no full Q-by-L scores allocation.
4. Cap split/partial scratch from (tile Q, heads, partitions), not L*Q*head_dim.
   Preallocate outside graph capture; cache device properties and shared-memory
   setup. Page-mass export is sampled/disabled for speed, not required per Q.
5. Test a bounded sweep of tile_q 16/32/64 and practical KV tiles (e.g.32/64)
   on Q=64/256/512; choose 2–3 candidates from register/shared-memory limits,
   not a huge Cartesian sweep. Capture attention time, occupancy and spills
   with events/one ncu sample.
6. Compare against 25-04 packed+dense TOTAL cost at the same selected rows and
   data. Use one micro-model request only after raw CUDA checks; 25-06 wires
   full-model batching. If packed wins all relevant shapes, select packed and
   document a tested direct fallback/negative experiment; don't force the
   custom kernel into production to satisfy the task title.

## Checks / acceptance

different physical-slot order and grouped heads. Compare numerical errors
