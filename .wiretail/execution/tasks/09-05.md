# 09-05 — Bind real CUDA promotion, publication, and clean eviction

## Objective

Replace remaining residency fakes with real H2D uploads, CUDA/VMM or compact-slot mapping, completion
events, atomic table swaps, and zero-D2H clean eviction.

## Read

- Task README, cluster `09b-live-transfers`, plan 8.8 and 22 steps 4–5.
- Handoffs 02-03–02-05, 04-04, 06-02, 09-02–09-04.
- Residency pool/transfer/transaction/prefetch, CUDA VMM and pinned APIs, graph scheduler fences, catalog.

## Implementation

1. Implement a CUDA residency adapter owning physical slots/mappings, upload stream(s), events, staging
   claims, and backend-granularity accounting. Do not make the VBR pool the page authority.
2. Coalesce compatible page/layer/side runs without crossing identity or allocation boundaries. Track
   useful versus aligned bytes.
3. Reserve destination slots and pin source/victims before copies. After event completion revalidate all
   generations and checksums, then atomically publish a complete immutable page table.
4. Roll back map/copy/event/publication failure to the prior table and release every temporary resource.
5. Clean eviction unpublishes after consumer fences and drops the slot/mapping with zero D2H. Dirty pages
   must reseal through 09-04 first.
6. Add actual transfer/latency/stall counters and teardown drains.

## Tests and live fixed-selection benchmark

Run CUDA memcheck/racecheck where supported plus event reordering, cancellation, stale completion, map
denial, allocation pressure, ring exhaustion, all-pinned, corrupt source, partial batch, and teardown.
Then run the real Qwen model beyond `H` using a deterministic manual page selection derived from the
reported capacity. Promote at least one old page, verify byte equality, evict clean pages, and record
VRAM/RAM, D2H/H2D, event, ledger, MTP placement, and teardown. Attention may still use a reference path.

## Acceptance

No fake callback remains on the production transfer route. The live run crosses capacity, host pages
remain canonical, promotion succeeds, clean eviction reports zero D2H, device usage stays bounded, MTP
stays GPU, and service state restores.
