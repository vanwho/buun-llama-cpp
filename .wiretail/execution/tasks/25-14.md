# 25-14 — Autotune hot capacity, selected rows and batch sizes with full-context MTP

Scope revision: speed-first-20260911. Recommended model: Luna High.
Phase 25; cluster `25e-mtp-integration`; depends on `25-13`.

## Objective / hypothesis

Optimize H (residency), A (attention work) and B (batching) jointly rather than
consuming every last GPU byte for hot KV. Admission must retain full-context
GPU Turbo4 MTP even at 262144; final capacity is not a guessed77K target cache.

## Implementation recipe

1. Produce a byte ledger from actual weight/target/MTP/GDN buffers, all
   layers' strides/alignment, graph/split/packed-view scratch, active B,
   host/D2H/H2D rings, descriptor/summaries, allocator overhead and safe
   headroom. Do not count a shared buffer twice or omit a duplicate pack.
2. Reserve MTP at exactly resolved L first, with actual compute scratch.
   Admit H only from the remainder. Target canonical host allocation covers
   full L plus bounded metadata; do not rely on sampled host rows for budget.
3. Within memory cap, reserve write-wave slots + promotion slack; remaining
   hot slots cache pages. Select A independently. Implement generic controls/
   validated internal policy for derived budgets, recording actual values.
   Explicit benchmark overrides remain test config, not production defaults.
4. Use short empirical coordinate search: choose safe B256/512 (1024 only
   if plausible), then2–3 A/H settings and winning MTP n-max from 25-12.
   Reuse stable process/model where safe; at most six configuration candidates
   initially, one original short question each. No giant Cartesian sweep.
   Optimize/report pp/s and committed tg/s separately; retain Pareto profiles
   if the best prefill and decode settings differ.
5. Validate full 262144 allocation with matching GPU MTP and one <=512-token
   smoke. On OOM hold L/draft rows fixed, reduce H or B/scratch and retry with
   a ledger-derived decrease and margin. Detect restart loops and stop them.
   Context reduction is a labeled diagnostic, not success for this step.
6. If even minimal useful H fails, report exact fixed-cost deficit and inspect
   double allocations/fallbacks rather than sending the task back to a16K
   “safe final” profile. Integrate the smallest source fix needed here.
