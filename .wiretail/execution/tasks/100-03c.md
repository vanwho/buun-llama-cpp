## Measured trigger

medians were 179.16/182.06/182.76 tok/s versus a 500 tok/s floor, MTP acceptance
was 20.74/0/0% versus 75/40/60%, and selected decode was slower than CPU-main-KV
on prompt 1. Across the selected placement's cumulative 12-row snapshot window,
there were 3,296 graph captures/rebuilds, 225,401 packed-copy updates covering
8,591,491 rows, 929,381,376 host seal D2H bytes, and 46,256,256 us in waits.
These are cumulative owner counters, not per-request or kernel-time attribution.
The full measurement and limitations are in the 100-03b handoff and its hashed
`SHORT_PATH_RESULTS.json`.

## Objective and scope

Make one source-directed repair in the selected packed-view refresh path, focused
on `llm_graph_input_attn_kv::refresh_selected_data` in `src/llama-graph.cpp`.
The current packed branch classifies each row against `metadata.query_positions()`
while it builds current-query versus frozen-history copy intervals. Establish the
query-position ordering/uniqueness contract first; use a linear merge/cursor (or
an equally bounded lookup) only when it preserves the existing semantics, and
retain a safe fallback if the contract permits unsorted positions. Preserve page
order, physical slots, native positions, query masks, generation invalidation,
rollback behavior, and packed source ownership. Do not weaken correctness or
change routing/geometry/MTP to improve the counters.

The intended cost change is to remove repeated row-by-query membership scans
from packed selected-view refresh, reducing refresh CPU work and avoidable packed
copy updates/rows for the same selected prompt shape. The 100-03b counters are
campaign evidence that justifies investigating this owner; they do not by
themselves prove that this one loop caused the measured speed miss. Keep the
change to one cause and one focused regression.
