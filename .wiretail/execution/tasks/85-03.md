# 85-03 — Promote automatic multi-page direct paged Turbo4 attention

Revision: `hotpath-v10-20260914`. Cluster: `85c-direct-route-v10`.
Prerequisite:85-02.

After 85-02 proves positive request-scoped native-MTP acceptance, repair the
multi-page direct CUDA boundary that phase 84 left fail-closed after an
illegal-memory result. The production selective route must consume the
persistent physical Turbo4 K/V slab and a stable page table; it must not
allocate or copy compact selected K/V per graph. Dense/reference are guarded
correctness fallbacks only, and `selected_packed` remains explicit diagnostic
only.

Exact implementation scope:

- `production_direct_shape()`,
  `llama_kv_attention_execution::planned_route()`, `same_graph()`, and
  `prepare()` in `src/llama-kv-attention-execution.cpp/.h`.
- `llama_context::prepare_kv_attention()` and
  `llama_context::prepare_kv_attention_graph()` in
  `src/llama-context.cpp/.h`; preserve the pager-owned physical pool, stable
  logical IDs, table epoch/update ownership, and graph input lifetimes.
- `ggml_cuda_flash_attn_ext_paged_turbo4_route()`,
  `ggml_cuda_flash_attn_ext_paged_turbo4()`,
  `ggml_cuda_flash_attn_ext_paged_turbo4_supported()`, and the page-table
  validator in `ggml/src/ggml-cuda/fattn.cu` (and its declared CUDA headers).
  Fix bounds, active page/row counts, tail masking, and multi-page query-tile
  handling at the source of the illegal-memory boundary.

Required tests:

- Extend `tests/test-kv-attention-execution.cpp` to assert automatic direct
  dispatch for the proven multi-page Turbo4 metadata, no packed bytes/epochs,
  stable page-table graph reuse, and guarded refusal for invalid/noncontiguous
  tables.
- Run `tests/test-cuda-kv-promotion.cpp` and the relevant CUDA page-summary
  test with the real Turbo4 representation. Assert selected logical IDs,
  physical slots, output parity against the guarded reference route, and
  completed target-graph use after H2D publication.
- Run a 256-token fail-fast CUDA smoke at L8192/C6143/H4096/A4096/B128/U128.
  Its receipt must show nonzero automatic direct-route counters, GPU
  utilization samples, zero automatic packed-copy updates, and deltas for
  graph rebuild/replay, H2D, table publication, and faults.

Do not add a second scheduler, CPU attention, F16 gather, compact selected
bridge, or a broad benchmark.
