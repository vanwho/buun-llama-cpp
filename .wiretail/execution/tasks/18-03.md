## Ordered implementation / experiment

1. Implement case IDs keyed by immutable provenance, prompt/config hashes, cache condition, mode and repetition. Flush raw response and atomic progress after every case; skip only matching successful completed keys on resume.

2. Separate connect, startup, prefill-progress, decode-idle and campaign wall limits. Derive prefill estimates from observed same-mode work with growth allowance; use server progress while no tokens stream. Persist ETA and last-progress timestamp.

3. Remove fixed whole-campaign 180/240/300s assumptions. Keep configurable hard limits but make expiry checkpoint resumably as incomplete, not wrong answer/zero speed. Do not impose a token-use cap in Wiretail.

4. Probe capabilities and three correctness sentinels before each mode's full matrix. A systematic mismatch routes a minimized reproducer to 18-05/06; a known 501 produces one unsupported record and stops that mode, not 24 identical failures.

5. Track request/slot identity and owned client PID/start time; cancel/drain after timeout and verify idle before the next case. Never kill generic Python, /dev/fd/3 or the runner renderer.

6. Measure true SSE TTFT/chunk gaps and server pp/tg separately, preserve real output counts, and correct summaries to distinguish runtime, invalid setup, semantic mismatch and censored timeout. Keep original-three-prompt primary settings.

## Verification and live checkpoint

- Regression: interrupt after case 2, resume, no duplicate completed rows; change bundle/config and reject reuse; known 501 short-circuit; progress without SSE; timeout with orphan drain; delayed SSE and multi-token chunks.
- Run a tiny live campaign, deliberately interrupt its owned client, then resume to a complete manifest without resending completed cases.

Run relevant existing regression tests before/after the fix, build changed targets,
and preserve exact commands/exit codes and raw results. Use runtime-supported
CLI options discovered with `--help`; do not invent an undocumented benchmark
mode. CPU/fake tests do not substitute for the named live target checkpoint.
Benchmark speed is a finding, not a numeric pass/fail gate.

## Acceptance

An interruption no longer discards progress or produces misleading zero/quality rows. Slow healthy prefill can proceed beyond 300 seconds with observable progress and finite operator-configurable bounds.

## Failure routing and restart behavior

Read the smallest failing record and named source owner, state a falsifiable
hypothesis, change one causal variable, and rerun the minimized case before a
full matrix. Follow `BENCHMARK_PROTOCOL_V5.md` for sizing, capability probes,
progress-aware timeouts, provenance and resume. Repeated setup failure is not
quality evidence. Keep an attempt fingerprint and changed-variable list.
Do not copy a known failure into another giant handoff or silently downgrade
Turbo4, MTP, logical context or measurement protocol. If an unplanned prerequisite
is needed, add a bounded, fully specified task/dependency through the normal
assessment/state workflow, preserving current task order and completed evidence.
Do not renumber tasks just to reset the same exhausted retry.

For site lifecycle operations use passwordless `sudo -n`; capture exact runtime
identity and keep a healthy tested candidate loaded. Restore only for declared
controls or failed-start recovery. Never touch the unrelated service on 8092 or
kill unowned clients/runner display processes.
