## Exact work and localization decisions

1. Trace native MTP in `common/speculative.cpp`: native class, target hidden
   state/output row mapping, `common_speculative_rollback_frontier_resolve`,
   rollback guard; server accept/rollback in `tools/server/server-context.cpp`
   (~20900 onwards), context output/hidden-state getters and hybrid memory.
   Find exact current symbols with rg; skip unrelated speculative algorithms.
2. Use85-10's finite target and SAME token sequence. Teacher-force a short
   prompt plus two proposed continuation tokens as target-only versus batched
   verification. Capture absolute positions, batch/logit/embedding row indices,
   token entering draft, target hidden row, proposals and target rows. First
   divergence dictates fix: attention→85-09 layout invariant; row/position→
   index owner; only post-rejection/reuse→rollback owner. Don't rewrite state
   because numerical attention corruption reduced acceptance.
3. Freeze selected mapping/content generation for one draft/verify/commit
   transaction. Each verification row uses its own absolute causal position;
   future proposal K/V cannot leak into earlier rows. Advance refresh by
   accepted target tokens, not attempted proposals/polls. Publish completed
   promotions between transactions; retain table readers through verify.
   Numerical target-only control uses the SAME frozen selection schedule;
   normal dynamic-selection performance is measured separately.
4. For accepted counts0/1/2 at n-max2, one owner resolves committed target
   frontier including bonus token. Align target attention K/V, recurrent
   state, draft K/V, saved hidden row and next draft position. Attention-only
   `seq_rm` is not a hybrid recurrent restore. Reuse native recurrent/checkpoint
   machinery, avoid full attention-cache serialization per verification.
   Don't disable required checkpoints solely for timing.
5. Audit85-08 `target_restored_without_draft` reporting: rejected suffix is
   not proof of successful restore. Propagate actual target/draft restore
   success/epochs, absence/failure distinct. Diagnostics may compute argmax
   from finite logits if side-output absent; production acceptance counters
   must not add full-vocab host scans.
6. Remove native-MTP prefill / `mtp_verify` exclusions from
   `llama_kv_attention_execution::planned_route` after parity. Select by
   supported shape/layout, not MTP enabled. Use genuine contiguous view or
   corrected direct route. Q1/2/3 must remain correct GPU consumers until
   85-14 optimizes them. No reference fallback to satisfy fast-route proof;
   keep explicit reference override for numerical tests only.
7. Draft KV stays separate from target pager: configured Turbo4/Turbo4 on
   GPU for resolved per-sequence L, never H/A or77K. Verify its route, own
   positions and storage, and ensure target eviction cannot reach it.
