# 21-01 — Run a bounded live pager capability gate

Recommended model: **Luna High**. Phase 21; cluster `21a-quality-curve`.
Depends on: `20-07`.

## Objective

Replace the stopped long corpus run with a short, decisive diagnostic that
answers whether the frozen Qwen3.8-27B candidate is actually using the intended
Turbo4 selective path. This task must not launch the full corpus or speed
curve. Preserve the stopped campaign as negative evidence and write a compact
receipt naming the first failing implementation owner.

## Required configuration

Use the immutable 20-07 bundle and the Qwen3.8-27B UD-IQ4_XS model. Target K
and V, draft K and V, and native MTP must all be Turbo4. Draft MTP must be GPU
resident. Use a 262144 logical context for allocation checks, but choose a
small occupied prompt (2K–8K tokens) for the diagnostic. Set hot capacity from
the runtime's safe VRAM budget (`auto` or an explicit byte budget); do not use
`--kv-hot-pages 4` except as a separately labelled negative control.

## Ordered work

1. Verify bundle/model/template/policy hashes and capture the exact argv and
   runtime identity. Confirm startup logs show all four Turbo4 types, GPU MTP,
   and resolved logical context.
2. Run one all-fit dense or selected-all warm sentinel. Run one selective
   warm sentinel, then one selective cold-needle request whose fact is known to
   be outside the initial resident page set. Keep each request to a bounded
   output and progress-aware timeout.
3. Require telemetry for route (`selected_direct` or `selected_reference`),
   logical/selected/physical page counts, host-valid rows/bytes, H2D/D2H,
   faults, evictions, queue/copy/wait time, and MTP placement. Missing values
   are `not_observed`, not zero or success.
4. Compare answer correctness and route counters. If the cold needle is not
   promoted, or the route is CPU/reference fallback, stop and identify the
   owning source function. Do not repeat equivalent prompts.
5. Run a small prefill timing comparison with pager `off`, `observe`, and
   `selective` at the same occupied tokens. This is a diagnostic only; do not
   call it the final speed result.

## Acceptance

Produce `handoffs/21-01.md` and `evidence/PHASE21_CAPABILITY.json/.md` with
raw pointers, route/movement/quality observations, and one of `capable`,
`partially_capable`, or `blocked`. A blocked result is complete only when it
contains a minimized reproducer and a precise next implementation owner.
Never run more than three selective requests after the first confirmed
systematic failure. Keep the successful candidate loaded for 21-02.

## Failure routing

The next task is implementation, not another giant benchmark. If startup or
telemetry fails, record the exact error and continue to 21-02 only when its
repair scope is clear. Do not change codecs, silently reduce logical context,
or reinterpret a four-page diagnostic as production behavior.

## Validation

Run focused C++/CUDA pager and attention tests, the benchmark contract tests,
`PROJECT_ROOT=/srv/repos/vanwho/buun-llama-cpp python3 /srv/wiretail/task_state.py validate`,
and `git diff --check`. Site paths and raw results remain outside generic code.
