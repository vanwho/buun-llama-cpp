# 100-03f — Stabilize the measured selected-view/graph hot path

Revision: `hotpath-v10-20260914`. Amendment: `post100-hotpath-20260930`.
Cluster: `forward100-postmerge-hotpath`. Model and assessments: `gpt-6-luna`, High.
Dependency: `100-03e`. Read only its compact handoff, HOTPATH_POST100 and
the selected source files below. Do not reopen 100-03b's full raw campaign.

## Decision already specified for the implementer

Use the request-local attribution from 100-03e. Implement the first applicable
branch below; do not pursue all branches for their own sake. A branch is
material if it costs >=20% of fresh-prefill wall time, or explains >=20% of
the selected-versus-dense delta. If neither is material, write a tested
no-change receipt and move to 100-03g. This prevents an unmeasured buffer
from consuming scarce 16GB VRAM.

### A. Capacity/owner or graph recapture dominates

`src/llama-kv-attention-execution.cpp::llama_kv_attention_packed_row_capacity`
currently follows selected extent; `packed_cache::find_or_create` keys owners
on row_capacity; `src/llama-graph.cpp::llm_graph_input_attn_kv::can_reuse`
rejects another capacity. Introduce a *bounded admitted-capacity bucket* in
the selected packed owner, not a full-L allocation. Compute required rows as
the maximum compact-row end, choose the smallest bucket at/above it (page
counts 1,2,3,4,6,8,12,... are a starting table; cap to admitted A rows),
and charge the owner plus one possible draining replacement to the VRAM
ledger before allocation. If the bucket would exceed admitted A, use the
current exact size or select a different GPU route; do not overcommit or
silently change H/L. Keep actual selected row count separate from allocated
rows. Mask padded rows as inaccessible, preserve native positions and causal
mask. Graph reuse may refresh descriptors/content within the same bucket only
when source lifetime, backend, K/V dtype, ubatch shape and physical key match.
When the bucket changes, safely retire old owners after their CUDA completion
event. Maintain replay/rollback epoch and original Turbo4 tensor names.
If profiling shows the recapture reason is instead ubatch shape/physical key,
repair *that exact key*: normalize an equivalent stable shape or stop bumping
an unchanged epoch; never ignore a genuinely changed physical/content key.

### B. Packed data copies dominate

Use `packed_cache::update_slots`, `page_action_make`, and
`llm_graph_input_attn_kv::refresh_selected_data` as the owner. Reuse frozen
history slots by `(logical page, physical slot, content version, row count,
source lifetime)`; copy only changed historical page intervals and the new
current-row suffix. Coalesce adjacent copy intervals before issuing K/V async
copies. Do not copy the whole selected view per ubatch, per output, or per
verification step. On page generation/rollback, invalidate exactly affected
intervals. On a page whose current row count grew, copy only newly valid rows,
and never mark its old prefix clean if the source lifetime changed. Keep copy
submission on the backend stream; wait only before a consumer that would read
not-yet-completed bytes. If unchanged pages are already reused and the measured
cost is *kernel* rather than copy, do not rewrite this path.

### C. GPU attention kernel dominates

Compare `selected_packed` and `selected_direct` on the *same* selected page IDs,
Turbo4 encoded bytes, Q shape and native positions. Include A preparation,
copy waits, graph creation and kernel time in total cost. Keep the faster
observed route in automatic dispatch for that measured shape. If direct is
slower, leave packed selected. If direct wins, gate it by supported shape and
memory budget in `select_route`; do not expose reference/CPU/F16 as a fallback.
Upstream's sparse CUDA interface is inspiration, not evidence that it accepts
our pager table already. Any kernel change must consume Turbo4 directly.

## Focused proof and stop

Add one small CUDA fixture to `tests/test-kv-attention-execution.cpp` or the
closest post-merge test owner: 1–3 noncontiguous pages, grow a current page,
leave one history page unchanged, then rollback/replace another page. Assert
exact K/V bytes or logits against the existing selected reference oracle,
page/slot/content identities, mask of padded rows, and no extra owner/copy on
the unchanged case. A diagnostic reference oracle is fine in a fixture, not
in the production route. One fresh prompt-2 live row (<=8K input, <=80 output)
with the same L/H/B/U/Turbo4/MTP geometry as 100-03e quantifies pre/post cost;
do not run the canonical 36 rows. A no-change decision instead needs the
100-03e timing artifact and the named capacity/copy invariants fixture.
Proof `selected_hotpath_measured_repair_or_no_change` goes in
`evidence/V10_100-03f.json`; compact handoff and raw root use 100-03f. If a
new bucket improves graph count but worsens total time or VRAM, revert that
bucket within this task and retain only correct fixture/diagnosis.
