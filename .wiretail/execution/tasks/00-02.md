# 00-02 — Pin source, model, build, and hardware provenance

## Objective

Produce a reproducible baseline manifest before code changes.

## Read

- `CONTRIBUTING.md`, task README, and plan sections 3, 5, 6, and 12.4.
- `/srv/ai/benchmarks/README.md` and the manifest-writing portion of
  `/srv/ai/benchmarks/run-profile-benchmark.sh`.
- `/srv/ai/config/profiles/qwen38-fast.env` read-only unless the handoff explicitly identifies a
  separately approved config change.

## Deliverables

- Add `.wiretail/execution/baseline/PROVENANCE.md` with exact Buun/llama SHAs and remote URLs.
- Add a machine-readable `.wiretail/execution/baseline/reference.json` containing model path/source/SHA256,
  GGUF architecture and context metadata, GPU/driver/runtime, server build options, profile values,
  K/V and draft types, MTP sidecar identity, batch/ubatch, and benchmark harness SHA256.
- Record the fork’s ahead/behind relationship to both `origin` and `upstream`. Fetch first; never merge
  over local changes. If upstream advanced, stop and request a deliberate rebase/sync decision.
- Verify computed target/MTP bytes from actual metadata; report any disagreement with plan section 3.

## Checks

- Validate JSON with `jq -e .`.
- Record commands without exposing API keys or tokens.
- Confirm no model/config/service mutation occurred.

## Stop conditions

Block on missing model/sidecar, unreadable metadata, unknown source SHA, or upstream movement that
changes relevant VBR/MTP/KV files. Do not guess.
