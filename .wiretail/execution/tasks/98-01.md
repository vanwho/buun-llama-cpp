## Exact implementation sequence

1. Trace seal_ready_pages, host completion polling, promotion publication and clean victim removal. Verify canonical host bytes remain valid after promotion; host source ownership cannot be moved/freed just because residency changes.
2. Make pageable full-L canonical storage plus a bounded pinned slab/ring the default where the backend supports it. Reuse the existing host-provider/transfer abstractions; keep pin/allocation settings backend-configurable. Account canonical bytes, pinned staging bytes and transfer concurrency separately.
3. Capture sealed pages once per content version. Async D2H completion authenticates host_valid; clean eviction is only mapping drop and does not issue another D2H. Keep versions/checksums and stale completion handling intact.
4. Ensure prefill chunk N sealing overlaps chunk N+1 compute. Use transfer streams/events and bounded backpressure only when a slot cannot be safely reused; do not wait for every token or every layer.
5. Add targeted tests for promote->clean-evict->promote preserving host bytes, dirty victim rejection, stale completion and bounded slab exhaustion. Profile one small CUDA multi-page ingest with events enabled only for the test; report useful/actual D2H, duplicates avoided, overlap and peak pinned bytes. No long-context fill.
