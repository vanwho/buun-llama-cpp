# 101-04 — Parallel GDN prefill with an exact rollback-snapshot tail

Revision: `hotpath-v10-20260914`. Amendment: `gpu-execution-101-20260930`.
Cluster: `gpu101-recurrent-graphs`. Implementation/assessments: gpt-6-luna High.
Dependency: 101-03. Read SPEED101, TESTING and handoff101-03 only.

## Root and selected algorithm

gated_delta_net_cuda in ggml/src/ggml-cuda/gated_delta_net.cu loops serially
over n_tokens. Its optimized FLA cubin path rejects snapshot K>1, Ada cc890
and U256. Do not mislabel fused_gdn_ch as parallel or simply disable MTP
rollback. Start from the existing graph-based chunk algorithm in
src/models/delta-net-base.cpp::build_delta_net_chunking (CS64 for ordinary
GDN), which uses batched CUDA matrix operations and supports a padded tail.

For a long prompt with snapshot count K=n_rs_seq+1, split into a parallel
prefix of N-min(N,K) tokens and a short exact serial tail of min(N,K).
The tail writes the existing newest-first K snapshot slots. Concatenate
prefix/tail attention outputs in time order; keep all final and rollback
states on GPU. Ordinary decode and MTP verify retain their original path.

   on actual llm_graph_params/execution phase, not just N>1 (MTP verification
   also has N>1). Expose the minimum needed generic phase in graph params if
   absent. Choose the split only for prompt/ingest or query replay with
   N>=128 and a nontrivial parallel prefix, scalar-gate GDN, valid strides and
   a GPU-capable chunk graph. Keep current small/other-architecture behavior.
2. Create views of q/k/v/g/b over dimension2 using each tensor's actual
   nb[2]/nb[3], preserving GQA head counts. Prefix uses
   build_delta_net_chunking(...,s,...), not build_delta_net whose fused flag
   would select the same serial op. Pass the prefix final state as the tail
   ggml_gated_delta_net input with the original K. Its attention tail and
   newest-first state output follow the existing gdn_out layout. Write only
   the last min(N,K) states into ssm_states_all as before. N<=K uses existing
   code. Never zero untouched older slots or detach convolution history.
3. Account GQA: the current fused path can keep H_k!=H_v; the chunk builder
   expects compatible repeat/broadcast shapes. Reuse its established repeat
   logic, do not reinterpret strided keys as full H_v. Qwen's GDN L2 norm,
   gate exponential and epsilon must be identical. Test actual H_v/H_k ratio
   from the model, plus a simpler ratio1 fixture.
4. Ensure graph reserve/output sizing covers prefix+tail intermediate tensors;
   include this plan in graph structural keys. Query replay/checkpoint restore
   and MTP verify must select the correct graph slot without stale aliases.
   Preserve current GDN norm/output fusion where compatible; don't force
   offload of unsupported chunk ops to CPU. Audit op placement once using
   the existing 101-01 profiling summary.
5. CUDA fixture: same input state, N1/3/64/128/256 and N257, K1/3, compare every
   output and newest-first snapshot against existing serial CUDA baseline
   with documented numerical tolerance. Test partial acceptance restoring
   each tail snapshot and next decode vs serial one-pass. CPU is only a small
   state/math oracle, never live Qwen prefill.
6. Time serial vs split in the CUDA operation harness at actual model geometry
   Q256 and K3; include all graph/copy/scratch costs. Enable the split for
   shapes where it wins consistently; if existing chunk decomposition loses,
   retain serial production and implement the same chunk arithmetic as a
   CUDA backend path in this task or one explicit immediate successor. Do not
   claim a fast path merely because the token loop moved into more nodes.
   Retake one 4K representative row if GDN was a material timeline owner.
