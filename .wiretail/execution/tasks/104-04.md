## Precise arithmetic and API

1. Add GGML_OP_KV_PAGE_RERANK and ggml_kv_page_rerank API/op registrations
   parallel to104-03. Inputs: persistent transformed probes, existing resident
   K tensor, bounded staged cold K tensor, checked logical/physical/valid-row
   descriptors, generation identity, and caller-owned max/sum state. Output
   log_mass [candidate_pages,Qheads,valid_probes] for one layer. Tile when
   needed; never allocate logits [query_tokens,full_L]. CPU scalar oracle
   decodes tiny Turbo4 keys and mirrors exact math, not CPU Qwen inference.
2. Kernel computes actual dot products with dequantized represented K
   coefficients using existing centroid/norm definitions. Q has already been
   transformed with InnerQ scale by the probe producer. Match target FA
   attention scale and optional logit softcap; do not transform Q twice or
   undo RoPE/K positions. Derive GQA head mapping from Qheads/KVheads.
   Inspect fattn-common.cuh and active Turbo4 FA helpers for this exact math.
3. For each page/head/probe, stable streaming state is (m,s):
   m_new=max(m_old,m_chunk); s_new=exp(m_old-m_new)*s_old+
   exp(m_chunk-m_new)*s_chunk. log_mass=m+log(s). -inf/0 is empty. Only valid
   causal token rows contribute. Read all current resident history K directly
   on GPU for this once-per-turn comparison, plus shortlisted cold K; no
   transfer of resident K and no V read. Partial/padded rows cannot win.
4. Normalize log_mass over resident+shortlisted-cold candidates for each
   head/probe, then emit peak and mean probabilities using104-03's record
   format. Record this is exact within the candidate pool only. Per-head
   probabilities are comparable across layers; raw logits/ranks are not.

## Host source and asynchronous staging

Reuse canonical host page units: find the bundle page by exact identity,
then key-side logical_unit_id for the compact cache layer (current capture
uses layer_index*2). Verify row_bytes/type/content_version/valid_rows. Read
unit.bytes in contiguous chunks into two pinned slots, each<=4MiB. Never
load entire K/V bundles or call read/dequantize for each host token. Keep
the page holder alive until its copies complete and recheck versions.

Two matching GPU slots reuse encoded Turbo4 bytes (<=8MiB total). Events order
H2D -> key-reader kernel -> slot reusable. One compute owner/stream may enqueue
layers/chunks in order; no blocking host synchronize per layer/chunk. Reuse
the existing event-backed backend abstraction; do not commandeer a host worker
backend concurrently. If an extra lightweight CUDA backend/stream is needed,
create it once per owner and charge its actual allocations; no second model.
Fused dot/partial logsumexp reads encoded K in place; no page-sized F16 cache.
Probe/scratch/result lifetimes extend through the final event/readback.

Resident K scoring should tile keys/probes/heads for coalescing and reuse a
key tile across probes. A simple scalar GPU loop over every row/head is not
the requested implementation. Follow existing warp-reduction/kernel launch
patterns; generate compact max/sum reductions, not a giant attention matrix.
Do not alter prefill attention kernels, graph shapes or MTP codecs here.
