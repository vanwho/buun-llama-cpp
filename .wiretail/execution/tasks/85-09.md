# 85-09 — Repair paged Turbo4 addressing and MMA numerical correctness

Revision: `hotpath-v10-20260914`. Amendment: `repair85-20260921`.

Model: Luna High; first retry High. Read only selected context and symbols below.

## Outcome

Correct CUDA attention from the actual layer-major, page-major, row-interleaved
Turbo4 storage, for several KV groups and nonzero Q. Fix the three established
bugs before another long server run. MTP fallback removal belongs to85-12.

## Source map and exact changes

1. Read `llama_kv_cache::get_k/get_v` in `src/llama-kv-cache.cpp` (~14449),
   direct and exact-wave branches of `llm_graph_context::build_attn` in
   `src/llama-graph.cpp` (~4920–5045), and graph overload
   `ggml_cuda_flash_attn_ext_paged_turbo4(ctx, ggml_tensor*)` in
   `ggml/src/ggml-cuda/fattn.cu` (~2779). The wrapper assigns raw `nb[1]` to
   row stride, `nb[2]` to head stride and `nb[3]` to page stride.
   For both K/V and both direct/exact producers set:
   `raw.nb[1] = original.nb[2]` (complete multihead token row),
   `raw.nb[2] = original.nb[1]` (one encoded head),
   `raw.nb[3] = geometry.layer_{k,v}_page_bytes[layer_ordinal]`.
   Do not change the wrapper convention alone or retain misleading comments.
   Audit every producer by rg. Expected address is
   `layer_base + slot*page_bytes + row*row_bytes + kv_head*head_bytes`.
   For a D256/four-KV-head fixture with66-byte Turbo4 blocks: head_bytes132,
   row_bytes528, page_bytes135168. Compute these, never hardcode in runtime.
2. In `fattn-mma-turbo.cuh`, store the GQA ratio/global head base in
   `ggml_cuda_fattn_mma_paged_turbo4_policy`. `q_value` and `store_output`
   receive **group-local** head indices from
   `flash_attn_ext_f16_process_tile` in `fattn-mma-f16.cuh` (~1652/2188).
   Both must address `global_head = kv_head*gqa_ratio + local_head`.
   K/V `row_ptr` already uses KV head, not query head; don't multiply it by
   GQA. Check non-power-of-two GQA6 (24 Q heads /4 KV heads), including
   partial tiles. Existing outer query/head guards must remain intact.
3. Correct Q-domain handling in paged MMA dispatch (~2441 fattn.cu).
   It receives original Q but decodes transformed K. Reuse ordinary
   `k_turbo_fwht_forward` math/signs/active inverse-channel scales (~2915),
   not another Hadamard convention. Add a stride-aware variant/helper if
   needed: read query/head byte strides; each128-coordinate block produces
   contiguous transformed Q. Launch once per Q tensor on the compute stream
   before MMA and pass transformed pointer/strides only to MMA. Cooperative/
   reference kernels already rotate Q and must not get rotated twice.
   Reuse backend-owned grow-only Q scratch; reserve admitted U capacity
   during warmup/reserve, never cudaMalloc/free inside capture. Factor/forward
   declare the existing helper if declaration order requires it. V stays
   transformed until existing graph output unrotation.
4. Verify graph output domain against `build_attn_v_unrotate`. Compare after
   exactly one V inverse transform, with same scale, encoded bytes and native
   causal positions. No tolerance widening to conceal bad head/order/transform.

## Regression fixture — required proof

Extend `tests/test-cuda-fattn-paged-turbo4.cu`, not a timing-only script:

- Add fast-path numerical cases with **24 query heads/4 KV heads**, D256,
  nonzero distinct Q/K/V per head, three physical pages, shuffled slot IDs,
  257/513-row partial tail and native gaps. Use **production interleaved
  rows**, not just the existing artificial head-major allocation.
- Exercise Q1/2/3/16/17/64/128 in a compact fixture table. Only multiquery
  shapes enter MMA at this step; existing cooperative short-query parity
  still required. No page_mass/split scratch in the actual MMA case. A
  test-only kernel-selection hook must prevent silent fallback. Timing-only
  cases do not count as numerical testing.
- Initialize output to NaN/canaries: every valid query/head/coordinate must
  be written and finite, including last KV group. Distinct V per group catches
  output overlap; nonzero Q catches missing WHT. Poison invalid padding too.
- Add a query with no causally valid rows and a padded GQA/query tile. Return
  neutral zero output/zero softmax mass rather than divide by zero; never
  mask NaNs in valid data to make it pass. Verify invalid-row poison cannot
  leak through a nominal zero attention weight.
- Compare to existing selected-byte CPU reference and same-page dense Turbo4
  oracle with justified existing tolerance. Test graph op wiring/descriptors
  as well as raw params; share a storage-view helper if needed so manually
  correct fixture params cannot mask a broken graph producer.
- CUDA graph warmup/capture/replay twice with changed active counts/tail and
  stable capacity. On the tiny multihead case use compute-sanitizer memcheck
  if installed, never the27B model or a large timing loop.
- Release checks remain active (`tests/CMakeLists.txt` already uses
  `-UNDEBUG`). Demonstrate each regression detects its original defect via
  isolated test controls, then remove negative controls from production.
