## Ordered implementation / experiment

1. Trace where the final chat request is rendered. Reuse the model/server template and tokenizer API; establish one authority so prompts are not templated twice.

2. Replace guessed two-tokens-per-word limits with token-aware construction or binary search over padding. Count complete messages, specials, factual context, final question and generation/lookahead headroom; preserve fact spans and question text.

3. Separate configured capacity, resolved capacity, occupied prompt/history, requested output, MTP rows and target hot rows in manifest fields with units.

4. Add exact token preflight before requests; compare server usage afterward and reject discrepancies instead of silently truncating context or facts. Track actual offsets of inserted facts.

5. Patch both generic adapters and the site canonical path so no active benchmark still obtains its length from BENCH_CONTEXT_WORDS heuristics. Keep any legacy word option explicitly non-authoritative.

6. Reproduce the punctuation-heavy 53,797-versus-22,016 mistake locally and show a valid corrected request with the target tokenizer.

## Concrete execution recipe

Read `EXECUTION_COOKBOOK.md` sections C1/C2/C3/C4. These are shared context; reuse them within the cluster.

Define one pure fitting API in the existing benchmark contract module taking
complete messages, desired occupancy, generation reserve, and an injected
render-and-tokenize callable. It returns final messages, exact token IDs/count,
template/tokenizer identity and kept fact spans. Unit tests inject a deterministic
tokenizer; live tests use the target's real template/tokenizer. Token fitting
must terminate by reducing only padding, never facts or final question.

Test empty padding, an oversized mandatory prompt, unicode and punctuation,
tail 255/256/257, then the reported marker-heavy 22,016 overflow. Mandatory
content that cannot fit returns an explicit error before HTTP submission.
Route profile, soak and quality prompt builders through the same API. Preserve
a legacy word count only as a non-authoritative input hint.

Run the existing three Python test modules; one small live diagnostic compares
local token count to server usage. Export API signature, error classes and the
exact template/tokenization endpoint or offline equivalent used. Do not run
the six-point final speed curve to test this fitter.
