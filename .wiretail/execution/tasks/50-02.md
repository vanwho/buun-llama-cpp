# 50-02 — Make cadence skip work and rank candidates in parallel

Revision: `hotpath-v10-20260914`. Cluster: `50a-gpu-catalogue-v10`.
Model: Luna High; first retry High. Prerequisite:50-01.

## Source

`ggml/src/ggml-cuda/kv-page-select.cu::{page_select_scores,page_select_rank,
page_select_eligible}`, existing CUDA argsort/top-k utilities, and
`src/llama-kv-cache.cpp` updates of `pager_query_generation_` and
`pager_query_refresh_enabled_`. Follow actual accepted target frontier through
native-MTP commit/rollback owner; query generation and accepted token count
are different concepts. Read49-04 handoff only through current task context
if necessary; its invariants are also in OVERVIEW and code tests.

## Implementation

1. Separate accepted-target-token refresh watermark from submission ID. First
   request, committed page crossing, explicit valid focus refresh and >=8 new
   accepted target tokens schedule work. Reject/cancel does not advance this
   watermark by draft proposals. Each submitted snapshot gets a unique ID;
   pending previous snapshot remains usable. Make cadence configurable using
   existing policy/config surface, not a server-specific environment hack.
2. Entire score kernel skips immediately when refresh=false; initialize output
   validity/generation so previous IDs cannot be mistaken for new work. On a
   refresh, reject invalid/causally future/summary-stale pages before expensive
   dot loops. For eligibility counts distinguish resident and cold; finite
   Q/bounds required. Control-scalar access must not force CPU/GPU sync.
3. Replace repeated rank scans and previous-winner search with existing CUDA
   sort/top-k building blocks. Preferred implementation: per-page parallel
   fp32 scores, stable64-bit sortable key (descending finite score in upper
  32bits, ascending logical page ID in lower32), two independently masked
   resident/cold partitions, preallocated CUB radix-sort temporary space or
   equivalent repository GPU top-k. No new external dependency. Mark invalid
   keys at the end; emit bounded resident and cold counts with explicit layout
   from49-04. Verify signed-float ordering, infinities/NaNs and ties in tests.
4. Scratch capacity allocated with catalogue owner and reused; no cudaMalloc,
   host std::sort(allpages) or full tensor readback every token. Cold top-k is
   small, but resident top-k can grow with A; avoid O(P*K*K) winner exclusion.
   Keep actual summary-score definition unchanged in this optimization.
5. Optionally avoid graph routing nodes on no-refresh only if it preserves
   graph reuse; normally stable graph+device-side skip is preferable. Trace
   disabled/active costs independently. No instrumentation-induced extra FA.

## Tests

CUDA/reference ordering for P32/128/512/1024, K0/1/2/16 and legal A-derived
sizes, both partitions, equal/negative scores, invalid floats, causal bounds
and no candidates. Test refresh false produces no new mailbox result and no
catalogue upload; accepted token batches1/2/3/64 advance watermark correctly;
rejected MTP rows do not. Run49-06 chain and two-slot graph replay.

Record sampled score/rank time and launched expensive-work counters at all
four page capacities, plus one same-input C6144 append trace. No-score
invocations must not perform a full page dot loop. Report cheap graph launch
overhead honestly; do not assert total GPU time zero.
