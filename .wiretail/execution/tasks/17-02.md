# 17-02 — Complete pager and native-MTP telemetry export

## Objective

Make the live `/metrics` contract describe the runtime that actually executed.
The current adapter requires `queue_us`, while the server omits the underlying
publish-time metric; `mtp_backend` also remains `not_present` because the
snapshot default is never populated from native MTP.

## Read

- Cluster `17a-harness-contract`, handoff 17-01, `src/llama-context.h/.cpp`,
  `tools/server/server-context.cpp`, `server-task.cpp`, and the adapter/parser.
- Existing metrics and lifecycle regression tests plus repository
  `CONTRIBUTING.md`.

## Work

1. Export every field required by the pager evidence schema, including
   publish/queue time, transfer timing, waits, bytes, page counts, epochs,
   and host/device residency.
2. Populate MTP backend/placement from the actual native draft context and
   retain Turbo4 K/V and GPU placement as explicit evidence. Never infer a
   successful placement from a command-line flag alone.
3. Keep absent or unsupported fields distinguishable from numeric zero and
   preserve fail-closed behavior for incomplete acceptance evidence.
4. Align Prometheus names, JSON names, adapter mapping, and contract validation;
   document the portable schema.
5. Add focused existing-test coverage for all identity gauges and timing fields,
   including an MTP-enabled snapshot and a disabled/unsupported snapshot.

## Acceptance

Build the server and run focused metrics/attention/pager tests. Scrape an
authenticated live candidate when available and show `queue_us` and a real
MTP backend value. A deterministic test may prove serialization but cannot be
called model-backed acceptance.

## Deliverable

Create `handoffs/17-02.md`, source/tests/docs changes, and raw metrics samples
with no secrets or machine-specific paths.
