# 25-09 — Specialize paged decoding and MTP verification for GPU throughput

Scope revision: speed-first-20260911. Recommended model: Luna High.
Phase 25; cluster `25d-decode-routing`; depends on `25-08`.

## Objective / hypothesis

Decode and native-MTP verify are not large-query prefill. Remove fixed
64-query resource costs and saturate the GPU without paying excessive split
and merge overhead. Select the fastest proven Turbo4 route per query shape.

## Source anchors

ggml/src/ggml-cuda/fattn.cu paged query/split-KV merge and dense Turbo dispatch;
fattn-paged-turbo4.cuh; attention-op scratch planning; tests/test-cuda-fattn-paged-turbo4.cu.
Read 25-04/05 winning-route table and 25-08 pressure case.

## Implementation recipe

1. Specialize resources for actual query count/buckets1,2,4,8, rather than
   reserving 64*256 floats for a one-token call. Query count may be n_draft+1
   at verification; preserve unsupported-shape fallback.
2. Cache device properties/kernel function attributes outside launches.
   Split selected KV across enough CTAs for current SM count and grouped
   query count, but amortize partial-state merge. Preallocate a bounded
   scratch pool; never allocate/zero logical-context-sized temporary state.
3. Reuse one decoded K/V tile across query heads sharing a KV head when
   occupancy/register pressure permits. Compare SIMT split-KV with mature
   Turbo/MMA grouping; do not assume Tensor Cores win batch1 or deep splitting
   wins a tiny selected set.
4. On pages fixed between tokens, reuse packed view or page table directly.
   Fuse permissible scale/WHT/mean handling once, preserve output domain and
   mask. Page-mass collection off for initial timing; its sampled version is
   integrated later.
5. Microbench q=1,2,3,5 at two KV working sizes (e.g.4K and16K) and one
   permutation; CUDA repetitions cheap, stop exploring a losing family.
   Report kernel + merge + pack time, bandwidth and shared/register usage.
6. One short server pressure request with MTP n-max 2 and the winning path,
   accepted tok/s/latency vs pre-task bundle. If packed dense beats direct,
   ship dispatch to it for those shapes rather than claiming an abstract
   “direct” preference improves speed.
