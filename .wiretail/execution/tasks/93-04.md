# 93-04 — Verify MTP acceptance and cold-page behavior quickly

Revision: `mtp-diagnostic-v10-20260922`. Amendment: `repair93-mtp-fast-20260922`.

Cluster: `repair93-mtp-diagnostics-v10`.

## Objective

Run the smallest useful post-repair verification and separate MTP acceptance
from page-promotion correctness and from throughput.

## Work

1. Repeat the three short controls from `93-01` with the repaired binary. Use
   identical prompts, seed, sampler, context, batch/ubatch, draft n-max, and
   output limit so acceptance is paired rather than compared across unrelated
   requests.
2. Require the dense MTP control and selected/all-pages-resident MTP case to
   report request-level acceptance. Report accepted draft tokens divided by
   actual verification denominator; do not use `accepted_target_tokens` as the
   denominator.
3. Run exactly one tiny-hot-set promotion case: ingest two short labeled
   documents, make the hot budget fit only one document, query the second, then
   query the first again. Record immutable page IDs, H2D completion/publication,
   target consumption, draft consumption, faults, and acceptance for each
   request. Stop after the required transitions; do not use a long context.
4. If dense MTP is high but paged resident MTP is low, mark the paging repair
   incomplete. If both are high but promotion is low, mark only promotion
   incomplete. If all are high, retain the evidence as the first valid MTP
   acceptance proof and do not infer large-context performance.

## Acceptance

The result contains paired acceptance percentages, route/placement identity,
and a separate promotion verdict. It must finish within a bounded runtime and
must not use the selected-reference route for a production claim.

## Deliverable

Create `handoffs/93-04.md`, `evidence/V10_93-04.json/.md`, and raw request,
metrics, and server-log files.
