# 92-01 — Make automatic attention dispatch fast-route-only

Revision: `hotpath-v10-20260914`. Amendment: `repair92-20260922`.
Cluster: `92a-route-policy-v10`.

## Objective

Remove the early implementation's silent `selected_reference` production
fallback. Automatic selective paging must always use the fastest eligible
GPU-native consumer for the actual selected view, especially Turbo4/Turbo4
Qwen3.8 and ordinary supported quantized K/V. If no GPU-native consumer is
eligible, fail closed with a machine-readable refusal and a precise reason;
never hide the problem with a generic gather/dequant/reference graph or CPU
attention. Keep the reference route only for explicit diagnostics and exact
parity until the final goal review has accepted the fast path.

## Implementation contract

1. Preserve the existing explicit controls. `--kv-pager off` remains dense;
   `observe` remains observational; `exact` may use the exact reference oracle
   when its contract requires it; and
   `LLAMA_KV_ATTENTION_ROUTE=reference` remains an explicit diagnostic
   override. Do not remove the oracle in this task.
2. Make automatic `selective` route selection an explicit ordered fast-path
   follow this truth table rather than a generic fallback chain:

   | selected physical view | K/V family | automatic route |
   | --- | --- | --- |
   | genuinely contiguous, device-resident, bounded selected rows | Turbo4 or a supported standard quant | mature `selected_dense` Flash Attention |
   | non-contiguous page table, supported causal Turbo4/Turbo4 geometry | Turbo4 | fused `selected_direct` paged CUDA attention |
   | direct-ineligible but device-resident packed cache with bounded charged copies | supported family | `selected_packed` only when its capability contract marks it eligible |
   | anything else | any | typed `refusal`, never `selected_reference` |

   Do not materialize a non-contiguous selection merely to make dense look
   eligible, and do not call packed a fast path when it copies through host or
   allocates full-L F16. The direct checks must include backend, causal mask,
   transformed K/V types, head dimensions, GQA mapping, page
   identity/generation, query tile and scratch reservation. Preserve native
   MTP direct/packed eligibility and do not route MTP verification through
   reference.
3. Do not hard-code a universal query-token cap merely to avoid implementing
   the prefill tile. Use the existing query-tile/chunk planner and the CUDA
   launch limits. If a shape is not yet safe, return `refusal` with a reason
   naming the phase, query tile, backend, K/V types, and missing capability;
   schedule a separate kernel expansion rather than falling back.
4. Change the final automatic branch in `planned_route()` from silent
   `selected_reference` to typed refusal (or an equivalent fast-route result
   only if the preceding capability check proves it). Add a distinct metric or
   reason counter for `automatic_reference_prevented`/unsupported automatic
   route so live telemetry cannot mistake an oracle route for a speed result.
   Keep explicit-reference counters separate.
5. Make standard quantized K/V behavior generic: if the mature GPU dense
   Flash-Attention backend supports the type and selected rows are contiguous,
   use it; if not, refuse instead of CPU dequantization. Turbo4 must prefer the
   fused direct/packed GPU consumer and must never allocate full-L F16 K/V as a
   fallback. Do not change canonical host Turbo4 backing or native-MTP GPU
   residency.
6. Update comments at the enum, `planned_route()`, `prepare()` and selected
   graph construction to say `selected_reference` is a diagnostic correctness
   oracle, not production fallback. Update root `README.md` and
   `tools/server/README.md` with the same policy and explain that reference
   timings are invalid performance evidence. Keep all server paths/secrets out
   of portable code.

## Tests and evidence

- Extend `tests/test-kv-attention-execution.cpp` so automatic direct, automatic
  dense, and supported automatic packed cases remain accepted; an otherwise
  valid but unsupported selected view returns `refusal`, while explicit
  `reference` still returns `selected_reference`.
- Add/adjust a test for standard quantized contiguous dense selection and a
  Turbo4 multi-query prefill shape. Assert route and reason/counter, not just
  process success. Update any old assertion that expected automatic reference.
- Build and run the focused CPU test and the CUDA execution/pager tests. Run a
  tiny live CUDA smoke only after the deterministic tests pass; verify metrics
  show no automatic `selected_reference`, and that explicit reference remains
  observable for the parity control. Do not run a long context benchmark here.
- Write `handoffs/92-01.md` and
  `evidence/V10_92-01_ROUTE_POLICY.json/.md` containing changed symbols,
  route truth table, test commands/results, refusal reason, and explicit-oracle
  proof. Do not claim speed improvement until a later benchmark task measures
  it.

## Acceptance

The focused tests pass; automatic selective dispatch has no path to
`selected_reference`; unsupported automatic shapes fail closed with telemetry;
Turbo4 and supported standard quantized GPU routes are selected without CPU or
full-L staging; explicit reference parity remains available; documentation and
comments agree with the code; and the receipt validates with:

`python3 .wiretail/execution/v10/validate.py --task 92-01 --receipt .wiretail/execution/evidence/V10_92-01.json`

a test-only oracle is a later task after direct/packed parity and goal
