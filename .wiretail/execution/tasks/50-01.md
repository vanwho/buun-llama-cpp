# 50-01 — Replace CPU page summaries with a persistent incremental GPU catalogue

Revision: `hotpath-v10-20260914`. Cluster: `50a-gpu-catalogue-v10`.
Model: Luna High; first retry High. Prerequisite:49-06.

## Exact cost to remove

`src/llama-kv-cache.cpp::pager_routing_summary_build()` loops stored rows on
CPU, decodes all KV heads repeatedly for each requested head and can call
`ggml_backend_tensor_get`. `src/llama-kv-pager.cpp::seal_ready_pages()` invokes
it at a global boundary. Catalogue/index interfaces are in
`src/llama-kv-routing-summary.h/.cpp`. `set_kv_page_select_inputs()` uploads entire bounds
arrays; `can_reuse_kv_page_select()` grows shape with inventory. The intended
GPU catalogue has not been realized efficiently. Preserve49-03 math/49-06 proof.

## Implement, no new scheduler

1. In existing KV-cache routing owner allocate persistent GPU buffers per
   attention layer, capacity `ceil(L/page_tokens)` logical IDs per sequence:
   min/max[D,KV_heads,page_capacity], extent/version/generation/ready metadata,
   residency membership and selector output. Check all multiplication overflow,
   actual layer/head geometry and budget before allocation. Stable logical
   page addressing avoids reallocation as C grows; include catalogue bytes
   in resolved ledger. Don't pin the whole L-sized host pool unnecessarily.
2. Add a compact internal GPU summary op/kernel alongside KV_PAGE_SELECT,
   wiring ggml declaration/op enum/shape validation, backend dispatch and
   tests using repository conventions. Input is actual Turbo4 K bytes from
   completed page writes, mapping and authoritative valid extent; output is
   the existing persistent catalogue owner. Do not put an unowned raw pointer
   in serialized op params. Dependencies and tensor/backend ownership must be
   visible to scheduler/graph lifetime machinery.
3. Kernel parallelizes by page/head/coefficient tiles; decode each stored row
   once per tile from packed Turbo4 codes plus norm to coefficient domain,
   reduce min/max for valid rows only. Reuse the actual codebook/calibration
   identity from49-03. No inverse FWHT to original K is required for bounds.
   Store conservative outward-rounded fp16 bounds; fp32 reference tests.
4. Update a newly committed sealed page once, directly from resident K on GPU
   before its slot can be reused. Order after real SET_ROWS writes with graph
   dependency/events; keep slot leased until summary and canonical D2H are
   complete. Never summarize rejected speculative lanes as committed history.
   Mutable tail stays mandatory/pinned and not a cold candidate. Invalidate
   dirty range on rollback, context erase, restore or content version change.
5. Host canonical copy may complete independently of GPU summary; eligibility
   requires both authoritative bytes and matching ready summary. Eviction
   does not delete its GPU summary. Context reset invalidates versions without
   clearing full arrays per token. Restoring a checkpoint can perform a
   bounded one-time GPU rebuild; no per-token CPU fallback.
6. `set_kv_page_select_inputs()` becomes small changed-range metadata updates
   plus Q/query-position parameters, not std::vector of allhistory bounds.
   `can_reuse_kv_page_select()` keys allocated capacity/shape/backend, not
   current number of pages or content version. Refresh=false uploads neither
   catalogue nor unchanged membership. Retain CPU summary builder only for
   explicit reference/unsupported-backend tests, not selective CUDA runtime.

## Required tests and measurement

Run49-03 coefficient/bound tests and49-06 promotion chain against the new
producer. Add GPU-vs-CPU summary parity over random Turbo4 rows, tails, GQA,
nontrivial calibration, rollback/restore and same logical page reused by a
new sequence. Assert no full catalogue upload on unchanged input; one sealed
page updates only its own slice; cold summaries survive eviction; graph owner
addresses stay stable across C growth. Test multiple CUDA graph replays.

Measure one C6144 fill and one128-token cached append with diagnostic traces,
same bundle/settings before/after. Record CPU summary decode calls/time,
catalogue H2D bytes, sealed-page GPU time, graph rebuild count and pp/append
rates. CPU host-summary decode calls must be zero in the repaired CUDA live
path. Timing need not meet an invented speed gate, but unexplained regressions
must be investigated before building on it.
