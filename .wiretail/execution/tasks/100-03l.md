Revision: `hotpath-v10-20260914`. Amendment: `post100-hotpath-20260930`.
Cluster: `forward100-final`. Model and assessments: `gpt-6-luna`, High.
Dependency: `100-03k`. This is the single measured remediation required before

## Measured finding

100-03k's direct prompt-batch timing was 185 ms across 4326 prompt tokens,
including 161 ms in three retained checkpoint captures. Prompt-marked
`llama_decode` calls took 20.098 s of the 20.394 s fresh-prefill interval;
the separately exposed explicit server wait was 4 us. API wall time may include
backend computation and internal synchronization, so this evidence does not
identify which internal cost dominates.

## Focused implementation and verification

1. Trace the prompt path from `llama_context::decode` through the backend graph
   execution boundary. Add request-local instrumentation that separates host
   preparation, backend submission, backend completion/internal wait, and any
   retained state work without introducing synchronization beyond what the
   existing synchronous decode contract requires.
2. Based on that attribution, make one source-owner-specific optimization in
   the measured dominant component. Preserve prompt results, cancellation,
   MTP rollback/promotion, pager admission, and the 100-03k selected route and
   configuration.
3. Add one deterministic regression assertion to the closest existing fixture.
   Build and run that fixture.
4. Build an immutable candidate and run exactly one canonical selected
   prompt-2 retake: one 40-token warmup and one 400-token measured request,
   same frozen prefix, L8192/H4096, page256, B1024/U256, selected GPU Turbo4,
   native full-L GPU Turbo4 MTP nmax2, reasoning off, temperature0, and fresh
   slot. Record direct stage timing, request/response, MTP counters, candidate,
   model and prefix hashes, and adapter health.
5. Classify the single row against the unchanged 500 tok/s floor. Do not claim a
   speed pass from instrumentation or fixture results.
