## Code diagnosis and prescribed decisions

1. At the first target/draft disagreement in common/speculative.cpp native MTP
   owner, capture bounded top8 logits/probabilities, proposal token, position,
   target actual causal rows, draft valid frontier and staged hidden/carry
   generation. Diagnostics are opt-in and capped to the first rejection per
   request; no host full-logit dump per token. Compare target finite logits
   with the CUDA mask fixture, then samplers/accounting. A non-finite target
   is an execution bug, not sparse quality loss. Correct its mask/loader owner.
2. If selected all-resident differs from pager-off with identical tokens/KV,
   repair the earliest mismatching encoded row, native position, mean/rotation,
   target final hidden, draft conditioning, or recurrent checkpoint. Use the
   same exact input state in a small CUDA regression. Never accept a drafted
   token the target rejects or alter the acceptance denominator to meet goals.
3. If all-resident is sound but C>H low, determine whether replay carry/frontier
   is sound before declaring inherent sparse/full-draft distribution mismatch.
   Compare one fixed proposal's target selected logits and draft logits under
   identical frozen native positions. Save the typed finding, not a guess.
4. For demonstrated full-draft-versus-selected-target mismatch, implement an
   **attention-view** follower option, not draft storage paging. Draft retains
   every L Turbo4 row on GPU. At the target's final history publication, bind
   the same logical historical page IDs plus its live causal query/output
   suffix to draft attention. Reuse operator metadata/native position masks
   and proven direct/packed consumers for the MTP layer; do not attend/dequant
   all L rows and mask afterwards. Expose a generic full|target-view policy
   with full unchanged for pager-off/unsupported architectures.
5. A draft-view snapshot is versioned by target history generation and session,
   not every speculative token. Draft's own tentative row positions still
   follow its full cache and causal mask; reject/rollback trims provisional
   suffix only. Checkpoint/replay restores the published-view reference plus
   carry; no extra historical H2D or missing draft cache rows. Full cache
   allocation and bounded view workspace are separate ledger leaves.
6. If follower is required, time paired full vs target-view draft on one
   <=80-output row and assert finite logits/valid frontier on both. Enable
   target-view automatically only for a supported selected architecture when
   acceptance **and net decode** improve. Otherwise retain full and insert
   one specific measured successor before final release. Sparse attention
   cannot guarantee dense-equivalent quality or the historical percentages;
   genuine residual disagreement is reported, never labeled a state pass.
