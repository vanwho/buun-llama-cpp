# Phase 93-05 MTP diagnosis

## Scope

This review uses only the compact 93-01 through 93-04 receipts and the raw
93-04 short-control hashes. It does not reopen historical frontier campaigns.

| Automatic fast-native route | not proven | Selection occurred, but a completed selected request and its target/draft consumption telemetry are absent. |

## Diagnosis

The dense control proves the 93-03 logical-prefix repair and native MTP
placement/acceptance. The selected route reaches the prompt trim seam in
`tools/server/server-context.cpp`, where the live or transient suffix removal
returns false for the Turbo4/paged memory. The mandatory full-reset fallback
then crashes instead of producing a coherent cold retry. The promotion probe
fails at the same selected request boundary, so it cannot distinguish page
selection from usable promotion.

This is a concrete selected trim/recovery defect. It is not permission to
interpret allocation, page selection, a partial HTTP record, or a process
restart as promotion success.

## Decision

Keep the short-control goal unmet. Do not schedule 256K or speed work. The
ordered remediation and verification chain is `93-06`, `93-07`, `93-08`, then
`93-09`.
