# V10 256K feasibility findings

The 51-03 scale prerequisite passed, so this task ran a receipt-backed
L262144 startup and a bounded first-request probe with the measured ledger
configuration. B/U was 128/128, then U=64 was tested as the next ladder step;
target and native MTP draft K/V remained Turbo4 on GPU throughout.

## Result

L262144 startup is feasible: the candidate reserved 262144 native draft rows,
276,955,136 bytes, and reported the model loaded. Occupancy is not feasible
with this candidate/profile at the tested resource points. H=30208/U=128
failed on the first request when VBR f16 dequant scratch attempted to grow to
512 MiB. Reducing H to 16384/U=128 failed on an 8.25 MiB packed selected
attention allocation and exposed a pending-pager-writes cleanup assertion.
Reducing U to 64 kept L and H unchanged but failed with CUDA out-of-memory
while configuring dynamic shared memory for `launch_mul_mat_q`.

All three attempts therefore have max observed C=0, zero generated tokens,
no measured speed, no physical-promotion proof, and no full-occupancy proof.
The full-L draft reservation is distinct from request-path feasibility. The
next bottleneck is the CUDA VBR scratch / packed-attention / kernel resource
reserve path, not model loading or a claimed context limit.

The tuning ledger had 16,206,500,000 charged bytes against 16,720,200,000
usable bytes and 201,327,000 bytes headroom at the earlier 77,824-row draft
coordinate. The 262,144-row draft reservation adds 194,641,936 bytes before
the failing request-time scratch. These are ledger calculations and startup
observations; missing live A and peak allocation fields are not inferred.

No reduced-L run, full C262144 run, speed curve, quality claim, or promotion
claim is substituted for the failed L262144 request path.

## Deferred verification

Full occupancy, quality/soak, original-prompt speed intervals, and physical
promotion remain deferred until the identified CUDA reserve/allocation path is
repaired. No hardware or credential check was unavailable; the required GPU
startup and bounded failure ladder were executable.
