# 10-01 handoff — selected-all-pages reference attention in the live graph

## Outcome

The selective pager mode now reaches the real Qwen3.5/Qwen3.5-MOE graph. For
causal Turbo4 attention with one sequence, it snapshots the live pager table,
selects every resident logical page when the configured logical page count
`L` fits the admitted hot capacity `H`, preserves arbitrary page order and
tail lengths, and builds an immutable attention metadata/fence object.

The graph consumes only the selected rows through bounded `I32` row IDs and
`ggml_get_rows` K/V gathers. The gather output is F32 and is converted by the
existing attention path as needed; there is no full-context F16 gather. Native
logical positions remain in the metadata and drive the selected causal mask.
The ordinary dense path is unchanged when the pager is off, and unsupported
selective shapes fail closed before graph submission.

## Exact live call chain

```text
llama_context::process_ubatch
  -> mctx->apply()
  -> prepare_kv_attention_graph
       -> pager.residency(sequence_id)
       -> llama_kv_attention_view::build(..., sequence_id)
       -> llama_kv_attention_operator_metadata::build
       -> llama_kv_cache_context::selected_attention_rows
       -> llama_context::prepare_kv_attention
  -> graph_params (route/table/content/representation/shape/metadata)
  -> model.build_graph
       -> qwen35 graph::build_inp_mem_hybrid / build_attn_inp_kv
       -> build_attn_inp_kv_impl
            -> selected I32 row-id input
            -> selected native-position causal mask
       -> llm_graph_context::build_attn
            -> compact ggml_get_rows(K)
            -> compact ggml_get_rows(V)
            -> existing build_attn_mha
            -> build_attn_v_unrotate(original Turbo4 V)
  -> scheduler allocation and graph compute
  -> llama_context::synchronize
       -> scheduler fence completion
       -> selected view fence release
```

Qwen3.5 hybrid input forwarding now calls the attention child's complete
`set_input`, so selected row IDs, masks, rotations, and meansub inputs share
the same binding path. The graph result and execution controller both retain
the immutable view until scheduler completion; route, table epoch, metadata
content key, representation epoch, and shape epoch participate in reuse.

## Dense/reference comparison

| Concern | Dense route | Selected reference route |
| --- | --- | --- |
| K/V source | Existing cache view over the dense physical rows | Same source, but only selected cache rows are gathered |
| Attention dimension | Existing `get_n_kv()` view | `metadata.get_n_kv()` from all selected pages |
| Ordering | Cache row order | Pager-selected page order, including permutations and gaps |
| Positions/mask | Existing cache mask | Immutable native positions, valid mask, and causal query comparison |
| V inverse transform | Existing Turbo4 view | Original Turbo4 V retained for `build_attn_v_unrotate` |
| Allocation | Existing dense graph allocations | Additional F32 K/V gather scales with selected rows, not configured `C` |

## Allocation/accounting evidence

The selected path creates one I32 row-ID input and two bounded `ggml_get_rows`
outputs. The execution scratch record charges

```text
selected_rows * (head_dim_k + head_dim_v) * n_head_kv * sizeof(float)
```

and logs selected page count, selected rows, and bounded gather bytes. The
source cache view is a view only; no full-context F16 materialization is
introduced. The all-pages admission predicate explicitly refuses when
`logical_page_count > physical_page_count`.
