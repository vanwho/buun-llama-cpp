# 04-01 handoff

## Outcome

Added the internal experimental `llama_kv_routing_summary_store`. It builds a
version-1 summary for every valid page in a residency snapshot from already
rotated K rows, sampling four to eight evenly spaced representatives per page.
The representation is immutable after construction, upload-ready, and remains
separate from full KV payloads. `update()` is the page-seal/mutation rebuild
boundary; a new store can be published while older stores remain safe for
in-flight readers.

Every summary record carries the complete page identity, including page and
representation generations. Scoring validates both snapshot epoch and page
identity, scores all pages, reduces representatives with max dot product, and
returns deterministic top-K ordering (descending score, then logical page and
generation). Missing inputs, malformed rows, duplicate pages, stale snapshots,
empty/invalid pages, and budget overflow/refusal are typed outcomes.

The stored format is F32 by design for this measured reference path. The
accounting reports payload, identity metadata, logical, and allocation-rounded
charged bytes. It does not expose a public C API or select victims/move pages.

The deterministic fixture covers sealed and tail pages, representative
construction, a synthetic needle selecting a page, stable equal-score ties,
all-page count/comparison accounting, exact byte accounting, allocation
granularity/budget refusal, missing input, duplicate protection, invalid query
shape, and stale page-generation rejection across table-local epoch reuse.
For the three-page, four-representative, four-dimensional fixture the exact
summary accounting is 192 payload bytes + 288 identity-metadata bytes = 480
logical bytes, with measured score latency returned in `latency_us`.

## Deferred verification

No configured CUDA upload/scoring owner currently consumes this internal format.
GPU-resident allocation, CUDA all-page scoring, radix top-K suitability/latency,
F16 or lower-precision recall, and live Qwen3.8 layer/head summary production
are deferred to the device/integration and acceptance tasks. The local CPU
reference is deterministic and provides the bounded format, stale-generation
fence, synthetic cold-needle behavior, and accounting oracle required before
that boundary is added.
