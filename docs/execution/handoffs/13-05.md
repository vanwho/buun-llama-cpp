# 13-05 handoff — policy calibration and release candidate

## Outcome

Locked an explicit phase-13 release candidate in the existing policy and pager
configuration seams. Hot-page and recent-token capacity remain `auto`; the
runtime-admitted `H` is still the only source of target capacity. The policy
now applies deterministic normalized weights to EMA, recent peak, frequency,
and recency evidence, with a bounded hysteresis term. Small-capacity rounding,
mandatory-page subtraction, and minima behavior are documented in the
calibration artifact.

The candidate is `40/10/35/15` recent/structural/historical/transient, with
recent and transient minima of one page when capacity permits. The pager
defaults are summary top-K 8, exploration 2, telemetry every 4 tokens, and
prefetch depth 2. The complete candidate/corpus/binary hash is
`2497f112026c71f904ac115cded4dd290a42bfd52a18ba202dc7337e5f88276b`.

Model-backed quality and speed are not claimed. The current available controls
are off/all-GPU and the server has no configured selective pager route with
the required counters. The release candidate is therefore locked as the
phase-14 input while the live calibration gate remains explicitly deferred.

component ablations without reading or changing held-out answers.
