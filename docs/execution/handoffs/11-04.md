# 11-04 handoff — live dynamic policy publication

## Outcome

Added the backend-neutral `llama_kv_live_policy` boundary. It validates one
immutable residency snapshot against a complete logical-page inventory,
including host-only cold pages, maps full page identities to the existing
capacity-relative policy, and records one trace for the boundary. Retrieval
scores remain separate from retention scores in the exported decision log.

The controller inserts mandatory/current/recent/structural/pinned pages first,
requires an exact `min(H, L)` target when the inventory is complete, assigns
existing slots deterministically, and assigns promotions to the lowest
available slot. It validates transfer identity, epoch, and destination before
calling the transaction. Missing host source, unavailable inventory, stale
snapshots, and all-unobserved telemetry are explicit diagnostics; an invalid
or incomplete routing result is never partially consumed. A complete prior
target is reused as a safe fallback when summary or telemetry evidence is
unavailable and it still covers all mandatory pages.

The pager now exposes the composition through its pager-owned residency pool
and table. The residency transaction was also corrected to reserve reseal
transfers before victim drops and reserve H2D promotions after clean drops, so
a full pool can safely reuse an evicted slot while retaining rollback.

## Live decision examples

| Boundary | H/L | Evidence | Result |
| --- | ---: | --- | --- |
| warm current plus routed cold page | 2/3 | current page, valid summary score, host-clean cold page | target `[current, cold]`, one promotion, commit to next epoch |
| missing/stale summary with complete prior target | 2/3 | mandatory pages covered, no usable summary | prior target retained; no partial retrieval target is published |
| no telemetry with complete prior target | 2/3 | all attention observations unknown | prior target retained and marked safe fallback |
| malformed/stale transfer or table snapshot | runtime | identity/epoch mismatch | publication is refused; old table remains authoritative |
| transfer/event failure | runtime | backend failure after reservations | transaction rolls back claims, mappings, pins, and drops |

## Capacity reconciliation and invariants

- `H` is supplied by the runtime boundary and is clamped only by the physical
  pool capacity; the expected target is exactly `min(H, L)`.
- Policy ordinals are private bookkeeping only. Published records retain the
  complete `llama_kv_page_id`; sequence/page generations and table epochs are
  checked before publication.
- Duplicate logical identities, duplicate physical slots, missing inventory,
  bad host-only state, malformed transfer destinations, stale retrieval epoch,
  and non-finite retrieval scores fail closed.
- Decision records distinguish `added`, `kept`, and `victim`, while retaining
  the policy selection reason, retention score, and independent retrieval
  score.
- The immutable table changes only through the existing transaction publish
  linearization point. Failed transfers leave the prior snapshot unchanged.
- Promotion reservations now occur after clean victim drops; reseals still
  reserve and execute while their old mappings exist.

## Calibration metrics

The deterministic checkpoint exercised a three-page inventory at `H=2`, a
summary-selected cold promotion, stale snapshot refusal, and injected transfer
failure. The live result exposes target size, mandatory count, unavailable
attention count, retrieval fallback, per-page reasons/scores, transfer
counters, and published epoch for later calibration. No model-backed latency,
recall, attention-mass, churn, or overlap number is claimed here.
