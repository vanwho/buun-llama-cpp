# 09-01 handoff

## Outcome

Added the normalized experimental pager configuration and construction gate.
The default is `off`; it is a value object with typed `auto` states and no
backend handles or allocation. Common CLI and environment parsing is the sole
registration point, and the target context copies the object before any later
pager resources can be created.

## CLI/config surface

| Option | Environment | Normalized field |
| --- | --- | --- |
| `--kv-pager off|observe|selective|exact` | `LLAMA_KV_PAGER` | `mode` |
| `--kv-page-size N` | `LLAMA_KV_PAGE_SIZE` | `page_size` |
| `--kv-vram-budget SIZE\|auto` | `LLAMA_KV_VRAM_BUDGET` | typed byte budget |
| `--kv-host-budget SIZE\|auto` | `LLAMA_KV_HOST_BUDGET` | typed byte budget |
| `--kv-safety-headroom SIZE\|auto` | `LLAMA_KV_SAFETY_HEADROOM` | typed byte headroom |
| `--kv-pin-recent TOKENS\|auto` | `LLAMA_KV_PIN_RECENT` | typed count |
| `--kv-hotset-policy NAME` | `LLAMA_KV_HOTSET_POLICY` | `hotset_policy` |
| `--kv-hot-pages N\|auto` | `LLAMA_KV_HOT_PAGES` | typed optional cap |
| `--kv-router-top-k N` | `LLAMA_KV_ROUTER_TOP_K` | `router_top_k` |
| `--kv-router-explore N` | `LLAMA_KV_ROUTER_EXPLORE` | `router_explore` |
| `--kv-prefetch-depth N` | `LLAMA_KV_PREFETCH_DEPTH` | `prefetch_depth` |
| `--kv-pager-debug` | `LLAMA_KV_PAGER_DEBUG` | `debug` |

Sizes accept bytes and K/M/G with binary or decimal-style suffix spellings
already used by the repository (`K`, `KiB`, `M`, `MiB`, `G`, `GiB`, etc.).
Overflow, non-finite values, zero explicit sizes, negative counts, and
non-256-multiple page sizes are rejected. `hot_pages` is only an upper bound;
no hot count is defaulted.

## Capability matrix

`llama_kv_pager_evaluate_capability()` is a pure fail-closed result seam. It
reports exact reason codes for backend, model architecture, causal mode,
Turbo4 K/V, attention geometry, page geometry, one-device topology,
sequence/slot layout, host budget, MTP match, and conflicting VBR authority.
Feature-off returns `ok` without evaluating or probing any of those inputs.

## Downstream constructor entry point

`common_context_params_to_llama()` supplies the normalized object through the
experimental `llama_context_params::kv_pager_config` pointer. `llama_context`
copies and validates it at construction, logs normalized settings for enabled
modes, and refuses invalid configuration before pager allocation. No pager
storage, transfer, graph, or capability probe is performed by this task.
