# Handoff 05-02

## Outcome

Native MTP now reserves the target model's full trained context frontier during
auto-fit, independently of the target attention working-set size. The MTP
context contract preserves independent draft K/V placement, forces MTP
contexts to static storage with no VBR controller, requires Turbo4 K/V, and
rejects any realized MTP context whose cache bytes are not GPU-resident.

The realized allocation is logged with K/V types, logical rows, bytes,
bytes per token, backend, and the `mtp_gpu_reserved` budget category. The fit
path includes the full MTP reservation before target context reduction and
fails startup when native MTP fit cannot be proven. Actual Turbo4 row sizes
are accepted by the pure admission arithmetic and are covered at the 1,056
bytes/token and 264 MiB reference geometry.

## Deferred verification

CUDA allocation placement, target host-backed KV under MTP pressure, target
faults while MTP remains resident, allocator/VMM granularity, and full
Qwen3.8 262,144-token startup/teardown remain deferred. This environment has
no configured CUDA backend, reference GPU, or Qwen3.8 model checkpoint. The
hardware follow-up must verify the emitted MTP rows/bytes/backend log, inspect
the actual K/V tensor placement, exercise target page pressure and faults,
and confirm MTP teardown releases its independent allocation.

## Remaining risks

The local tests cover deterministic parameter, fit-contract, row-size, and
fail-closed arithmetic paths only. A model-backed CUDA run is still needed to
confirm that the selected target layer placement gives every native MTP KV
tensor a GPU buffer and that the measured allocation matches the expected
264 MiB payload before allocator overhead.
