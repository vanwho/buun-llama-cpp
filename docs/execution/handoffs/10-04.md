# 10-04 handoff — bounded Turbo4 prefill and decode transition

## Outcome

Prompt execution now keeps the live pager write frontier within the admitted
physical window. When selective or exact pager mode is active, the memory
batcher receives an effective prefill ubatch of at most
`H * page_tokens`; the configured `n_ubatch` remains the upper bound when it
already fits. The bound is derived from the runtime pager snapshot and never
from the logical context length.

Selected prefill uses the existing compact reference graph. It snapshots the
currently resident pages, preserves their native logical positions and causal
mask, gathers only those rows, and leaves the direct Turbo4 route decode-only.
The selected source view spans the admitted physical row window so high
physical slots remain valid gather indices; it does not materialize a full
logical-context F16 K/V buffer. A logical prompt may therefore cross `H` and
continue with the current resident window while completed pages are retained
by the canonical host seal path for later exact/policy work.

## Prefill state machine

```text
batch split (effective ubatch <= H*P)
  -> apply: reserve pager rows for this chunk
  -> graph: selected reference over current resident pages
  -> submit: complete/cancel row tickets atomically
  -> scheduler fence: finish async K/V writes
  -> host seal: authenticate complete Turbo4 pages and publish catalog entry
  -> next chunk or final fence
  -> decode: current partial tail remains GPU-authoritative; full pages are clean victims
```

Feature-off and observe modes retain the existing batch size and asynchronous
dense path. Selective mode uses the resident selected-reference path for
prefill and may use direct paged attention for qualified one-token decode.
Exact mode is bounded at ingestion but its all-page wave execution remains the
next task's route. A short tail is never sealed as a complete host page; it is
kept pinned and included in the first decode table. Graph/table fences are
released only after the scheduler completion boundary, so a changed table
between chunks cannot reuse stale graph inputs.

## Memory scaling and timings

The new prompt bound is `min(configured_n_ubatch, H * P)` rows in flight. The
selected gather scratch remains proportional to selected resident rows and
head geometry; graph reuse still rebuilds when table/content/representation/
shape epochs change. The live context logs `H`, logical page count, selected
pages, selected rows, and bounded gather bytes. No model-backed prompt
throughput, TTFT, page-seal time, VRAM high-water, or logits parity result was
recorded by the deterministic checks.
