# 09-05 handoff — real CUDA residency transfer boundary

## Outcome

Implemented the production ggml residency adapter for compact pager slots. A
configured pager now owns a bounded slot-tensor view adapter and residency pool
over its already-admitted backend buffer. The transfer executor selects the
real `ggml_backend_tensor_set_async`/`get_async` route for that adapter; the
callback route remains available only for deterministic fake/fault tests.

The adapter uses one storage tensor plus bounded per-slot views, owns mapping
state and fallback events, and drains outstanding events before teardown. The
host pager's H2D ring attaches to the D2H ring's direction-neutral core, so the
pinned staging capacity is not duplicated. Clean pool eviction drops a mapped
slot directly and performs no D2H. Existing transaction publication remains
the immutable table's atomic linearization point, with transfer rollback before
publication.

## Invariants/evidence

- Slot views are backed by one exact-size ggml allocation; per-slot offsets
  cannot cross the allocation boundary.
- Real tensor transfers use the backend/device-bound destination or source
  tensor and the bounded ring's backend event completion path.
- Slot mapping is reserved before H2D, and failed mapping/transfer/recheck
  rolls back the claim and releases mapped slots.
- Transfer counters report useful and aligned bytes, completion waits,
  backpressure, transfer time, stale completions, and map failures.
- Clean eviction does not invoke a transfer callback; the deterministic test
  verifies the mapped slot count reaches zero after the drop.
- The storage checkpoint is machine-readable at
  `docs/execution/evidence/09-05-storage-checkpoint.json`.
