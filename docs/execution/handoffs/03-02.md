# 03-02 handoff

## Outcome

Added `llama_kv_attention_operator_metadata` as the backend-neutral contract
for selected-page attention. It wraps the immutable compact view and exposes
the bounded page table, compact row count, native positions/mask, source
physical slots, native query positions, Turbo4 K/V types, K/V head dimensions,
GQA head counts, batch size, query-token count, and causal semantics.

The contract is fail-closed: selective mode requires non-empty validated page
metadata, 256-token page alignment, causal attention, Turbo4 K/V on both sides,
valid query-position cardinality, positive dimensions, and divisible GQA
(`n_head_q % n_head_kv == 0`). It rejects malformed source slots, native/page
identity mismatches, tails with inconsistent row counts, compact gaps, and
range overflow. Off mode returns a typed `disabled` result and adds no graph
operator or tensor.

Capability detection has typed results. CPU is identified as the deterministic
reference capability; CUDA, integrated GPU, accelerator, meta, and unknown/null
backends are explicitly unsupported and never reinterpret the metadata. The
table epoch is exposed as the metadata graph reuse/capture key and is now part
of `llm_graph_params::allow_reuse`.

## Deferred verification

No backend currently executes this selected-page metadata as a paged Turbo4
attention operator. CUDA/device verification is deferred because no configured
CUDA backend or target hardware is available here. Task 03-03 owns the later
Turbo4 paged flash-attention implementation; it must consume this contract and
prove device capability, tail masking, GQA, and graph-fence completion without
whole-cache dequantization.
