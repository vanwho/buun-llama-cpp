# 11-01 handoff — production routing summaries for sealed pages

## Outcome

Routing summaries now have a live owner. `llama_kv_pager` keeps an immutable
copy-on-write summary store, and `llama_kv_cache` supplies a representation-
specific sampler at the post-scheduler-fence seal boundary. The sampler reads
only four evenly spaced K rows from the configured runtime layer/head, decodes
those rows from Turbo4, and passes the already FWHT/position-treated K vectors
to the summary store. It does not reread a page on every decode token and does
not copy full K/V pages into summary storage.

The baseline is four-to-eight representative vectors per page. The bounded
calibration candidate is one centroid plus an L2 radius; its score is tagged as
an admissible dot-product upper bound. The form, layer, head, source rows,
source bytes, build time/count, invalidation count, and deterministic content
hash are accounted. All non-tail live pages must have a current summary before
the scorer returns results; missing metadata fails closed. The current partial
tail remains a structural responsibility for the policy layer.

## Ownership and lifecycle

- `llama_kv_cache::pager_routing_summary_build()` owns the Turbo4 decode and
  runtime layer/head selection. It runs only after the scheduler fence through
  `seal_kv_pager_pages()`.
- `llama_kv_pager::seal_ready_pages()` builds a summary before host publication,
  publishes the sealed host page, then atomically installs the summary against
  the resulting residency epoch. Summary failure rolls the page back and
  invalidates any host publication.
- `update_page()` replaces one logical page without rereading existing page
  payloads. `reconcile()` drops summaries whose full page identity no longer
  matches the published table. A write invalidates the touched logical page
  before payload publication; erase, clear, copy, keep, shift, and rewind are
  reconciled after their table transaction.
- Full identity includes session, sequence/page generations, logical/native
  range, model/topology, codec/codebook, rotation, mean-subtraction, and
  representation generations. The scorer checks both the table epoch and
  every identity, preventing stale restore/artifact data from being consumed.

## Summary formats and counters

`llama_kv_routing_summary_form::representatives` stores four-to-eight F32
rotated-K vectors. `centroid_upper_bound` stores one F32 centroid and one F32
radius per page. The summary accounting reports payload, identity metadata,
allocator-rounded charge, bounded source bytes/rows, build time/count,
invalidation count, and a deterministic FNV-style content hash. The pager
exposes this accounting and the immutable store to the next routing task.

The production default is four representatives from runtime layer 0, KV head
0, with vector dimension taken from admitted geometry. This is intentionally a
baseline for calibration, not a frozen quality choice. No context/page-count
allocation default is encoded.

## Remaining risks

The initial runtime candidate uses one layer/head and F32 vectors. 11-02 should
measure layer/head coverage, representative count, centroid bound usefulness,
top-page recall, score latency, and summary bytes on calibration data before
choosing a selective routing configuration. No candidate should be promoted
based on the synthetic fixture alone.
