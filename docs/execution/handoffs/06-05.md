# 06-05 handoff — exact page-wave reference

## Outcome

Implemented an explicit internal `exact` attention mode and a correctness-first
all-page wave reference. The online-softmax state keeps `(m,l,o)` unnormalized
until every resident and cold wave has merged. A deterministic bounded plan
validates logical page coverage, native position ranges, tails, resident
identity/slots, host backing, and separate cold staging. The executor supports
serial GPU callbacks first and a bounded two-slot double-buffer schedule after
that path is available; it never falls back to CPU Turbo4 attention.

The Turbo4 CUDA page decoder now exposes optional per-head partial output in
`[m,l,o[256]]` layout and supports partial-only launches without allocating a
normalized/full-cache F16 buffer.

## Deferred verification

- Full 256K Qwen3.8 exact execution with every host Turbo4 page streamed
  through the live transfer scheduler and per-layer CUDA graph is deferred;
  this worktree has no production pager graph/CLI wiring or model-backed exact
  telemetry endpoint.
- Dense-Turbo4-vs-exact model logits and the frozen selective-vs-exact
  `pager-corpus-v1` quality delta are deferred because 06-04 recorded that the
  current server has no live selective pager runtime or expected-answer stream.
- CUDA graph capture/reuse, live transfer fault injection, and raw full-context
  staging/latency evidence remain integration checks. The bounded CUDA
  partial-state and memcheck artifact is recorded in
  [`EXACT_REFERENCE.md`](../evidence/EXACT_REFERENCE.md).
- A CPU Turbo4 attention implementation remains intentionally absent; no CPU
  fallback was introduced.

## Remaining risks

The callback boundary proves the merge and coverage contracts and the CUDA
kernel can emit the required partial state, but a production graph must still
connect those callbacks to host-catalog page payloads, transfer events, query
positions/masks, and per-layer/head accumulation. No exact quality or
throughput claim is made from the bounded fixtures.
