# 10-03 — Prove decode graph epochs and record the first live speed checkpoint

## Objective

Harden table changes and CUDA graph reuse around direct paged decode, then quantify its overhead against
dense and selected-reference controls before dynamic selection.

## Read

- Task README, cluster `10a-live-decode`, plan sections 22 and 24.
- Handoffs 03-04, 09-05, 10-01, 10-02; baseline V2.
- Graph keys/capture allocator, scheduler completion callbacks, pager table publication/fences, benchmark
  harness and live metrics.

## Work

1. Test unchanged table reuse, page-order/content change, slot remap, representation/page/table generation,
   query shape, tail growth, and fallback-route change. Each required change rebuilds once; irrelevant
   controller metadata must not.
2. Attempt promotion/eviction while a graph consumes the old table; prove old pages remain pinned until
   completion and new table becomes visible only to later graphs.
3. Instrument graph capture/replay/rebuild counts, table upload bytes, descriptor preparation time,
   kernel time, total token time, scratch high-water, and waits.
4. Run small all-pages-fit dense, selected reference, and direct routes with identical prompts/outputs;
   at least five measured trials after warmup. Also run a bounded `H<L` manual selection for allocation
   and timing only, without a quality claim.
5. Profile and repair obvious regressions caused by per-token allocation, descriptor copy, or graph rebuild.

## Acceptance

All epoch/race tests pass; no use-after-unmap or stale graph occurs; unchanged tables reuse graphs; live
direct output matches reference; first checkpoint reports raw pp/tg/latency and accounts every major
overhead. This is not the final 3x gate.

## Deliverable

Create `handoffs/10-03.md` and `evidence/DECODE_CHECKPOINT.md/json` with route comparisons, raw paths,
graph/resource counters, bottlenecks, and next prefill requirements.
