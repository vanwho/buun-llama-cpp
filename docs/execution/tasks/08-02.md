# 08-02 — Make native MTP capacity follow the resolved target context

## Objective

Replace trained-frontier MTP sizing with the invariant `MTP rows == resolved target per-sequence context`
for every native-MTP run while retaining independent Turbo4 GPU placement and fail-closed accounting.

## Read

- Task README, cluster `08a-dynamic-contract`, plan 21.1 and D23.
- Handoffs 00-05, 01-03, 05-02, 08-01.
- `common/speculative.*`, `common/common.*`, `common/fit.*`, `tools/server/server-context.cpp`, cache budget,
  argument parser, MTP/server tests, and all callers of `common_speculative_mtp_context_params_resolve`.

## Implementation

1. Define one helper that accepts the resolved target context contract and returns native-MTP geometry.
   Never take `max(..., llama_model_n_ctx_train())` and never default to a numeric context constant.
2. Ensure both fit projection and realized construction consume the same resolved value. If target auto-fit
   changes the candidate, recompute target and MTP together before allocation.
3. For native MTP, omission of `-cd` means match target. Reject a nonmatching explicit `-cd` with a clear
   typed/error diagnostic. Preserve external draft-model `-cd` semantics.
4. Keep `--spec-draft-kv-device gpu` independent of target `--no-kv-offload`; require a usable GPU and
   verify every realized MTP context-memory buffer is non-host.
5. Require Turbo4/Turbo4 for native MTP under pager modes; keep ordinary non-pager compatibility where
   existing behavior requires it unless the current fork already globally requires Turbo4.
6. Account actual row bytes times resolved rows plus allocator overhead; log rows, bytes, bytes/token,
   device, context source, and budget category. MTP stays static and outside VBR/pager authority.
7. Update generated help/docs through the normal generator if parser text changes.

## Tests and live checkpoint

- Unit tests: `-c 0`, small, intermediate, odd/non-page multiple, maximum metadata context; explicit
  matching/mismatching `-cd`; `auto|gpu|cpu`; target CPU/GPU K/V; no GPU; external drafter unchanged;
  multiple slot/topology cases supported by current server.
- Fit tests prove MTP bytes scale linearly with the resolved value and target admission reserves them once.
- Build CPU parser/budget/server targets and Release CUDA server.
- Model-backed startup at three runtime contexts including maximum: inspect logs and memory breakdown;
  assert MTP rows equal target context, types are Turbo4, backend is GPU, and target `--no-kv-offload`
  does not drag MTP to host. Capture teardown memory.

## Acceptance

No production MTP context-size constant or trained-context floor remains. All tests and live startups pass;
a mismatched native `-cd` fails before partial context creation. Raw live logs are retained externally.

## Recovery

If target context is unresolved during fit, trace the final candidate through server fit and move geometry
resolution to the first point where it is authoritative; do not guess. If maximum startup lacks memory,
verify target KV is actually host/paged and account the failure before changing budgets.
