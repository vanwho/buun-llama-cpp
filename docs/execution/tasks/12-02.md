# 12-02 — Expose pager metrics/ledgers and bind the benchmark adapter

## Objective

Provide bounded, generation-consistent runtime telemetry and make every pager benchmark consume it
directly from the server.

## Read

- Task README, cluster `12a-operator-surface`, plan 24.
- Handoffs 06-03, 08-04–08-05, 10-03, 11-03–11-05, 12-01.
- Server metrics/schema/debug endpoints, benchmark adapter, `/srv/ai/benchmarks`, manifest validators.

## Implementation

1. Export gauges/counters listed in cluster context: context/logical/resident/host pages, detailed bytes,
   MTP placement, faults/prefetch/evictions/waits/transfers, attention/routing, generations, graph reuse,
   errors and teardown state.
2. Snapshot related fields under one epoch or include start/end generations so a scraper cannot combine
   incompatible states. Bound per-page debug output and keep prompts/attention matrices private.
3. Update generic benchmark adapter to collect pre/post/request-window telemetry, validate monotonic versus
   gauge fields, and calculate deltas/ratios without environment stand-ins.
4. Update server-specific `/srv/ai` runner/corpus glue as authorized, preserving unrelated changes and
   keeping raw outputs external.
5. Missing required telemetry makes pager runs invalid; legacy controls remain parseable and labeled.

## Tests and live smoke

Serialization/schema, concurrent scrape, epoch change, counter reset, absent pager/off mode, overflow,
redaction, adapter dry-run and malformed input. Run one request in each mode and verify manifest, raw
records, summary and server counters reconcile.

## Acceptance

No pager field is `not_configured` in a configured live run; MTP/context/hot/host/transfer evidence is
machine-verifiable; benchmark deltas match server snapshots; service restores.

## Deliverable

Create `handoffs/12-02.md`, schema docs and a live telemetry smoke summary with raw paths/hashes.
