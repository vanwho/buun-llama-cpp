# 13-01 — Establish reproducible live profiles and performance budgets

## Objective

Measure the release candidate by component, identify the dominant costs, and freeze microbenchmark shapes
and optimization budgets before changing kernels or transfers.

## Read

- Task README, cluster `13a-kernel-transfer-opt`, plan 24.
- Handoffs 08-05, 10-03–10-05, 11-03–12-03; live telemetry schema and raw baselines.
- CUDA profiling tools available on the host, kernel resource logs, benchmark harness.

## Work

1. Build/hash Release CUDA binaries with symbols/line information needed by the chosen profiler without
   changing optimization level.
2. Select representative calibration cases from live traces: all-pages-fit, warm `H<L`, cold promotion,
   focus shift, churn, odd tail, short/long prefill, and exact wave. Record selected rows/pages rather than
   embedding them as defaults.
3. Capture end-to-end CPU/GPU timelines and component timing: request/server, graph build/replay, descriptor
   preparation/upload, direct attention, mass reduction, policy/router, D2H/H2D, event waits, prefill seal,
   MTP and recurrent work.
4. Record occupancy, registers, shared/local memory, memory transactions, launch count, transfer bandwidth/
   overlap, CPU utilization, allocations and latency tails.
5. Produce a ranked bottleneck table and numeric budgets for 13-02–13-05. Identify at least three plausible
   optimization hypotheses with expected metric and regression test.

## Acceptance

At least five repeated measurements per checkpoint case are stable enough to rank costs; raw profiler and
benchmark files are preserved; every major token-time component is accounted or explicitly labeled
unattributed; no optimization is made in this task.

## Deliverable

Create `handoffs/13-01.md` and `evidence/PERFORMANCE_PROFILE.md/json` with commands, environment, shapes,
bottlenecks, budgets, hypotheses, and raw paths.
