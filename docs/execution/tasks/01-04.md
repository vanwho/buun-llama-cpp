# 01-04 — Implement pure retrieval and retention policy replay

## Objective

Implement deterministic, allocation-bounded policy logic before any live page movement.

## Read

- Task README; semantics doc; plan sections 8.6–8.7.
- `common/common-retention-sidecar.*`, `tools/server/server-cache-yield.*`,
  `src/llama-vbr-policy.h`, and prototype policy tests from the salvage matrix.

## Implementation

- Retrieval union: write page, recent pages, anchors, application pins, in-flight pins, summary top-K,
  and exploration pages.
- Retention state: attention EMA, retrieval hits, recency, dirty cost, age, pins, and hysteresis.
- Deterministic capacity reconciliation and victim ties.
- Never update a non-observed/cold page as though its attention were zero.
- Provide a bounded trace input/output format for offline replay; version it internally.

## Tests

Cover cold-needle recall, stable focus, abrupt focus shift, exploration, dirty victim penalty, all pinned,
capacity shrink/grow, identical-score ties, stale telemetry, and deterministic replay.

## Acceptance

- Pure CPU tests pass in an existing target.
- Hot-path data structures have explicit bounds.
- Policy constants are named/configured and no unexplained magic thresholds remain.
