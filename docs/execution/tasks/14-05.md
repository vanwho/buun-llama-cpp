# 14-05 — Run endurance, churn, concurrency, restore, and teardown acceptance

## Objective

Prove that the speed-qualified pager remains correct and bounded over prolonged real server operation and
destructive lifecycle events.

## Read

- Task README, cluster `14b-performance-soak`.
- Handoffs 11-05, 12-03, 14-01–14-04; server lifecycle metrics and fault corpus.

## Runs

1. Run a prolonged maximum-context conversation cycling warm focus, cold recall, competing focus, churn,
   speculative accept/reject and periodic checkpoints for a predeclared token/request duration.
2. Exercise request cancellation during prefill, D2H seal, H2D promotion, attention and exact waves;
   slot reuse; sequence copy/remove/keep/shift; prompt-cache adoption; checkpoint save/restore; clear;
   graceful shutdown; forced service restart; and repeated context creation.
3. If multi-slot pager support is enabled, run concurrent isolated sessions and prove no cross-session page,
   summary, MTP or generation publication. If not supported, verify startup refuses `-np > 1` clearly.
4. Sample host RSS/pinned bytes, catalog pages, CUDA allocations/mappings/events, VRAM categories, table/
   graph generations, stale drops, faults, waits, errors and throughput over time.
5. Confirm no monotonic resource growth, stale/corrupt output, lost host page, MTP CPU migration, deadlock,
   crash, restore mismatch or unrecovered allocation.
6. Restore the starting profile and health endpoints; preserve full logs and failure timeline.

## Acceptance

The predeclared soak completes with correct scored outputs, bounded resources, valid lifecycle state and
successful restore. Any leak/deadlock/corruption is fixed and the full affected soak rerun. Cannot defer.

## Deliverable

Create `handoffs/14-05.md`, `evidence/SOAK_ACCEPTANCE_V2.md/json`, resource time series, raw logs, health
proof and final phase-14 acceptance summary.
