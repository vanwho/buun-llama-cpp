# 05-02 — Pin full-context Turbo4 MTP KV in VRAM

## Objective

Give the native MTP context a full 262,144-token Turbo4 K/V allocation in VRAM that target paging can
neither evict nor charge as its own capacity.

## Read

- Task README; plan sections 3.3, 3.4, 8.1, and the 00-05 placement handoff.
- `common/speculative.*`, MTP context construction/sizing, `87b37eac9`, current draft K/V parser, fit and
  cache accounting, and llama.cpp #28115.

## Implementation

- Resolve `-ctkd t4`/`-ctvd t4` through current accepted Turbo4 type names and verify actual tensors.
- Use the independent draft-KV residency contract from 00-05; do not reintroduce target/draft coupling.
- Separate target page budget from MTP placement/accounting; MTP remains GPU even though target has host
  backing.
- Size MTP to the full accepted target frontier/logical context as required by native MTP semantics.
- Reserve MTP before target hot pages and fail startup if it cannot fit safely.
- Disarm any independent dynamic VBR/pager controller in the MTP context.
- Log exact type, rows, bytes, backend, and budget category.
- Update the generated CLI/server option tables so they no longer omit parser-supported Turbo cache
  types, following the repository's normal documentation-generation workflow.

## Tests and acceptance

Assert reference payload 1,056 bytes/token and 264 MiB at 256K using actual row sizes. Test accidental
F16, coupled no-KV-offload, insufficient VRAM, shortened target, target pressure, and teardown. A CUDA
run must show MTP tensors remain GPU-resident while target faults occur.
