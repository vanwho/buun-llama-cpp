# 04-02 — Collect per-page attention telemetry

## Objective

Measure real page attention mass for retention while preserving attention output and disabled overhead.

## Read

- Task README; plan section 8.7.
- Phase 03 paged kernel and existing metrics/logging conventions.
- Existing bounded cache-plan observer patterns; do not reuse whole-artifact scores as page scores.

## Implementation

- Add an optional GPU per-logical-page probability-mass and recent-peak reduction for selected pages.
- Aggregate across documented heads/layers/tokens; define normalization and sampling interval. Copy only
  bounded reduced scores to the controller (1,024 floats are about 4 KiB), never an attention matrix.
- Publish results only after the graph/event completes and table epoch still matches.
- Feed bounded EMA/peak state keyed by logical page generation.
- Add counters for sampled tokens/pages and stale/dropped observations.
- `off` performs no allocation/work; `observe` can collect against dense/current execution where
  supported; `selective` reports only observed selected pages and marks others unobserved.

## Tests and acceptance

Output with telemetry on/off matches within tolerance. Probability aggregation is checked against a
small CPU/reference calculation. Stale epochs do not update EMA. Profile the kernel; record overhead
and keep it under the threshold specified in the handoff before enabling by default in selective mode.
