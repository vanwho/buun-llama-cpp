# 08-03 — Remove fixed hot-set assumptions and derive policy capacity

## Objective

Make target GPU hot capacity and all automatic policy quotas depend only on runtime context, measured
resource accounting, backend granularity, and user limits.

## Read

- Task README, cluster `08a-dynamic-contract`, plan 21.2–21.3 and D21–D22.
- Handoffs 01-03, 01-04, 02-05, 04-02, 04-03, 08-01, 08-02.
- Cache budget/accounting, fixed-window, residency, policy, telemetry, routing and prefetch sources/tests.

## Implementation

1. Replace default `mtp_tokens`, fixed policy capacity, fixed logical-page telemetry arrays, and any
   implicit Qwen maximum with runtime-sized/configured storage bounded by checked arithmetic.
2. Add a pure admission result containing every term in plan 21.2, actual/estimated provenance, alignment,
   admitted `H`, logical `L`, unused remainder, refusal reason, and post-allocation reconciliation status.
3. Treat a user hot-page value only as an upper bound. Reject attempts to exceed safe admission; `auto`
   chooses the largest safe page-rounded capacity.
4. Replace absolute recent/structural/history/transient defaults with capacity-relative auto policy.
   Mandatory pages are exact; remaining quotas clamp and sum to `H` after deduplication. Preserve explicit
   test/user overrides without embedding a preferred capacity.
5. Make routing/telemetry/controller memory scale with `L` through bounded dynamic allocations, with
   overflow checks and stated maximum derived from the resolved context.
6. Delete or rename “fixed window” production APIs when their semantics are now dynamic; preserve useful
   fixtures as explicit manual-capacity tests.

## Tests

Cover zero/negative usable budget, one page, mandatory overflow, `H<L`, `H==L`, `H>L` clamp, odd tail,
allocator alignment changes, context-sized MTP changes, headroom, explicit upper bounds, very small
capacities, large synthetic checked-overflow inputs, deterministic ties, and quota reconciliation.
Test at least five distinct explicit capacities without treating any as default.

Run focused CPU tests, parser tests, `git diff --check`, and a production-source scan for the historical
hot token/page values. Occurrences may remain only in old task/evidence files or explicitly named fixture
inputs with comments stating that status.

## Acceptance

No production default or array size encodes the old estimate. Admission produces the largest safe `H`
and a byte-complete ledger; policy outputs exactly `H` or a typed mandatory-overflow refusal.

## Recovery

If a bound is needed for allocation safety, derive it from checked `ceil(C/P)` and reject overflow rather
than restoring a model constant. If ratios create rounding drift, assign remainders deterministically in
documented priority order.
