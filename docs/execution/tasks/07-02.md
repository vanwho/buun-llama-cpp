# 07-02 — Finalize documentation and evidence index

## Objective

Leave a self-consistent implementation, operator guide, evidence index, and resumable final state.

## Read

- Task README, canonical plan, all handoffs, final acceptance, and slice map.
- User-facing CLI/server docs affected by the actual implementation.

## Work

- Update experimental usage, supported/unsupported scope, memory math, tuning, logs/metrics, failure and
  fallback behavior, host RAM/VRAM requirements, and benchmark reproduction.
- Add `docs/execution/evidence/INDEX.md` linking every baseline, test matrix, raw result directory,
  acceptance decision, and deferred check.
- Reconcile plan claims with actual names/behavior; mark superseded design choices clearly.
- Validate every task/handoff/state link and run doc/link/config tests.
- Ensure secrets, huge result payloads, build output, and machine-specific mutable paths are not staged.
- Run a changed-file portability scan: implementation commits must not embed `/srv/ai`, `/srv/repos`,
  `/home/ninja`, machine-specific systemd/PID/port/model/profile values, or RTX 4080 assumptions. Keep
  Qwen3.8 geometry as runtime capability/test data behind the generic pager interfaces; record any
  deliberate fixture-only exception in the evidence index. `/srv/ai` benchmark/profile paths belong in
  execution metadata or the external benchmark repository, never in Buun production code.

## Acceptance

- `tool/codex/task_state.py validate` passes.
- Every task is done or explicitly deferred with permitted reason; required release checks are not
  deferred.
- Git diff/status is reviewed and unrelated user work is untouched.
- The final handoff states the achieved hot page count, MTP placement/type, CPU backing type, quality
  thresholds, throughput ratios, limitations, and exact raw evidence.
- The clustered runner leaves Git untouched. A user-authorized outer agent may commit/push `vanwho/*`;
  a human remains responsible for upstream prose, PR creation/review replies, and merges.
- The final code range-diff is portable and contains no server-specific paths or operational state; the
  execution-metadata commit may contain local evidence pointers but is excluded from upstream slices.
