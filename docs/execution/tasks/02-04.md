# 02-04 — Publish residency transactions with rollback

## Objective

Join policy, page table, host catalog, and async transfers into one failure-atomic residency operation.

## Read

- Task README; plan sections 8.2, 8.8, and 9.1.
- Phase 01 table/policy code and Phase 02 capture/catalog/transfer code.
- Existing VBR transaction, operation, hard-seal, and occupied-replacement implementations.

## Implementation

Use explicit phases: snapshot, plan, reserve, pin, reseal or reject dirty victims, drop clean mappings,
load additions, fence, recheck, publish, retire old resources, release. Reuse VBR operation IDs and
outcome vocabulary where semantically correct. A table epoch advances exactly once on successful
publication and never on aborted work. Representation/VBR and residency/pager remain separate objects;
one composite transaction orders their generations and publication.

The transaction must reject stale session/sequence/page/representation/table generations, insufficient
slots, all-pinned victims, missing clean host source, short page, and shutdown. Rollback must preserve the
old immutable snapshot until all old graph consumers release it.

## Tests and acceptance

Fault-inject every phase and both sides of publication. Prove reverse-map bijection, pin balance, catalog
charges, event lifetime, occupied replacement, deterministic retries, and no ABA. Add a handoff state
diagram listing the exact publication linearization point.
