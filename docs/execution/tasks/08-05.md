# 08-05 — Capture corrected same-build control matrix

## Objective

Record new controls with the 08-02 dynamic-MTP build so later pager speed and quality comparisons have
identical model, binary, context, sampling, and placement provenance.

## Read

- Task README, cluster `08b-benchmark-contract`, plan 24.
- Handoffs 08-02–08-04 and old baseline results.
- `/srv/ai/benchmarks` runner, active profiles, model/build provenance.

## Runs

1. Build the Release CUDA server from the current task branch and hash it.
2. Capture initial active profile, command, GPU state, and 8080/8091 health.
3. Run a context ladder that includes a small all-pages-fit context, one intermediate context, an odd
   tail context, and model maximum. Context values are harness inputs and recorded, not source defaults.
4. At each applicable context run ordinary target `--no-kv-offload` with Turbo4 target K/V and native
   Turbo4 MTP forced GPU. Verify MTP rows equal the resolved context from server logs/metrics.
5. Discover the largest safe all-GPU target+MTP context for this exact build with a reproducible ladder;
   retain pass/fail allocation evidence and safety margin.
6. Run feature-off and selected-all/observe controls only if already live; label unavailable pager modes
   as pending rather than fabricating counters.
7. Use frozen corpus control prompts, fixed seed/temperature/output sizes, required warmups, and at least
   five measured trials. Record pp/tg, TTFT, latency tails, MTP acceptance, CPU/RAM/VRAM and placement.
8. Restore the starting profile and verify both health endpoints even after a failed run.

## Acceptance

All required CPU-KV and all-GPU controls complete without request errors; manifests contain binary/model/
corpus hashes and explicit MTP GPU evidence. No control is called a pager result. Raw outputs remain in
timestamped `/srv/ai/paged-kv/results/` directories.

## Recovery

On allocation failure, preserve the sample and continue the ladder downward; do not edit production
defaults. On restore failure, diagnose 8080 server and `ai-long-memory.service`/8091 through systemd,
never substitute 8092, and retry restoration before blocking.

## Deliverable

Create `handoffs/08-05.md` and `evidence/BASELINE_V2.md/json` with raw paths, tables, placement proofs,
failed ladder points, and the restored-service result.
