# 15-03 — Make the benchmark launcher real and keep successful state loaded

## Objective

Replace adapter-only/dry-run acceptance with an explicit live launcher for Qwen3.8 Turbo4 pager+native
MTP, and change lifecycle semantics so a successful benchmark configuration remains active for the next
task or retry unless a revert/control benchmark is explicitly requested.

## Read

- Task README, cluster `15c-harness-lifecycle`, plan sections 12.4, 19, 25–27.
- `/srv/ai/benchmarks/README.md`, `run-profile-benchmark.sh`, current profiles, pager adapter, metrics
  serializer, and V2 performance/quality logs.

## Work and acceptance

Add explicit mode/device/page-size/context/MTP flags to the launcher and capture command line, startup
placement, `llamacpp:kv_pager_*` metrics, raw requests, and lifecycle state. The launcher must clone the
canonical Qwen3.8 profile, derive context dynamically, use Turbo4 for target and draft K/V, and never
assume the historical context or hotset. Add a lifecycle policy with `keep_loaded` default: after a
successful run, leave that server/profile loaded and health-checked; restore only for an explicit
`--restore-control`/revert benchmark, teardown, failure recovery, or final cleanup. On interruption,
record whether the loaded state is usable for resume. Preserve the separate 8092 service.

Run an isolated short live smoke with pager enabled and native MTP, then a deliberately requested
control/revert smoke proving restoration. The launcher must not call restore automatically between
ordinary consecutive tasks.

## Deliverable

Create `handoffs/15-03.md`, launcher/lifecycle changes, schema updates, and raw smoke/restore evidence.
