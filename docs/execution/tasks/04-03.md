# 04-03 — Implement deterministic hot-set controller

## Objective

Combine router candidates and retention evidence into bounded target residency decisions.

## Read

- Task README; Phase 01 policy replay; Phase 04 router/telemetry; plan sections 8.6–8.7.

## Implementation

- Update retrieval and retention state only at explicit decode boundaries.
- Union mandatory pages first, then summary top-K and exploration, respecting physical capacity.
- Preserve current write/recent/anchor/in-flight/speculative pins.
- Begin with the exact 304-page policy partition: 96 recent, 32 persistent/structural, 140
  attention-selected historical, and 36 transient/prefetch pages, after deduplication.
- Rank victims by normalized attention EMA/peak, frequency, recency, fault/dirty costs, and age with
  hysteresis. Do not adopt fixed coefficients before trace-calibrating input scales.
- If mandatory pages exceed capacity, return a typed refusal; never drop an anchor silently.
- Emit a bounded decision record with reasons for adds, keeps, victims, and unavailable evidence.
- Make trace replay use the same policy function as live execution.

## Tests and acceptance

Replay stable focus, abrupt shift, cold recall, periodic exploration, noisy scores, dirty costs, pinned
exhaustion, capacity changes, and stale observations. Assert deterministic output and no oscillation under
the documented stable trace. No transfer or graph call belongs in the policy function.
