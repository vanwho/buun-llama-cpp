# 09-02 — Instantiate the production pager owner and compact GPU target storage

## Objective

Create the one runtime owner that joins dynamic admission, logical page identity, compact physical target
storage, immutable table publication, and teardown inside the real target context.

## Read

- Task README, cluster `09a-live-memory`, plan 21.2 and 22 steps 1–2.
- Handoffs 01-02–02-05, 05-01, 08-03, 09-01; production wiring map.
- `llama_context`, KV/memory interfaces, graph allocator, cache accounting, VBR/VMM authority, Qwen
  memory construction, pager component headers, and relevant tests.

## Implementation

1. Add a context-owned pager runtime with deterministic init/free order and no global singleton.
2. Query resolved `C`, runtime attention-layer geometry and actual Turbo4 row sizes. Construct `L`; reserve
   context-sized MTP, recurrent/fixed, graph/kernel, staging/routing, allocator guard, and headroom terms.
3. Perform a backend-aware dry allocation/projection, derive `H`, validate mandatory minimum, then allocate
   exactly `H * page_tokens` physical rows/slots for target K/V. Reconcile projected and realized bytes.
4. Keep logical metadata sized to `L` in host/controller memory. Device page tables are bounded to `H`.
5. Establish one representation/residency authority and reject co-tenancy or unsupported multi-device/
   sequence layouts. Do not overload the VBR pool; share low-level CUDA VMM utilities only.
6. Wire init failure rollback and teardown for partial allocations, MTP, slots, tables, events, and host
   controller state.
7. Expose internal accounting snapshots needed by later server telemetry.

## Tests

Pure allocation planning plus fake backend success/failure at every init phase; dynamic `C/H/L`, odd tails,
tiny budget, all-pages-fit, user cap, allocator granularity, mismatched realized charge, duplicate authority,
and teardown. CUDA fixture checks real mapped bytes/slots and leak-free repeated init/free.

## Acceptance

With a model-backed context, target device KV allocation follows `H`, not `C`; host logical metadata may
follow `L`; MTP rows match `C` and remain GPU. Ledger sums reconcile with backend memory within documented
allocator granularity.
