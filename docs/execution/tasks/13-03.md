# 13-03 — Optimize host sealing, promotions, and compute/transfer overlap

## Objective

Minimize paging stalls and CPU overhead by tuning canonical host storage, staging, transfer batching, VMM/
slot operations, and stream scheduling from live measurements.

## Read

- Task README, cluster `13a-kernel-transfer-opt`.
- Handoffs 09-04–09-05, 11-05, 13-01; transfer timelines/counters and CUDA backend APIs.

## Work

1. Reproduce warm, single-fault, burst-fault, focus-shift and churn transfer baselines.
2. Compare pageable canonical backing plus pinned ring against a bounded pinned-backing experiment, keeping
   host budgets/RSS explicit. Choose by end-to-end latency and system impact.
3. Sweep bounded staging slots/ring size, copy batch size, adjacent logical/layer/side coalescing, stream
   priority/count, prefetch distance, and double/triple buffering. Use runtime auto rules keyed to measured
   page bytes/bandwidth, not a GPU model.
4. Remove avoidable synchronization, duplicate copies/checksums, map/unmap calls and per-token allocations
   without weakening generation/checksum/publication ordering.
5. Measure useful/aligned bandwidth, overlap percentage, CPU time, late waits, p95/p99 latency, host pinned
   high-water, VRAM staging, faults and clean zero-D2H eviction.
6. Run corruption/stale/cancel/ring/all-pinned/map-denial/teardown tests and sanitizer after retained changes.

## Acceptance

Meet the transfer/overlap budgets from 13-01 or test at least three distinct measured hypotheses before
blocking. Canonical host backing remains complete, clean eviction remains zero-D2H, and no unbounded pinned
memory or hidden synchronous fault path is introduced.

## Deliverable

Create `handoffs/13-03.md` with sweep table, selected auto rules, before/after timelines, fault tests,
resource high-water, rejected variants, and raw paths.
