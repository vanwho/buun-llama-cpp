# 06-03 — Integrate canonical profile benchmark harness

## Objective

Extend the established `/srv/ai/benchmarks/run-profile-benchmark.sh` result contract for pager evidence
without losing comparability or overwriting unrelated `/srv/ai` changes.

## Read

- Task README; plan section 12.4 in full.
- `/srv/ai/benchmarks/README.md`, `benchmarks.md`, and `run-profile-benchmark.sh`.
- Current `/srv/ai` Git status before editing; its existing modifications belong to the user.
- Pager metrics/config implemented by prior phases.

## Implementation choice

Prefer a repo-local adapter/collector under an existing appropriate tools/bench area if that avoids
overlapping dirty `/srv/ai` files. If editing `/srv/ai/benchmarks` is necessary, stop when an overlap
cannot be safely preserved and request direction. Never copy API keys or service secrets into Git.

Add compatible pager variants for:

- short/default MTP throughput;
- established ~44K large scratch run;
- stable-focus locality;
- cold needles at fixed page distances;
- abrupt focus shifts;
- adversarial page churn.

Preserve current `run-config.json`, `records.jsonl`, raw responses, HTTP metadata, summaries, clean
isolation, interruption summary, and production-profile restoration. Append pager configuration,
placement verification, page metrics, RAM/VRAM, copy bytes/times, and corpus/expected-answer identity.

## Tests and acceptance

- Shellcheck/syntax and a no-service/dry manifest test pass.
- Old default/large records remain readable by the summarizer.
- A smoke run writes a complete new-format result and restores the initial profile.
- No benchmark is run during an active workload without a maintenance-window decision.
