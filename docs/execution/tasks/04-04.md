# 04-04 — Add page-fault prefetch and backpressure scheduler

## Objective

Translate hot-set decisions into overlapped residency transactions without unbounded stalls or queues.

## Read

- Task README; Phase 02 transactions; Phase 04 controller; plan section 8.8.
- Existing server/VBR update-boundary and async service mechanisms.

## Implementation

- Use prior-token/query routing to prefetch the next required set at configurable depth on a dedicated
  upload stream, with at least double-buffered staging where measurement supports it.
- Bound queued pages, bytes, events, and pinned slots.
- Coalesce duplicate requests and cancel obsolete generations.
- Define explicit not-ready behavior: wait within budget, reuse safe old hot set, or fail/fallback as
  specified by semantics; never publish partial pages.
- Apply backpressure before all physical slots become pinned.
- Evict sealed clean pages by dropping their GPU mapping/slot without D2H. Dirty pages must reseal or be
  ineligible; record any reseal separately from eviction.
- Record fault, prefetch-hit, late wait, eviction, amplification, cancellation, and stage latency.
- Drain safely on request cancellation and context teardown.

## Tests and acceptance

Fake delayed completions, reordering, cancellation, focus reversal, all-pinned state, host miss, transfer
failure, and shutdown. Demonstrate at least one transfer/attention overlap timeline. A CUDA smoke test is
required where available; missing hardware is deferred to 06-02.
